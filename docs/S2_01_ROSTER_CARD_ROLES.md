# S2-01 / BUG_REPORT — роли в карточке команды

В блоке «Состав по OpenDota» рядом с именем игрока автоматически показывается
подсказка Carry / Mid / Offlane / Semi-support / Hard support либо «Роль не
определена». Это текущая описательная подсказка, не подтверждение участия в
будущем матче и не восстановленная роль в последней сыгранной карте.
Известные позиции показаны по порядку 1–5, неизвестные — после них.

Используется прежняя политика редактора: допустимая однозначная заявка
PandaScore → профиль STRATZ → локальная pro-история. Сопоставление требует
совпадения подтверждённого числового аккаунта в реестре и отчёте ролей.
Одинаковые ники не дают роль; повторный canonical ID в списке не используется.
Устаревшие/неподходящие профили остаются недопустимыми по прежнему resolver.

Источник подсказки виден сразу. В «Основания роли» раскрываются число карт
с оценкой, область истории (эта организация / все организации), состояния
и времена получения профилей. Малый N, эвристика линии/GPM, разногласия и
одинаковые позиции у нескольких игроков отмечены. Недостающие роли не
распределяются по порядку списка; резервные игроки не отбрасываются.

Для изменения ролей перейдите «Выбрать пятёрку для сравнения». Там доступны
ручные позиции, проверка и обновление API-профилей. Просмотр карточки не
сохраняет сценарий и не изменяет роли в истории, БД или модели V1.

## Запросы и границы

Новых API endpoints, миграций или зависимостей нет. Vue вызывает существующий
`POST /api/v1/lineup-role-profiles` с `refreshProfiles:false`: только локальная
история и сохранённые профили, без внешнего HTTP. Подтверждённые игроки идут
пакетами до пяти, последовательно, с единым серверным cutoff из ответа
реестра и проверкой ответа. Часы браузера не задают срез истории.
Пятёрка не дополняется искусственно: для одного игрока нужен один запрос,
для шести — два. Ограничение отображения ролей: 30 записей реестра, максимум
шесть локальных запросов; при большем списке предлагается выбрать пятёрку
в сравнении. Сам список участников не обрезается.

Ключ Vue Query включает команду и числовые личности, актуальность кэша —
60 секунд; префикс совпадает с инвалидированием сопоставлений в редакторе.
Повторное обновление реестра с теми же участниками не вызывает
нового чтения ролей. Изменённый список получает отдельный запрос, поздний
ответ старого списка не подменяет новый. При ошибке роль не показывается
по прежнему успешному ответу; есть кнопка повторного чтения. Неподтверждённые
аккаунты и отсутствие данных остаются неизвестными.

Окно pro-истории и лимит прежнего reader: 90 дней, до 20 карт на игрока,
строго до cutoff. Это ограниченная локальная выборка, не вся карьера.
Слоты последней наблюдавшейся карты перенесены в отдельные подробности;
они не переименованы в Carry–Hard support. Участники карты сохранены.

Рабочая проверка Team Spirit 10 ноября: пять подсказок из локальной pro-истории,
Yatoro — Carry на 18 картах с оценкой роли. История содержит эвристику линии/GPM,
а сведения реестра уже устарели: оба ограничения показаны. Это не проверка
официального состава или измеренной точности ролей. Итоговый просмотр сделал
один локальный запрос ролей, без внешних HTTP и сохранения сценария.
