# S1-16 / BUG_REPORT №7 — имена в ссылочных фильтрах

11 ноября 2026. Срез `readable-labels/context-filters/references`.

В блоке **«Профессиональные карты»** соперник выбирается по названию или тегу
организации, а игрок для фильтра роли — по нику из локального каталога.
В блоке **«Герой и позиция»** герой выбирается по отображаемому или внутреннему
названию. Нажмите «Найти», выберите запись и примените фильтры отчёта.
В карточке игрока соперник означает организацию другой стороны карты.

Поиск не меняет действующий выбор и не запускает пересчёт. Пустая выдача,
недоступность каталога и поздний ответ не снимают ограничение. Сброс — явная
кнопка. Поиск пустой строки открывает первую страницу; страницы по20 записей.
Одинаковые имена не объединяются: локальный ключ доступен в подробностях.
Пустой ник/название показаны честной подписью без придуманного имени.

Старый числовой ввод сохранён в **«Технический ID»**. Это локальный ключ,
не OpenDota account/team ID. При наборе цифр нет запросов на каждую цифру;
название читается после выхода из поля. Неизвестный положительный ключ
сохраняется и не превращается в «Все». Некорректный ID по-прежнему отклоняет
сервер анализа. Герой/игрок/соперник передаются прежними строками, без Number.

Применённые подписи читаются из ключей ответа отчёта, а не из ещё редактируемой
формы. Общий кэш выбранных названий исключает дополнительный точный запрос
после выбора результата. Имя самого игрока повторно не запрашивается в
фильтрах его карточки. Подписи — текущая metadata, не исторический факт.

## API и границы

Существующий приватный `GET /api/v1/context-catalog` дополнен видами
`heroes`, `players`, `teams`, сохранив `patches`, `leagues`. Это только SELECT
локальных записей: ID-lookup до1 результата, поиск до20/hasMore, query80,
offset10000, bigint-safe ID и Zod-проверка несовместимых режимов.
Таблица/колонки выбираются закрытым mapping; `%_` ищутся буквально,
Unicode-поиск не зависит от C-locale. Команды доступны и для исторической
статистики, без ограничения текущим активным составом. Ник не разрешает
слияние личностей, название героя не подтверждает его доступность в патче.

ContextPicker/ContextFilterLabel переиспользованы; новых endpoints, библиотек,
SQL-миграций и изменений защищённых packages нет. Нормативный API:
[контракт](API_CONTRACTS.md). Исходные pro-only/cutoff/role/patch условия,
N/WR, nullable n=0, immutable snapshots и активная модель V1 прежние.
Рабочие таблицы и источники не пополняются через поиск.

## Проверки

Проверены точные локальные ID больше2^53 вместо provider ID, N=1 после
именованного выбора соперника/игрока/роли, выбор героя/N=2, пустая выборка
с null win rate, дубли/пустые имена, literal Unicode search, страницы,
unknown ID/invalid input, ошибки/повтор/поздний ответ и360px.
Совместимость включает патчи/турниры, сравнение, сглаживание, сохранённые
отчёты и будущие пятёрки. [Результаты](evidence/bug-report-reference-filters.json).
