# S3-04 — воспроизведение списка карт из архива v2

15 ноября 2026. Срез `S3-04/conditional-collection-v2-discovery`.

Добавлен внутренний read-only адаптер `tools/research/conditional-collection-v2-discovery.mjs`. Он связывает [журнал v2](S3_04_COLLECTION_V2_JOURNAL.md) и [архив ответов](S3_04_COLLECTION_BLOB_ARCHIVE.md) со списком наблюдённых карт. HTTP, импорт в рабочую историю, обучение и выдача прогнозов не выполняются.

## Как получается список

1. Проверяются пакет регистрации v2, его SHA, сроки, закреплённые турниры и исключения. Заново воспроизводится цепочка резервов и исходов запросов.
2. Только для завершённых `archived` запросов читается исходное тело. Проверяются SHA тела и квитанции, ID запроса, endpoint, время, размер и принадлежность регистрации. Сохранённая, но ещё не завершённая квитанция остаётся ожидающей и не добавляет карты.
3. JSON/UTF-8, повторяющиеся ключи, числовые ID и структура проверяются до проекции. В список попадают только `match_id`, `start_time`, `leagueid`, `series_id`, ID команд по сторонам. Победитель, длительность, герои и показатели игроков не используются.
4. Каждый `/proMatches` начинает отдельный наблюдаемый проход. Следующая страница обязана использовать минимальный ID предыдущей принятой страницы; все её ID должны быть меньше курсора. Короткая непустая страница не означает конец. Пустая страница означает только наблюдённый конец endpoint. Новый корневой запрос сохраняет прежний проход, включая отметку незавершённости.
5. `/matches/:id` допустим в воспроизведении только после обнаружения этого ID как потенциальной целевой карты. ID внутри ответа обязан совпасть. Низкоуровневый транспорт сам этого ограничения ещё не обеспечивает; будущий runtime должен использовать discovery-проверку перед отправкой.

## Конфликты, серии и пределы

Наблюдения не перезаписываются: каждое сохраняет request ID, endpoint, время и SHA исходного ответа. `null` может быть дополнен известным значением; два разных известных значения дают конфликт и `null` в согласованной проекции. Отсутствующий `leagueid` не заполняется ID из URL. Несовпадение ответа с league endpoint отмечается отдельно.

Все наблюдённые кандидаты учитываются один раз по строковому BIGINT-safe ID. Неизвестные время или турнир считаются потенциальным попаданием, пока не доказано обратное. Ранее учтённый кандидат не исчезает из счётчика после уточнения или исключения. Карты известной серии с конфликтом, выходом за окно или иным неразрешённым условием получают предупреждение о проблеме участника серии. Известное исключение одной карты распространяется на наблюдённых участников её серии.

Предел300 относится к уникальным потенциальным картам, включая исключённые. Ответ, обнаруживший301 карту, сохраняется целиком и останавливает рекомендации; дальнейшие запросы в таком журнале отклоняются при воспроизведении. Это не отбор первых300. Дополнительный технический предел100000 проекций метаданных защищает память: превышение даёт ошибку, исходный архив остаётся доступным. Тела читаются последовательно, в отчёт не встраиваются.

`nextRequest` — только подсказка следующего endpoint: сначала отсутствующие league responses, затем недостающие допустимые детали, затем глобальные страницы. Это не разрешение HTTP. Ошибки JSON/структуры, неизвестный исход, ограничения журнала или превышение бюджета останавливают подсказки. Автоматического обхода ошибки или ручного сброса в этом срезе нет.

## Согласованность и границы

Адаптер PostgreSQL проверяет активного владельца, закреплённый SHA нового модуля и весь архив существующим verifier. Затем под общей блокировкой архива сверяет head журнала, количество квитанций/ссылок и объём тел. Если между проверкой и чтением что-либо добавилось, возвращает `discovery_snapshot_changed_retry`; смешанный снимок не публикуется. Повторное чтение не тратит квоту провайдера и ничего не записывает.

Чистая функция проверяет переданные свидетельства, но не удостоверяет источник их получения. Это явно указано в `bindingBasis`; DB-адаптер добавляет отдельный результат проверки базы. Ни один путь не выдаёт разрешение на сбор, оценку или активацию.

Полнота реального турнира, подтверждённый pro-статус, результаты карт и пригодность для модели здесь **не устанавливаются**: `denominatorComplete:false`, `verifiedProMaps:null`, `eligibleForScoring:false`. Нужны отдельный проверенный реестр событий/карт и существующие source/enrollment verifier. Наблюдённый конец API и количество строк не заменяют эту проверку.
