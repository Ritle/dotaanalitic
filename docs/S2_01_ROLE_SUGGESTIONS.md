# S2-01 — автоматические подсказки ролей

**Текущее расширение:** добавлены [профили STRATZ/PandaScore и согласование с историей](S2_01_ROLE_PROFILES.md). Описанный ниже локальный reader сохранён как fallback; V1 Elo по-прежнему не использует роли.

По решению владельца от 2026-11-04 работа над Linux deployment временно отложена в пользу ролей. Это отдельный описательный срез; V1 Elo остаётся без role features.

## Как пользоваться

В редакторе сценария и форме будущей встречи выберите пять игроков в любом порядке. Блок «Автоопределение ролей» автоматически запрашивает локальную историю. Если для всех пяти получились разные позиции, кнопка «Применить роли A/B» расставляет игроков по позициям 1–5. Замена и назначенный герой перемещаются вместе с игроком. Подтверждение состава сбрасывается; сохранять новую редакцию нужно обычной кнопкой сценария.

Ручной порядок сам не перезаписывается. При совпавших позициях, неизвестных ролях или неполной пятёрке применение недоступно; можно расставить игроков вручную. Обновление подсказок не изменяет сохранённый сценарий или прогноз. Ожидаемая baseline-пятёрка остаётся ручной.

## Основание подсказки

- Окно 90 дней до среза, максимум 20 последних подходящих карт игрока, через любые организации. Это параметры удобства отображения, а не валидированная модель роли или прогнозов.
- Только положительно установленные pro-карты, без конфликтов, с известным результатом и завершением не позднее среза; начало строго раньше среза. Одна каноническая карта даёт один голос, даже если receipt несколько.
- Личность определяется заново по подтверждённому numeric account evidence. Кэшированный `match_players.player_id`, ник и recent-member flag не подтверждают роль или личность.
- Сначала используется однозначная подтверждённая историческая позиция. Явный конфликт или дублирование позиции не разрешаются эвристикой.
- Иначе — **непроверенная эвристическая оценка** из уже сохранённых OpenDota receipt: полная идентифицированная сторона, native slots, схема линий 2–1–2. Mid → 2; среди двух игроков safe lane больший итоговый GPM → 1, меньший → 5; off lane → 3/4 соответственно. Равный/неизвестный GPM оставляет пару неизвестной. Другие схемы линий не получают выдуманную расстановку. Различие линии и позиции проверено по [исходному коду OpenDota](https://github.com/odota/core/blob/master/svc/util/compute.ts): `lane_role` 1/2/3/4 означает safe/mid/off/jungle и само не разделяет core/support.
- Receipt привязан к canonical map ID, началу, длительности, результату, native slot, аккаунту и нормализованному GPM. Противоречащие подходящие receipt не разрешаются выбором самого свежего. Source payload проходит Zod; нет новых запросов к провайдерам.
- Позиция предлагается при строгом большинстве среди карт с оценкой. Показываются отдельно N подходящих карт, N с оценкой, число голосов за позицию, источник, период и время проверки. Малая выборка, неполное покрытие и эвристическое основание явно отмечены. Процент уверенности не рассчитывается.

Смена профессиональной роли, roaming и нестандартная стратегия могут сделать подсказку ошибочной. Итоговый GPM не равен приоритету фарма в начале игры; точность этого правила **не измерена**. Подсказки не объявляются подтверждённой будущей ролью. Данные, загруженные сегодня, не становятся исторически известными до среза: endpoint маркирует `current_descriptive_suggestion`, а не as-of features. Для будущего среза UI запрашивает доступную сейчас историю.

## API и сохранность

`POST /api/v1/lineup-role-suggestions` — owner session + same-origin + CSRF, `Cache-Control: no-store`. Тело: `playerIds` (1–5 разных локальных ID-строк), необязательный `cutoffAt` в UTC, не позже текущего времени. В UI запрос начинается после выбора полной пятёрки. Некорректный ввод, неизвестный ID или превышенный лимит окна возвращают структурированный 400; отсутствие подходящих данных — 200 с nullable позициями.

Ответ содержит versioned policy, N, распределение, match/receipt/context/identity proof IDs, source clocks и предупреждения. Оценки не записываются в исторические role observations, training datasets или features. После явного применения и сохранения позиции становятся **выбором владельца для сценария**; отдельная историческая/официальная роль этим не подтверждается. Диагностический ответ подсказки не добавляется в старую схему snapshot. SQL migrations и существующие runtime modules остаются прежними, добавлены только новые модули и barrel exports.

## Проверки

Автоматические проверки охватывают native Dire slots, порядок игроков, core/support, пропуски/равный GPM, нулевую историю, pro-only, точный cutoff/завершение, конфликт идентичностей и источников, дубли receipt, смену ролей, ограничение 20 карт, confirmed-role precedence, owner/CSRF, bigint IDs, сохранение героя/замены, stale/incomplete UI и сохранение редакции.

Read-only проверка рабочей истории: 60 verified игроков получили подсказки по 17 уникальным картам (160 player-map оценок, **не** 160 независимых матчей). Подтверждённых role facts в рабочей БД нет; это демонстрация покрытия эвристики, **не** измерение точности. Все 78 working relations и замороженные артефакты проверяются отдельно; очередь не исполнялась. Результаты QA и ограничения зафиксированы в [PROGRESS](PROGRESS.md) и [evidence](evidence/s2-01-role-suggestions.json).

Возможные усиления: provider `position_est` с явным статусом estimate, текущие team/player role profiles с numeric identity/source time, early-farm признаки и проверенная выборка профессиональных ролей. Они не реализованы этим срезом и не меняют модель Elo. Полноценные role-aware прогнозные признаки требуют отдельной версии и backtest.
