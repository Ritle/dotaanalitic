# Применение подсказок ролей в будущей встрече

Задача `S2-01/role-apply-feedback`, уточнение владельца 12 ноября 2026: кнопка **«Применить роли A»** у Aurora не давала заметного результата.

Кнопка переносит предложенные роли в редактируемую пятёрку. Если назначения уже совпадают, она выключена и рядом видно **«Роли A уже расставлены в форме»**. В будущей встрече сообщение указывает следующий шаг: проверить игроков и нажать **«Подтвердить пятёрки и роли»**. Применение подсказки само по себе состав не сохраняет.

Если роли изменены вручную, «Применить роли A» снова доступна при наличии пяти однозначных подсказок. Явное нажатие восстанавливает предложенные назначения, сохраняя выбранные аккаунты, героев и отметки замены. Последующий автоматический ответ не должен затереть ручной выбор. Для стороны B действует та же логика.

Исправлены два случая: бессмысленный повтор уже выполненной расстановки без сообщения и блокировка явного применения после ручной правки подготовленной пятёрки. Автоматическое и явное применение теперь различаются; сохранён приоритет ручных назначений. Во время общего сохранения применение ролей блокируется.

Изменения ограничены Vue-компонентами `RoleSuggestions`, `RoleProfiles`, `UpcomingScenario` и браузерными проверками. Приоритет источников, проверка числовых аккаунтов, API сохранения, SQL и модель Elo прежние. Неоднозначная подсказка не превращается в подтверждённую роль.

В рабочем интерфейсе Aurora—GamerLegion проверены смена роли и возврат подсказок без сохранения сценария/состава. Во время диагностики в базе появились подтверждение Aurora и шаблоны обеих команд; эти записи сохранены. Прежние строки отдельно проверены проекцией по времени, изменения владельца не откатывались. Новые чтения страницы могут штатно обновлять кэш расписания; нулевой расход API за всё время диагностики не заявляется.
