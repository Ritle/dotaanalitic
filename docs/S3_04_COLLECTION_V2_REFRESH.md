# S3-04 — явный повторный обход v2

16 ноября 2026. Срез `S3-04/conditional-collection-v2-refresh`.

После завершения первого [локального прохода](S3_04_COLLECTION_V2_RUNTIME.md) можно явно начать следующий, чтобы обнаружить появившиеся карты. Списки зарегистрированных турниров и глобальная лента перечитываются; уже сохранённые подробности карт повторно не запрашиваются. Старые наблюдения, конфликты и расход квоты сохраняются.

## Контракт

Новый runtime использует прежние транспорт, журнал, архив, блокировку runner, ограничение времени и числа запросов. Новая миграция `070_conditional_collection_v2_sweeps.sql` добавляет только неизменяемые границы проходов: UUID, порядковый номер, SHA головы журнала, число прежних попыток, SHA предыдущей границы и серверное время. Начало нового прохода не сбрасывает ни суточный/общий бюджет, ни Retry-After, ни архив.

В локальный запрос добавляется один обязательный объект:

```json
{"action":"begin","sweepId":"<UUID нового прохода>","expectedHeadSha256":"<SHA завершённого журнала>"}
```

Он передаётся в поле `sweep`. Для продолжения:

```json
{"action":"resume","sweepId":"<тот же UUID>"}
```

Повтор `begin` с тем же UUID и исходным SHA идемпотентен, в том числе после частичного выполнения. Для следующего обновления требуется новый UUID и актуальный SHA. Неизвестный `resume`, повтор UUID с другим SHA, устаревшая голова, попытка заменить ещё незавершённый проход или вернуться к предыдущему проходу отклоняются. Граница фиксируется до первого HTTP; потеря ответа на её сохранение разрешается повтором той же команды.

Первый проход выполняется прежним runtime. Для нового прохода проверяются свежие ответы каждой зарегистрированной лиги и отдельное окончание глобальной ленты. Короткая непустая страница не означает конец. Детали выбираются из всей сохранённой истории: только для ещё не захваченных потенциальных карт, с прежними ограничениями по конфликтам/исключениям. Появление новой страницы или карты не очищает ранее обнаруженные карты.

SQL защищает неизменяемость, серверные часы, связь границы с завершённой попыткой, число запросов, последовательность и синтетический режим. Сервис дополнительно проверяет завершённость предыдущего обхода по проверенному архиву и сверяет голову в транзакции. Повреждённые границы не используются. Полнота турнира и пригодность карт для оценки модели этим не подтверждаются: `denominatorComplete:false`, `verifiedProMaps:null`, разрешения оценки/активации выключены.

В отчёте разделены время прочитанного архива (`sourceDiscoverySnapshotAt`), время создания границы (`sweepStartedAt`) и время итогового снимка (`snapshotAt`). Сохранение новой границы не выдаётся за факт, уже существовавший при более раннем чтении архива.

## Запуск и ограничения

```powershell
node --env-file=.env tools/research/run-conditional-collection-v2-refresh.mjs --request <локальный-json-запрос>
```

CLI принимает только `local-synthetic`, буквальный HTTP loopback `127.0.0.1` и отдельную PostgreSQL-базу `codex_ingest_<12 hex>`. Рабочая `.env` не является разрешением запускать сбор в рабочей БД. Сохраняются ограничения 16 КиБ входа, запрет повторяющихся JSON-ключей, 1–20 запросов за запуск и 100–60000 мс; SIGINT/SIGTERM передают отмену в HTTP. SQL и проверка среды могут закончиться позже кооперативного лимита времени.

SHA нового модуля, CLI и SQL070 включаются в новый манифест поверх прежних 298 файлов. Прежние модули/SQL001–069 и регистрационные пакеты не переписаны. Не предусмотрены автоматическое расписание обходов, удалённый источник, регистрация реального эксперимента или активация модели. API/UI не меняются. Рабочая БД остаётся на061.
