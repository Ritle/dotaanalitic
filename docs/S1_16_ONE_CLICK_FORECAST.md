# S1-16 — прогноз из выбранной встречи одной кнопкой

Запрос владельца 12 ноября 2026: после проверки составов назначение карты, сценарий, актуализация расписания и расчёт должны выполняться автоматически.

В «Предстоящих матчах» выберите встречу, при необходимости исправьте и сохраните пятёрки/роли, затем нажмите **«Получить прогноз первой карты»**. Результат показан прямо под встречей: вероятность либо причины недоступности. Редактор сценария для этого открывать не требуется. После расчёта доступна ссылка на драфт подготовленной карты; выбранные герои пока не влияют на pre-match V1.

**Обновление 13 ноября:** точные сохранённые пятёрки и роли применяются без нового подтверждения. Для нового турнира не требуется настройка Tier 1. Точное ранее проверенное соответствие турнира переиспользуется; неизвестная локальная лига и tier остаются null, уровень не угадывается по имени. Прогноз с неизвестным уровнем содержит предупреждение об отдельно не установленной точности. [Условия и проверки](S1_16_FORECAST_CONFIRMATION_REUSE.md).

`POST /api/v1/upcoming/:id/forecast` принимает UUID попытки, точные provider/local IDs команд, выбранные 5+5 и необязательную настройку турнира. Проверяются сохранённые связи команд и точное совпадение игроков/ролей с актуальными шаблонами владельца. Перестановка участников источника не меняет назначенные A/B. Устаревшая страница расписания обновляется один раз существующим quota-aware сервисом; свежий источник повторно не запрашивается. Ошибка/лимит/отмена/неполные участники не обходятся.

Новая миграция `054_upcoming_forecast_preparations.sql` хранит неизменяемую подготовку: исходный запрос, назначение, scenario ID, выбранный scope и ревизии/время подтверждения двух шаблонов. В одной транзакции создаются узкий pre-match сценарий карты1 без драфта, его immutable snapshot и запись попытки. Повтор того же UUID использует эти записи; другое содержимое отклоняется. Назначение и прогноз проходят прежние идемпотентные сервисы. При обрыве ответа кнопка повторяет исходный запрос, в том числе после изменения времени/статуса встречи, если результат уже сохранён. Если новый расчёт ещё не состоялся, прежние freshness/start gates продолжают действовать. Неполная подготовка после конфликта остаётся для аудита, автоматически не удаляется.

Запрошенный cutoff сценария — плановое начало карты; существующий runtime ограничивает фактический срез временем расчёта. Сохранение состава строго раньше эффективного среза покрыто отдельной regression-проверкой. Время подтверждения, записи, источника и начала игры не подменяется. Исходная попытка задним числом не изменяется.

SessionStorage хранит только запрос/указатель на результат в рамках текущего аккаунта и вкладки; пароль/CSRF туда не добавляются. Повторное открытие сохранённого результата выполняет GET. Источник идемпотентности — PostgreSQL, а не состояние кнопки. Сессия, CSRF/origin и ограничение частоты API сохранены. Новый tournament setup доступен владельцу; вычисление не выдаёт права менять составы.

Изменения: API quick-forecast contract/service/http + регистрация в app, Vue UpcomingForecast/клиент и подключение в UpcomingScenario, новая SQL054. Shared model/kernel, contracts barrel, lockfile, исторические SQL001–053, quality gates и активный артефакт не менялись.

Проверки завершены: frozen offline install/typecheck/build PASS, 959 unit/CLI tests PASS (последний API пакет 63/63 повторён после прерывания сессии), 6 API/PostgreSQL integration, 14 Chromium/API/PG и 3 финальных повтора compact UI PASS. Дополнительный temporal regression сначала воспроизвёл слишком ранний cutoff; исправление проверено в финальных 6 integration cases. Браузерные проверки включают потерю POST-ответа, один и тот же UUID, отсутствие дублей, однократную настройку турнира, восстановление результата через GET и mobile 360px. Синтетические тесты не являются доказательством live accuracy. 54 SQL checksum, docs links и diff PASS. Сборка сохраняет нефатальные Vite chunk-size/Zod annotation warnings.

SQL054 применена к рабочей БД; повторный migrate — SKIP. API и web запущены, general worker OFF. Рабочая read-only проверка страницы матча1785745 при 1440/360px прошла: кнопка видима, нет горизонтального переполнения и JS ошибок; выбранные составы и прогнозы не записывались. Невалидный POST нового маршрута возвращает 400 до подготовки. Автоматические POST браузера блокировались диагностикой. Первичный live selector выбрал TBD из-за фильтра уже начавшихся встреч; исправлен только проверочный скрипт. Forecast SHA/model_eligible, 2232 pro-карты, 2 прогноза/2 сценария и 13 exact queue rows сохранены. Новый live прогноз не выпускался. [Evidence](evidence/s1-16-one-click-forecast.json).

Ограничения: только карта1 до драфта; недостаток pro-истории или отсутствие активной проверенной модели возвращает unavailable. История автоматически не импортируется этим действием. Неизвестные команды/составы требуют проверки; уровень турнира не блокирует расчёт. После очистки хранилища вкладки старые результаты доступны через журнал/назначение; новый UUID означает новую попытку.
