# S3-07/persistent-provider-results — сохранение сверок источника

16 ноября 2026. По запросу владельца устранена повторная загрузка результатов завершённых карт при открытии журнала и после перезапуска API.

## Поведение

GET результата сначала читает сохранённую квитанцию PostgreSQL. Подтверждённое завершение первой карты или отмена сохраняются без автоматического срока истечения. Незавершённая встреча получает обновление не чаще раза в 5 минут. Кэш процесса ограничен 100 встречами; PostgreSQL advisory lock объединяет обращения разных экземпляров API к одной встрече.

«Сверить с источником» выполняет защищённый POST `/api/v1/forecast-journal/results/:requestId/refresh` с пустым JSON body, CSRF/Origin/session и лимитом6/минуту. У одной встречи общий cooldown60 секунд. Этот запрос обходит кэш процесса; исправленный ответ добавляется новой квитанцией. Старые квитанции неизменяемы. Если провайдер временно недоступен, ранее сохранённый результат остаётся доступным с прежним временем проверки.

Новая SQL071 содержит независимую append-only таблицу `journal_provider_result_receipts`: числовой provider match ID, исходное нормализованное наблюдение с source SHA/часами, SHA сохранённого текста, terminal и recorded_at. Квитанции общие для повторных прогнозов одной встречи; соответствие команд, права на прогноз и его hash проверяются до чтения. Вердикт пересчитывается для каждого замороженного прогноза отдельно. Хранятся полные наблюдения провайдера, размер ограничен клиентом и SQL. Секреты не сохраняются; при echo токена ответ отвергается.

Это хранилище доказательств PandaScore для прежних **map**-прогнозов. Оно не превращает такие записи в прогнозы серии, не создаёт канонические OpenDota labels и не меняет статистику архивных отчётов. Модель серии остаётся отдельной задачей S3-09.

## Проверки и развёртывание

- PG/API: общая загрузка двух пересчётов, чтение новым экземпляром сервиса без HTTP даже после старения terminal-квитанции, CSRF, cooldown, новая ревизия при исправлении победителя, защита от DELETE, неизменность снимков и канонических исходов.
- Browser: GET открывает таблицу, ручная кнопка выполняет отдельный POST с CSRF; отменённые владельцем записи не запрашиваются.
- Рабочий тест одной завершённой встречи: результат сохранён; повтор новым сервисом с запрещённым HTTP вернул тот же результат, повторных запросов0; snapshot SHA прежние.
- В рабочей БД применена только независимая SQL071 с SHA и записью в schema_migrations. Отложенные исследовательские062–070 не применялись. Обычный migration runner позднее применит пропущенные файлы и проверит SHA071.

Фактически выполненные проверки и логи: [evidence](evidence/s3-07-persistent-provider-results.json). Старые source evidence и модель не переписываются. Текущая сверка и повторное подтверждение фактических результатов не входят в обучение.
