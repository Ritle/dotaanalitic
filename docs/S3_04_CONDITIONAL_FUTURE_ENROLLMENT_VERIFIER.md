# S3-04 — проверка перечня карт условного будущего теста

Реализован offline-срез `conditional-future-enrollment-verifier`. Он сопоставляет сохранённые страницы списка матчей, проверенные исходные карты и отдельно составленный локальный реестр основного выпуска турнира. Пропуски сохраняются в отчёте; отсутствие данных не улучшает долю пригодных карт.

## Контракт и ограничения

- `tools/research/conditional-enrollment.mjs` проверяет native league/map/series ID, последовательность страниц, SHA исходных байтов, время получения, соответствие выпуску и статус серий.
- `/proMatches` проверяется по цепочке `less_than_match_id`, вычисленной из минимального ID предыдущей страницы. Временной порядок из ID не выводится. Ошибка запроса отличается от успешного пустого ответа. Ограниченный просмотр допустим и явно обозначен; обход всей глобальной истории не требуется.
- Для `/leagues/{id}/matches` не придуманы параметры пагинации. Ответ сохраняется как есть. Ни он, ни пустая страница сами по себе не доказывают полноту турнира.
- `reviewed-native-event-register-v1` — **внутренний локальный реестр**, а не формат ответа OpenDota. Его автор должен установить основной выпуск, native ID серий, фактические карты и завершённость события. Ссылка `evidenceRef` и время review сохраняются, но содержание ссылки автоматически не проверяется. `main_event` не означает автоматически Tier 1.
- `denominatorComplete:true` означает согласованность **при условии доверия этому проверенному локальному реестру**. Серверной подписи и независимого доказательства полноты API нет: `providerCompletenessIndependentlyProven:false` остаётся всегда. Ошибочно неполный реестр вместе с такими же неполными страницами не может быть опровергнут без дополнительных свидетельств.
- Завершившийся раньше конца окна турнир не требует повторного получения тех же страниц. Старые страницы дают предупреждение; противоречивые карты, время окончания серии или преждевременный review блокируют полноту. Итоговая оценка самого окна допускается только после его конца.

## Знаменатель и целые серии

`knownPossibleMaps` сохраняет все известные возможные карты, включая неизвестные/неподтверждённые. `verifiedProDenominator` считает уникальные подтверждённые профессиональные карты в выбранном окне. При неполноте перечня `eligibleCoverage:null`, а не процент по удобному подмножеству.

Отсутствие подготовленного входа для одной карты не уменьшает знаменатель и исключает всю её серию из пригодной части. Также исключаются раскрытые карты/серии, незавершённые серии, серии через границу окна, конфликты и отсутствующие участники серии. Внеоконные карты остаются в журнале, но не прибавляются к числу карт внутри окна. Отмена/перенос без фактических карт учитывается административно.

`preparedTargetIds` пока только заявляет наличие подготовленного входа. `eligibleMaps` здесь — пригодность по **перечню и серии**, а не пройденная проверка признаков, coverage модели или numerical gate. Следующий срез должен связать её с реально проверенными feature-файлами. Исходы побед не включаются в результат enrollment.

## Сохранение и воспроизведение

`tools/research/conditional-enrollment-files.mjs` принимает только локальные файлы внутри `.tools`, проверяет реальные пути и размер, внешний SHA каждого входа и закреплённую политику. Новый каталог создаётся без перезаписи. `enrollment.json` и `manifest.json` фиксируют результат, версии кода/runtime и источники.

```text
node tools/research/conditional-enrollment-files.mjs build INPUT INPUT_SHA ARCHIVE ARCHIVE_SHA OUTPUT_DIRECTORY
node tools/research/conditional-enrollment-files.mjs verify OUTPUT_DIRECTORY MANIFEST_SHA
```

`verify` требует внешний SHA манифеста и повторяет вычисление. Изменение источника, результата, манифеста либо кода отклоняется. Компиляция прежнего research runtime выполняется локально; приложения/API/SQL не меняются.

## Фактически проверенные данные

Положительная синтетическая фикстура отдельно маркирована. Реальная локальная диагностика использует прежний закреплённый архив двух уже раскрытых карт. Новые страницы или реестр турнира из деталей карт **не конструировались**: без них результат `insufficient`, подтверждённых карт 2, пригодных 0, покрытие `null`. Это проверка отказа при недостающих сведениях, а не независимый тест качества.

Все результаты остаются `independentTest:false`, `registrationAllowed:false`, `collectionAllowed:false`, `scoringPerformed:false`, `deployable:false`. Новых запросов к провайдерам, обучения, регистрации окна и активации модели не было. Контрольные суммы и фактические проверки записаны в [evidence](evidence/s3-04-conditional-future-enrollment-verifier.json).
