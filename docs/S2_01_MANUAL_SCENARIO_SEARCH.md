# S2-01 / BUG_REPORT №7 — поиск в ручном сценарии

В отдельном редакторе `/scenarios/new` и сохранённых сценариях команды и
игроки выбираются через общий каталог: введите название/ник, нажмите «Найти»,
проверьте карточку и выберите результат. Технический ключ остаётся в
раскрываемых данных записи. Существующие сценарии открываются по прежним URL.

Поиск подключён к двум командам, выбранным 5+5 и обоим необязательным ожидаемым
составам. В выбранных 5+5 нельзя повторить игрока на другой позиции или стороне;
команды также должны различаться. Для ожидаемых составов действует отдельная
проверка уникальности по включённым сторонам: тот же игрок может присутствовать
одновременно в выбранном и ожидаемом составе. Выключенная база не влияет на выбор.

Роли, герои, stand-in, подтверждение и смена редакций используют прежнюю логику.
Занятая роль меняет игроков местами вместе с героем и stand-in. Правки сбрасывают
подтверждение; чтение имени из каталога не изменяет сценарий. Для обычной замены
игрока выберите другой результат поиска; если нужна перестановка двух игроков,
используйте список ролей либо сначала освободите занятую позицию.

Имена хранятся только в локальном состоянии редактора под ключом `team:id` /
`player:id`. Они не входят в `ScenarioInput` или immutable snapshots и не
используются для подтверждения личности. Сохранённые версии продолжают содержать
числовые ID как строки, UTC-срез, позиции, героев и другие исходные поля.
При повторном открытии общие lookup-запросы читают только выбранные записи;
одинаковые ключи, в том числе в baseline, используют общий Vue Query cache.
Обновление профилей внешних API остаётся явным действием в блоке ролей.

Backend, contracts, SQL и V1-модель не менялись. `ScenariosView.vue` использует
существующий `CatalogPicker`. Браузерные тесты теперь выполняют явный поиск и
выбор; проверки точных ключей сохранены через невидимые атрибуты. Целевые снимки
заменяют гигантские full-page capture, на которых Chromium вернул protocol error.

Проверки и сохранность: [evidence](evidence/bug-report-manual-scenario-search.json).

Frozen offline install, общая типизация, 908 unit/CLI с одним worker и сборка —
PASS, без повторов. Chromium: 12 целевых и 11 совместимых сценариев PASS на
временных PostgreSQL-базах: роли/поздний ответ/герой/stand-in, создание и
перезагрузка baseline, конфликт вкладок, первая immutable-редакция, Draft Lab,
отчёты, история прогнозов и переход из будущей встречи. Проверка исходной
сохранённой редакции выполнена по полному ответу API, а не только по тексту UI.
52 SQL и ссылки документации проверены. Отдельные full-PG/Node-fixture/Python/
Linux наборы не повторялись; прежнее предупреждение Vite >500kB остаётся.

Рабочий UI: Team Spirit/BetBoom/Yatoro, блокировка дубля, независимый baseline,
перенос героя/stand-in при смене роли и сброс подтверждения — PASS на desktop
и 360px. Сценарий в рабочей БД не сохранялся; provider HTTP/business POST/
page errors/5xx — 0. Финальная сверка: 83/85 public-таблиц неизменны, только
auth-записи изменились. 2232 карты, 12 строк очереди и 9703 защищённых файла
сохранены, активная модель `model_eligible`.
