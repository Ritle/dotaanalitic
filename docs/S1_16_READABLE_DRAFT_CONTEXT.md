# S1-16 — понятные подписи драфта и контекста

Срез №7: `S1-16/BUG_REPORT/readable-labels/draft-context`.

## Использование

В Draft Lab рядом с выбранной ролью показан ник игрока. Его карточка и
точный canonical ID доступны в «Данных записи». Роль/A/B, герой и отметка
замены остаются прежними. Поиск и выбор героя работают с теми же hero IDs.

В проверке доступности и её сохранённой версии показаны названия героев,
патча и локального турнира. Подписи — текущий каталог, а не названия на
дату карты. Время чтения metadata отделено от checkedAt/knowledgeAt и
сохранённых доказательств. Изменение имени не меняет статус, решение,
причину, registryRevision, карту, роли, action или proof timestamps.
Точный hero ID находится в «Данных записи», patch/league ID — в подробностях.
Неизвестный патч/турнир остаётся неизвестным; имя не заполняет eligibility.

В форме сценария используйте «Турнир карты», в назначении будущей встречи —
«Локальный турнир назначения». Найдите название и явно выберите запись.
Поиск сам по себе не меняет выбор или подтверждение. Смена ID снимает
подтверждение; сброс означает неизвестный турнир (`null` в запросе), а не
все турниры. Технический ввод прежнего локального ID остаётся в раскрытии.
Это не ID PandaScore/OpenDota и не автоматическая классификация Tier1:
межпровайдерное соответствие и проверка области события остаются отдельными.

## Загрузка и совместимость

Новые подписи используют только прежние private local-only endpoints:
`catalog-labels` и `context-catalog`. Схемы, backend, зависимости и SQL не
менялись. Родитель передаёт известные выбранные ники; для открытого старого
сценария без этих подписей — один batch до10 игроков. Имя привязано к
canonical ID, не к совпадению ника. Nullable игрок не получает выдуманный ID.

Проверка драфта читает до50 разных hero IDs одним batch (10 picks/40 bans),
при пустом наборе не делает lookup. В раскрытой истории её имена получены
от уже существующего ScenarioDisplayLabels: повторного batch/кнопки нет,
включая отсутствующее имя героя. Сохранённая и предварительная проверки с
одинаковыми наборами используют общий5min cache. Patch/league singleton
lookup также использует прежний общий кэш. Нет запроса на каждого героя,
provider HTTP или перерасчёта драфта при обновлении подписей.

DraftDisplayLabels отделяет display data от assessment. Error/rename/retry
не меняют frozen JSON. Пустое и отсутствующее имя различаются; неизвестная
карточка сохраняет ключ. Hero profile-ссылка не создаётся: такого маршрута
нет. ContextPicker получил только необязательные подписи пустого значения
и назначения поля; старые фильтры сохраняют прежний текст и поведение.

Текущие hero selector options/неизвестные fallback ещё содержат numeric IDs:
их единый формат остаётся последующим cosmetic-fallback срезом №7. Также
открыты аналитические patch distributions/prior. Этот срез не меняет V1 Elo
или предсказательную модель и не доказывает историческую доступность героев.

scenario/roles, назначение карты и acceptance flow проверяются отдельно.
