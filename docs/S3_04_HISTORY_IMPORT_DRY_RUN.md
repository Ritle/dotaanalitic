# S3-04 — пробный импорт дополнительной истории

Срез `S3-04/history-import-dry-run` проверяет [закреплённый план](S3_04_HISTORY_IMPORT_PLAN.md): ровно 28 карт в отдельной тестовой БД. Рабочая история и модель этим инструментом не обновляются.

## Реализация

- `tools/research/post-draft-history-replay.mjs` — offline-адаптер сохранённых проекций. Проверяет исходные и производные контрольные суммы, точный набор карт, числовые аккаунты, десять различных героев и нативные слоты. Запрос карты вне плана отклоняется.
- `tools/research/post-draft-history-import-inventory.mjs` — повторное чтение той же проекции локальных ссылок, которая использовалась при планировании. Любое изменение её данных останавливает проверку до импорта.
- `tools/research/post-draft-history-import-dry-run.mjs` — регистрация входов и кода, копирование БД, запуск существующего importer и `SeriesProvisionRepository`, проверка исходов и повторного импорта. Команда `verify` сверяет сохранённые результаты без БД и HTTP.
- `tests/node/post-draft-history-replay.test.mjs` — синтетические тесты границы адаптера и защиты целевой БД. Синтетика не используется в реальном dry-run.

Копия создаётся через локальные `pg_dump`/`pg_restore` под случайным именем `codex_s304_dry_<16 hex>`. Имя нельзя передать снаружи. Проверяются localhost, исходное подключение, отдельное имя и `current_database()`. До импорта данные копии должны совпасть с исходной БД; в конце копия удаляется. Существующий каталог запуска не перезаписывается.

На копии выполняются базовый импорт 28 карт, preview всей известной группы каждой серии, регистрация недостающих серий, повторный импорт для связывания и ещё один повтор для проверки идемпотентности. Проверяются все известные карты затронутых серий, включая ранее импортированные. Совпадение соперников и дня не используется для автоматического объединения серий.

## Происхождение данных

Оригинальные байты ответов OpenDota не сохранены. Передаваемая проекция получает собственную SHA и явный adapter version `opendota-projection-replay-v1`. Исходные SHA, endpoint, adapter version и время получения остаются отдельно в `report.lineage`, вместе с ID созданных receipts. Это неизменяемый сопроводительный файл **тестового запуска**, а не новое поле production-схемы. Рабочий импорт должен сохранять такую связь до записи карт и проверять её после записи.

Справочники переиспользуют сохранённые нормализованные наблюдения. Адаптер не создаёт для них вымышленных исходных HTTP-байтов. `known_at` остаётся NULL; текущая identity-связь не превращается в доказательство заранее известного состава. Исторические роли, `patch_id` и `map_number` не назначаются автоматически.

## Проверки и запуск

```powershell
node --test tests/node/post-draft-history-replay.test.mjs
node --env-file-if-exists=.env tools/research/post-draft-history-import-dry-run.mjs run
node tools/research/post-draft-history-import-dry-run.mjs verify
```

Запуск требует локального PostgreSQL и права создать отдельную БД. `PG_BIN` может указывать на каталог PostgreSQL client tools; по умолчанию используется `.tools/pgsql/bin`. Архив локальной БД хранится в ignored-каталоге `.tools`, не публикуется и не включается в evidence документации. Вывод CLI не содержит строки подключения или паролей.

## Фактический результат

Dry-run завершился успешно. В копии число карт выросло с 2232 до 2260; добавлены 280 строк участников, две команды и 15 серий. Всего затронуто 16 серий. Проверены исходы 30 карт: 28 новых и двух существующих соседних карт. Пять исключённых карт не импортировались.

Первый импорт дал 28 accepted; после регистрации серий повторная загрузка связала 27 карт, одна уже имела существующую серию. Третий проход вернул duplicate для всех 28 карт, строки всех 100 таблиц остались теми же. Пропуски sequence IDs при INSERT ON CONFLICT допустимы; проверяется идемпотентность строк и ревизий, а не отсутствие пропусков последовательностей.

Созданы 83 receipts: 28 received, 28 исходных accepted и 27 accepted с обновлённым контекстом серии. Все связаны с исходными SHA через lineage. Справочники, identity links, provider quota, очередь, модель и прогнозы на копии не менялись. Прежние карты и строки их участников совпадают полностью. Полные fingerprints всех 100 таблиц public/pgboss рабочей БД до/после совпали; временная БД удалена. Дополнительная проверка подтвердила прежние 2232 карты, три прогноза, 13 строк очереди и active model_eligible.

Offline verify, отказ повторного запуска, отказ подмены отчёта и независимый пересчёт 28/280/30/16/15/2/83 прошли с недоступным DB URL. Семь целевых Node-тестов прошли. Исходные файлы запуска не менялись. Проверены 54 SQL checksums. [Evidence](evidence/s3-04-history-import-dry-run.json) связывает manifest, report, входы и проверки. Отдельные браузерные suites не запускались; UI/API и production SQL не менялись.

Начальный sandbox-вызов pnpm install остановился с ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY из-за другого store, без переустановки. Повтор с существующим пользовательским store и --frozen-lockfile --offline успешен; lockfile и зависимости не менялись.

Frozen offline install, typecheck, 962 общих теста и build — PASS. Сверка плана и dry-run после сборки — PASS. Проверки ссылок документации и git diff --check — PASS. Сборка сохранила прежние предупреждения Zod annotations и web chunk >500 kB. Полный общий PG suite не запускался; выполнена отдельная реальная интеграционная проверка этого среза на копии PostgreSQL.
