# Состав команды и команда игрока — BUG_REPORT №1/9

Карточки команды и игрока используют общий сохранённый реестр OpenDota
`/proPlayers`. В карточке команды появился блок «Состав по OpenDota», в карточке
игрока — «Команда по OpenDota». Кнопка «Обновить из OpenDota» запрашивает реестр,
если общий часовой кэш устарел. Обычное открытие карточки провайдера не вызывает.

Это текущие сведения источника о принадлежности, а не гарантированная заявка
на будущую встречу. Дата трансфера неизвестна. Для прогноза действует выбранная
владельцем пятёрка. Последний наблюдавшийся состав завершённой карты остаётся
отдельным историческим блоком.

## Связи и границы данных

- Команда сопоставляется по `teams.opendota_team_id`, игрок — только по
  подтверждённой однозначной связи canonical player ↔ числовой аккаунт.
- Совпадение ника, устаревшее поле `players.opendota_account_id` или участие
  в прошлой карте не заменяют проверку личности/текущей принадлежности.
- Все перечисленные источником участники показаны без искусственного ограничения
  до пяти. Неизвестный или конфликтующий аккаунт имеет ссылку на OpenDota,
  но не связывается с произвольной локальной карточкой.
- Отсутствие команды/игрока в реестре не означает распад или статус свободного
  агента. Отсутствие подтверждённого аккаунта показывается отдельно.
- Проверяются схема, уникальность аккаунтов, SHA исходного ответа, endpoint,
  время получения и соответствие Steam64/Steam32. Непроверенный кэш не отображается.
- При ошибке обновления прежняя валидная запись остаётся видимой с пометкой
  об устаревании. Сохраняются общий quota budget, Retry-After, lease/cooldown и
  single-flight существующего клиента. Повторный просмотр другой карточки
  использует тот же реестр.

## HTTP и реализация

`GET /api/v1/{teams|players}/:id/roster-context` — локальное чтение.
`POST /api/v1/{teams|players}/:id/roster-context/refresh` — явное обновление,
строго пустое тело `{}`. Оба метода требуют owner session, POST также Origin/CSRF.
Query-параметры запрещены; некорректный ID/параметры — 400, отсутствующая локальная
запись — 404. Ошибка провайдера отражается в `source.refreshFailed`, без выдачи
технических подробностей или подмены состава.

Ответ версии 1 содержит статус, список участников, подтверждённый аккаунт
игрока, nullable local/provider team IDs, разрешение на обновление и источник
с fetchedAt/SHA. `eventAt` и `knownAt` остаются null: время загрузки не является
датой перехода. BIGINT ID передаются строками.

API-оркестрация и read-model находятся в `apps/api/src/modules/catalog/roster-context-*`.
Чистая Zod-схема `roster-context-contract.ts` импортируется Vue-компонентом
`CurrentRoster.vue` напрямую; серверные зависимости в неё не входят. Это
ограниченный presentation-контракт: frozen `packages/contracts` и вычислительные
пакеты активной V1 не изменяются. Обобщение этого контракта в пакет требует
отдельного решения с проверкой совместимости frozen runtime.

Чтение выполняется в repeatable-read transaction. Обновление устаревшего кэша
использует compare-and-set; ответ запоздавшего GET не перезаписывает результат
обновления в Vue Query. Остальные карточки инвалидируются. Выход из аккаунта
не допускает запись позднего ответа в приватный кэш.

Исторические таблицы, canonical metadata, ручные составы, сценарии и прогнозы
не переписываются. Миграций и новых зависимостей нет. Роли, архив команд и
остальные подписи ID остаются отдельными пунктами BUG_REPORT.
