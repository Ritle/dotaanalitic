# S1-16 — итоговый аудит числовых подписей №7

Дата: 11 ноября 2026. Задача: `S1-16/BUG_REPORT/readable-labels/final-audit`.
Аудит завершён как отдельная задача; весь BUG_REPORT №7 остаётся частичным.

## Что проверено и исправлено

Статический просмотр 57 Vue-файлов в `apps/web/src`, поиск интерполяций ID и
проверка связанных formatter helpers выявили остаток, приведённый ниже.
Это аудит исходников, а не утверждение о браузерной проверке всех экранов.

В RoleProfiles и RoleSuggestions основная строка теперь содержит только
ник/подпись выбранного игрока. Внутренний ID доступен в раскрываемых
основаниях либо «Данных игрока». Для исторической подсказки этот блок
доступен с клавиатуры. При отсутствующем имени выводится «Имя недоступно»,
при пустом — «Игрок без ника». Свежий проверенный alias источника сохраняет
прежний приоритет; для неразрешённой личности доступно только выбранное
display-имя. Одинаковые ники остаются отдельными записями с разными ID.

Никакой поиск аккаунта по нику, новый запрос, смена роли или изменение
eligibility не добавлены. Numeric payload, история, N, выбранные герои,
замены и подтверждения сохраняются. Эти подписи не являются историческим
доказательством участия игрока. Backend, SQL и общие пакеты не менялись.
Дополнительно исправлен найденный браузерным тестом пропуск: ScenariosView
теперь передаёт известные имена и в историческую ветку без выбранной
команды. Ранее этот prop условно отключался, хотя игроки оставались выбранными.

## Числа, которые остаются осмысленными

- Steam32/числовой аккаунт, OpenDota map ID и проверяемая series ID нужны
  при сопоставлении игрока и результата. Ник и название турнира их не заменяют.
- PandaScore team/player/tournament/match IDs и STRATZ team/account IDs нужны
  в форме явного межпровайдерного соответствия. Ссылки на источник, подписи
  имени и раскрытие ключа полезны вместе; локальный ID не является внешним ID.
- Model UUID, requestId, snapshot/artifact SHA, ревизии и provider receipts
  — ключи воспроизводимости. Их не переименовывать в названия сущностей.
- Номер карты/роли/слота, количество карт/N, проценты, рейтинг, страница и
  дата — значения, а не отсутствующие названия. Слоты не выдаются за роли.
- Technical details и сохранённый исходный JSON содержат ID намеренно;
  удаление их усложнило бы проверку и воспроизведение.

Каталог/поиск, имена текущих команд, основные сравнения/H2H, фильтры,
раскрытая история героев, составы сохранённых аналитических отчётов и
source matching уже получили именованные подписи в предыдущих срезах.
ScheduleTargetDetails уже хранит имена локальных команд/турнира, а числовое
соответствие показывает отдельно. Дубли и отсутствие metadata требуют
честного fallback, а не подмены identity. Поиск ID в исходниках сам по себе
не доказывает баг: большинство совпадений — keys, маршруты и payload.
