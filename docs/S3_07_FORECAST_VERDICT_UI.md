# S3-07 — понятный итог прогноза

16 ноября 2026. Срез `S3-07/forecast-verdict-ui` выбран пользователем вместо очередного шага сборщика Draft Lab.

## Что видит пользователь

Журнал открывает последний сохранённый отчёт, если конкретная версия не выбрана в адресе. Сначала показаны итоги и карточки прогнозов; создание нового отчёта и история находятся ниже, с быстрыми переходами вверху страницы. На широком экране карточки располагаются рядом, на телефоне — в одну колонку без горизонтальной прокрутки. Составы, причины исключения, метрики Brier/log loss, калибровка и идентификаторы доступны в раскрывающихся блоках.

У каждой карточки есть отдельный итог с текстом, знаком и цветом:

| Состояние | Отображение |
|---|---|
| Проверенный фаворит выиграл карту | «Прогноз верен», зелёный |
| Проверенный фаворит проиграл карту | «Прогноз неверен», красный |
| Исход отсутствует или ещё не проверен | «Ожидает результата» |
| Нет проверенной связи со сыгранной картой | «Нужно связать с картой» |
| Владелец отметил отмену | «Встреча отменена»; не ошибка прогноза |
| Вероятность не выдана | «Прогноз не выдан» |
| Ровно0,5 | «Фаворит не выбран»; не верный и не неверный прогноз |
| Условный расчёт / исключённая запись | «Условный расчёт» / «Не оценивается» |
| Источник изменился или данные противоречат друг другу | «Нужна повторная проверка» |

Рядом сопоставлены «Прогнозировали победу» и «Фактически победила», указаны A/B, названия команд и сохранённая вероятность фаворита. Названия читаются из текущего локального каталога, не восстанавливаются из строки названия встречи. При недоступном имени остаётся сторона и явная отметка неизвестного названия. Подписи не меняют идентичность команды или результат.

Тот же блок используется при просмотре сверки конкретного прогноза из расписания. Для архивной сверки явно указаны дата и редакция. Допуск к предматчевой статистике и выбор основного прогноза остаются отдельными понятиями: предыдущий пересчёт может оказаться верным, но не увеличивает общий счётчик точности.

## Алгоритм и границы

Фаворит определяется по исходной, неокруглённой вероятности: больше0,5 — A, меньше0,5 — B. Сравнение выполняется только с проверенным победителем карты. Для журнала результат дополнительно сверяется с сохранённым `correct`; несовпадение не окрашивается как победа/ошибка, а требует проверки. A/B не переводятся в Radiant/Dire по расположению элементов.

Общие счётчики «верные», «неверные» и точность берутся из всего сохранённого отчёта, не пересчитываются по текущей странице. Неверные = `accuracyN - correct`; равные вероятности не входят в `accuracyN`. `null`-точность отображается прочерком. Дата отчёта видима: открытие журнала не создаёт новый снимок и не обновляет фактические исходы автоматически.

Расчёт модели, серверные критерии допуска и выбор основного прогноза не меняются. Новых API-контрактов, миграций, внешних provider-запросов и перезаписи старых прогнозов нет. Для подписей используется существующий лимит двух команд за запрос, кэш на5минут и объединение одинаковых пар через Vue Query. Составы игроков загружаются только при раскрытии соответствующего блока.
