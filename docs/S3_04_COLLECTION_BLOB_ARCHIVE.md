# S3-04 — отдельный архив исходных ответов

Внутренний компонент `ConditionalBlobArchive` сохраняет исходные байты в PostgreSQL отдельно от компактного журнала. Это следующий срез после [регистрации v2](S3_04_REGISTRATION_V2_STORAGE.md). Прежний сборщик с inline-журналом 64 МиБ сохранён для воспроизведения; новый архив ещё нужно подключить к учёту запросов и транспорту v2.

## Что реализовано

- SQL067 добавляет четыре таблицы: заголовок архива, тела по SHA-256, квитанции ответов и цепочку коротких ссылок. SQL001–066 и прежние исполняемые модули не меняются.
- Инициализация требует активного владельца, подтверждённой регистрации v2, её ожидаемого SHA и двух новых файлов в закреплённом executable manifest. Проверяются прежний runtime manifest, исходный exposure и среда. Настройки архива неизменяемы. Для существующей регистрации без этих двух файлов подключение запрещено.
- `saveResponse` одной транзакцией сохраняет тело и квитанцию. SHA считается по исходным байтам, включая некорректный UTF-8, пустой ответ и некорректный JSON. Это свидетельство полученного ответа, а не подтверждение профессиональной карты. `knownAt` остаётся `null`; время получения не объявляется исторической доступностью данных.
- Повтор с теми же request/operation ID и содержимым возвращает сохранённую квитанцию. Изменение содержимого или повторное использование operation ID для другого запроса отклоняется. Одинаковые тела в одной регистрации занимают место один раз.
- `appendResponse` отдельной транзакцией добавляет ссылку с проверкой предыдущего SHA. Если квитанция уже зафиксирована, а журнал не обновился, её можно завершить по request ID без тела от вызывающего кода и без повторного HTTP. Если тело вообще не было зафиксировано, восстановить его этим способом нельзя.
- `replay` читает согласованный снимок: страницы до 100 записей, каждое уникальное тело отдельно. Проверяет заголовок, цепочку, квитанции, SHA/размеры, часы и оставшиеся незавершённые записи. Весь архив не преобразуется в один JSON.
- INSERT-проверки SQL защищают границы размеров, SHA, связи, порядок, часы, форматы метаданных и активного владельца. UPDATE/DELETE/TRUNCATE запрещены. Отложенная проверка не позволяет зафиксировать тело без квитанции. Проверка файлов и среды выполняется адаптером; SQL сам не аттестует файловую систему.

## Ограничения ёмкости

| Предел | Значение |
| --- | --- |
| Одно исходное тело | 8 МиБ |
| Все уникальные тела архивов в одной БД | 512 МиБ |
| Архив регистрации | Неизменяемый предел до 512 МиБ |
| Квитанции регистрации | До 1000 и не больше закреплённого бюджета попыток |
| Метаданные одной квитанции | 16 КиБ |
| Одна запись цепочки | 4 КиБ |

Подсчёт места и запись сериализуются общей advisory-блокировкой, запись разрешена только при READ COMMITTED. Снимок остатка места не резервирует байты: запись всегда проверяет предел заново. Считается логический размер уникальных исходных тел, не физический размер PostgreSQL, WAL или свободного диска. Ошибка диска откатывает транзакцию. Автоматического удаления старых доказательств нет; исчерпание общего предела требует отдельного решения.

## Границы этого среза

Архив предназначен для полных ответов 2xx OpenDota, переданных внутренним вызывающим кодом, с ограниченными путями `/matches/:id`, `/leagues/:id/matches`, `/proMatches`. Полноту HTTP-передачи должен проверять транспорт: архив проверяет целостность сохранённых байтов. Он не отправляет HTTP, не доказывает подлинность переданных байтов, принадлежность карты зарегистрированному турниру или полноту выборки. `receivedAt` — наблюдение вызывающего кода, ограниченное серверными часами. Реестры запросов, окно сбора, квоты, полнота обходов и оценка карт остаются обязанностью следующего слоя.

Сохранение архивного свидетельства до окна сбора не разрешает начать сбор. `collectionAllowed`, `realEvaluationAllowed`, `activationAllowed`, `deployable` остаются `false`. SQL066 по-прежнему запрещает запуск прежнего журнала для v2. Новых API/CLI для реального сбора нет. Миграция применяется только к временным тестовым базам; рабочая БД остаётся на061.

При сопоставлении рабочей базы обнаружены25 карт из отдельного завершённого обновления истории игроков:12 уже входят в базовый список изученных карт,13 находятся вне него. Перед реальной регистрацией нужно обновить дополнительный exposure snapshot по текущим картам и сериям; замороженный базовый файл не менять. Существующая серверная проверка регистрации требует актуального перечня исключений.

## Проверка

Проверяются точные повторы и конфликты, конкурентное заполнение места, CAS журнала, откат тела при ошибке квитанции, восстановление незавершённой записи, права владельца, некорректные кодировки, изменение исходного буфера вызывающим кодом, повреждения SHA и неизменяемость таблиц. Нагрузочный сценарий использует 12 разных синтетических тел по6 МиБ. Это проверка логической ёмкости и воспроизведения, не измерение физического диска и не реальное покрытие API.
