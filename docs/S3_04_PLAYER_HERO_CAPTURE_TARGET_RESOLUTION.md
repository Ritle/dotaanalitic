# S3-04 — проверка фактической карты для снимка драфта

Реализован **offline-срез** `player-hero-capture-target-resolution`. Проверка читает локальные снимки и карты, сохраняет самостоятельный неизменяемый JSON-отчёт и воспроизводит результат по внешнему SHA. Автоматическая привязка в приложении, точная граница начала игрового процесса и пригодность для независимой оценки остаются открытыми. Это не прогноз после драфта.

## Что проверяется

- Исходный снимок из SQL058 читается с проверкой SHA; его JSON, часы, игроки и история не меняются.
- Кандидаты — все локальные карты той же пары организаций, без угадывания временного окна, сортировки «первая/вторая карта» или совпадения ников.
- Проверенный завершённый pro-исход нужен только как подтверждение реальной карты. Применяется прежний `OutcomeVerifier` с проверкой receipt и классификации профессиональной лиги. Исход не становится признаком.
- Provider series ID сравнивается только в одном пространстве идентификаторов. Первый поддержанный путь — OpenDota series → OpenDota receipt. Числовое совпадение PandaScore/OpenDota не принимается; существующая V1-привязка первой карты не переносится на произвольный post-draft ordinal.
- Номер карты требует отдельного accepted `context.map_number` с evidence reference, согласованным SHA значения и часами записи/получения. Значение должно совпасть с canonical map number и номером в снимке. Конфликт, отсутствие, поздняя относительно проверки запись или неподтверждённое значение сохраняются как причины отказа.
- Проверяются десять различных Steam32, героев и корректных слотов, source receipt ↔ canonical players, затем A/B/account → hero ↔ фактическая сторона. A/B не приравниваются Radiant/Dire, роль не приравнивается слоту массива. Перестановка транспортных строк не меняет результат.
- Две подходящие карты дают `AMBIGUOUS_MAP`, а не выбор первой. Дубли одного map ID отклоняются.

`bindingStatus: matched` означает единственное совпадение в проверенном локальном инвентаре, **не** полноту удалённого источника или model eligibility. История снимка может оставаться непригодной для модели даже при успешном сопоставлении карты.

Счётчик `matched` относится к снимкам с найденной связью. Несколько снимков одной фактической карты не превращаются в несколько обучающих примеров; этот отчёт не формирует training dataset или статистику качества прогнозов.

## Время проверяется отдельно

`decisionCutoffAt` и серверный `recordedAt` сравниваются с сохранённым provider start в целых микросекундах, через BigInt. Оба должны быть строго раньше; равенство не проходит. Время сохранения после provider start отображается как `not_before_provider_start`.

Если оба времени раньше, статус — `before_provider_start_semantics_unverified`. Предыдущий [аудит источников](S3_04_PLAYER_HERO_PROSPECTIVE_SOURCE_READINESS.md) не установил точную семантику UTC начала относительно драфта/pregame. Совпадение часов источников не закрывает этот вопрос. Поэтому **во всех результатах `prestartVerified:false`, `primaryEligible:false`, `deployable:false`**. В модуле нет переключателя, позволяющего пользователю назвать неподтверждённые часы проверенными.

Позднее полученные факты о фактической карте разрешены для этой ретроспективной сверки. Они не добавляются в старые признаки или историю снимка. Плановое начало встречи не подменяет время начала карты.

## Хранение и запуск

После сборки:

```powershell
node --env-file-if-exists=.env tools/audits/draft-target-resolution.mjs capture .tools/target-audit-new.json
node tools/audits/draft-target-resolution.mjs verify .tools/target-audit-new.json SHA_ИЗ_ПЕРВОЙ_КОМАНДЫ
```

Нужен новый JSON-путь внутри проекта. Перезапись запрещена (`wx`). Отчёт содержит frozen source input, его SHA, отпечатки кода и полный ledger кандидатов/причин. Проверка требует внешний SHA файла, совпадение кода и точный повтор расчёта; подмена результата, кода, источника и незаявленных полей отклоняется. Это локальный audit artifact, не зарегистрированная DB-привязка или защищённый журнал прогнозов.

Коллектор использует repeatable-read транзакцию, только SELECT и share locks прежнего verifier; DML/HTTP нет. Предельные размеры: 100 снимков, 200 кандидатов на снимок, 100 ordinal observations на карту, 60 MiB source budget и 64 MiB итоговый файл. Превышение отказывает целиком, не выдаёт успешный усечённый результат. У SQL есть statement/lock timeout. Частные исходные снимки сохраняются только в локальном ignored файле, в консоль выводятся счётчики и SHA.
