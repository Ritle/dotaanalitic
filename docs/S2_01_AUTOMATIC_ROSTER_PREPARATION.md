# Автоматическая подготовка составов

S2-01/automatic-roster-preparation · решение владельца2026-11-05 после проверки Yellow Submarine — GamerLegion.

## Как пользоваться

Выберите встречу. Сервис читает сохранённые пятёрки и подготавливает аккаунты для отсутствующих составов. В карточке команды сразу видны игроки заявки и состояние поиска.

- Готовая сохранённая пятёрка подставляется сразу.
- Если все пять участников уже имеют проверенные общие связи PandaScore player ID → canonical player ID/Steam32, эти связи переиспользуются автоматически, в том числе после перехода в другую организацию.
- Для новых соответствий по никам показаны имена и Steam32. Проверьте их и нажмите **«Подтвердить аккаунты и выбрать пятёрку A/B»**. Это одно действие для всей пятёрки; сравнение по-прежнему требует подтверждения выбранного состава.
- При шести и более участниках отметьте нужных пятерых прямо в карточке. Неизвестный или отсутствующий в заявке запасной автоматически не определяется.
- При неоднозначности, конфликте или отсутствии аккаунта нажмите **«Уточнить аккаунты A/B»**. Расширенный поиск и исправление соответствий доступны в прежней форме.

Точное совпадение текущего имени или сохранённого псевдонима имеет приоритет перед частичным совпадением при подготовке. Например, единственный точный RCY предпочтительнее mercy, найденного по подстроке. Если один точный ник/псевдоним принадлежит нескольким числовым аккаунтам, неоднозначность сохраняется. Совпадение имени остаётся предложением и не создаёт связь автоматически.

Числовой ник из заявки, например86, остаётся именем. Подготовка не делает из него запрос профиля Steam32=86. Явный ручной поиск по числовому аккаунту сохраняет прежнее поведение.

## Исправить аккаунт в сохранённой пятёрке

Откройте **«Подготовить составы» → «Выбрать или исправить аккаунты A/B»**. Если игрок скрыт, включите **«Показать подтверждённые аккаунты A/B»**. Найдите правильный числовой профиль в поле этого игрока и нажмите найденную запись. После смены аккаунта снова отметьте **«Подтверждаю соответствие команды и пяти аккаунтов A/B»**, затем нажмите **«Сохранить связи и подставить пятёрку A/B»**.

При открытии пригодной сохранённой пятёрки восстанавливаются выбранные игроки, их аккаунты и ранее проверенная внешняя ссылка команды. Повторно нажимать «Подготовить игроков» или выбирать организацию для исправления одного аккаунта не нужно. Сохранение остаётся явным; пять аккаунтов должны быть различными. Если сохранённая связь команды непригодна либо в ней нет проверенного источника организации, команду выбирают в форме отдельно.

## Запросы и сохранность выбора

Автоматический `/catalogue/prepare` отправляет `{externalSearch:false}`: проверяются общие связи, локальные подтверждённые аккаунты/псевдонимы и общий кэш реестра OpenDota. Внешний поиск по отдельным никам автоматически не запускается. В ручном запросе `{}` прежний ограниченный поиск до трёх имён сохранён. Отложенный поиск отделён от сбоя источника через необязательный `reason`.

Подготовка кэшируется на клиенте на60 секунд по встрече, SHA заявки и режиму поиска; автоматическая ошибка не запускает цикл повторов. Оба пригодных сохранённых состава не требуют подготовки. Сохранение пятёрки перечитывает связи и обновляет optimistic tokens без повторного поиска всех участников.

Автоматический выбор возможен только в нетронутом редакторе. Открытие ручного редактирования или формы аккаунтов останавливает автоподстановку. Задержавшийся ответ не заменяет ручной выбор; изменившаяся заявка, конфликт token/revision и повторный аккаунт блокируются существующими проверками. Источники, часы и SHA сохраняются в прежнем immutable binding. Автоматическое переиспользование уже проверенных связей разрешено владельцем для этой версии; новые соответствия аккаунтов требуют отдельного явного подтверждения.

SQL и модельные признаки не менялись. Выбор ожидаемой пятёрки не подтверждает явку, не загружает карты и не активирует прогноз. Персональные исправления для GL не добавлены.

## Уточнение аккаунтов

По запросу владельца подтверждённые соответствия скрыты в форме уточнения по умолчанию. Видны счётчики подтверждённых записей и тех, которым нужна проверка. Переключатель **«Показать подтверждённые аккаунты A/B»** раскрывает записи для исправления. Сохранённая пятёрка также свёрнута в отдельный раздел.

Скрываются только пригодные сохранённые связи или актуальные проверенные общие связи. Предварительный кандидат по нику, конфликт и изменённый аккаунт остаются видимыми. Очистка поля при ручном поиске не скрывает редактируемую строку. Выбранные участники и аккаунты сохраняются при сворачивании; скрытые подтверждённые значения переиспользуются в черновике, их не требуется выбирать заново. Фильтр не делает запросов к источникам.

## Приоритет кандидатов с pro-историей

Среди найденных аккаунтов сначала показываются точные совпадения имени/псевдонима, затем аккаунты с завершёнными pro-картами в локальной базе. Явный числовой ID всегда ищет именно указанный аккаунт. Размер выборки не используется для выбора личности: два аккаунта с pro-картами остаются спорными, порядок внутри этой группы стабилен.

Если в неоднозначном списке ровно у одного проверенного локального аккаунта есть pro-карты, он предлагается в черновике с пояснением. Статус неоднозначности сохраняется, остальные кандидаты доступны, новую связь подтверждает владелец. Сохранённые привязки и ручные исправления таким приоритетом не заменяются.

Счётчик показывает только загруженные завершённые карты с положительным `is_pro`, до времени запроса; паблики, будущие карты и конфликтные записи не учитываются. Неизвестная история не заменяется нулём. Ноль локальных карт не доказывает отсутствие профессионального опыта и не блокирует ручной выбор. Дополнительные запросы за историей ради ранжирования не выполняются.

Приоритет работает среди найденных кандидатов. Он не обнаружит аккаунт с полностью другим ником без соответствующего числового ID или сохранённого псевдонима. Такой профиль сначала находят по ID/распознанной ссылке, затем подтверждают соответствие. Dota2ProTracker автоматически не читается.
