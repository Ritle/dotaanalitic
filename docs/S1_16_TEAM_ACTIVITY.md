# S1-16 / BUG_REPORT — активность команд и архив

## Поведение

В карточке команды есть отдельная отметка активности: «Активна», «Неактивна»
или «Неизвестно». Основание — проверенный источник с HTTPS-ссылкой либо
явное решение владельца для личного справочника. Пояснение обязательно.
Приложение не загружает ссылку и не устанавливает статус по отсутствию карт,
числу участников, давности синхронизации или совпадению названия.

В справочнике по умолчанию скрыты только команды с отметкой «Неактивна».
Фильтр «Архив: неактивные» открывает их список; «Все команды» объединяет оба
списка. Неизвестная активность оставляет команду видимой. В поиске команды
для сравнения доступен флажок «Искать также в архиве команд».
Прямая ссылка, история карт и ранее выбранные составы сохраняются.

Чтобы вернуть команду, откройте её через архив → «Изменить статус команды» →
«Активна» или «Неизвестно», укажите основание и сохраните. Прежняя отметка
останется в истории. Показаны последние 20 отметок; более ранние хранятся в
БД, отдельной страницы для них пока нет. Автоматического мониторинга статуса нет.

Отметка относится к организации в личном справочнике. Она не подтверждает
пятёрку для будущей карты, не является историческим признаком, не меняет Elo
и не отменяет проверки состава/истории/турнира при прогнозе.

## Контракт и хранение

- `GET /api/v1/team-directory`: прежние `query`, `limit`, `offset` плюс
  `activityView=current|archived|all` (по умолчанию `current`). Фильтрация до
  пагинации, стабильная сортировка по имени и числовому ID. В каждой записи
  `activityStatus`; источник `local_catalog`. Старый `/api/v1/teams` остаётся
  включающим все команды для совместимости.
- `GET /api/v1/teams/:id/activity`: `teamId`, nullable `current`, `history`,
  `hasMore`, `computedAt`. Без параметров запроса, только сессия владельца.
- `POST` по тому же пути: сессия + CSRF; строгое тело `requestId` UUID,
  `expectedRevision`, `status`, `basis=source|owner`, nullable `sourceUrl`,
  `note`, `checkedAt`, nullable `effectiveAt`. Для `source` обязательна HTTPS
  ссылка без встроенных credentials; для `owner` ссылка должна быть null.
  Даты передаются в UTC. Невалидное тело/будущая проверка — 400, отсутствующая
  команда — 404, устаревшая редакция/изменённый повтор — 409.
- `checkedAt` — когда проверено основание; `effectiveAt` — известная дата
  изменения статуса, не позднее проверки; `recordedAt` — время записи на
  сервере. Неизвестная дата изменения остаётся null. Поля формы используют
  часовой пояс браузера, отображение дат — UTC.
- SQL052 добавляет `team_activity_reviews`: append-only журнал с привязкой к
  owner и точному team ID. Триггер запрещает UPDATE/DELETE. Advisory locks,
  unique request ID и проверка редакции защищают от повторов и гонок.
  Точный повтор возвращает исходную запись, UI затем перечитывает актуальную.
  Разные организации с одинаковым названием не объединяются.

Контракты представлены в `apps/api/src/modules/catalog/team-activity-contract.ts`
и переиспользуются Vue. Замороженные packages/contracts и вычислительные
модули V1 не менялись. Миграция применяется обычным `pnpm db:migrate`;
SQL001–051 не изменены.

## Рабочая проверка 10 ноября 2026

BetBoom (локальная запись 607) отмечен неактивным по
[официальному заявлению клуба](https://betboom.team/). Дата начала неизвестна.
Две отдельные записи B8 (288/289) убраны в личный архив по прямому замечанию
владельца в BUG_REPORT. Это основание `owner`, без утверждения об официальном
статусе клуба и без объединения организаций.

Все три отметки сохранены через интерфейс. Проверены обычный поиск, архив,
доступ к истории, ширина 360px и выход из сессии. Новых provider HTTP нет.
До изменения создан custom-format backup; восстановление в отдельную БД
сверено по всем 84 public-таблицам и 12 заданиям очереди, затем на копии
выполнены SQL052, повторный запуск и проверка допуска активной модели.
На рабочей БД миграция применена, повтор пропущен; API перезапущен.

Итоговые результаты тестов и проверки сохранности — в
[evidence](evidence/bug-report-team-activity.json).
