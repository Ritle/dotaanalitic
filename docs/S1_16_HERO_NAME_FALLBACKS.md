# S1-16 — неизвестное имя героя и точный ключ

Срез №7: `S1-16/BUG_REPORT/readable-labels/cosmetic-fallback`.

В Draft Lab, рейтинговой практике и её подробностях, таблице игроков,
meta и парах сохранённого отчёта используются одинаковые подписи:

| Данные | Подпись |
|---|---|
| Известное непустое имя | Прочитанное имя |
| ID известен, название отсутствует | Название героя недоступно |
| ID известен, имя пустое или из пробелов | Герой без названия |
| Герой не назначен | Прежнее пустое значение выбора; в отчёте «Не назначен · все герои» |

Точный ID находится в «Данных записи». У героев нет выдуманной profile-ссылки.
В нативном списке выбора имя дополнено `ID`: раскрытие подробностей внутри
`option` невозможно, а одинаковые или пустые имена надо различать.
Значение option и исходный hero ID не меняются.

DraftEditor помнит уже прочитанные имена по hero ID до закрытия редактора.
Поиск, пустая выдача и ошибка не стирают эти подписи и выбранные значения.
Следующий успешный ответ с тем же ID может обновить имя. Герой вне текущих
результатов остаётся отдельным выбранным option; это относится и к ещё не
добавленному бану. Кэш не получает имена от соседнего ID, роли или ника игрока.
Никаких дополнительных HTTP-запросов, постоянного хранилища или импорта нет.

Рейтинговая практика сохраняет отдельные публичные N/WR/период/провайдера.
Сохранённый отчёт использует собственное frozen имя, а не обновляет его из
текущего каталога. Старый текстовый placeholder, уже записанный как имя,
остаётся текстом снимка; из него не восстанавливается название. Пустые и
nullable имена форматируются при отображении, без перезаписи JSON/hash.
Цифровые map/series/model IDs и provenance по-прежнему доступны.
