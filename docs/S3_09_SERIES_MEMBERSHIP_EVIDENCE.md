# S3-09 — полный список карт и начало серии

16 ноября 2026. Завершён срез `series-corpus-and-protocol/membership-evidence`: реализована offline-проверка полного состава серии по сохранённому официальному источнику и измерено реальное покрытие. **Подтверждены 35 серий / 77 карт: 5 BO1 и 30 BO3.** Это development-корпус; ни оценка качества, ни регистрация независимого теста, ни активация модели не выполнялись.

## Источник и границы доказательства

Использованы два уже сохранённых ответа Valve `GetLeagueData/v001`: лиги **16935** и **17765**. Проверены точные SHA исходных байтов, URL/league ID, clocks из прежних квитанций. Значения `ELeagueNodeType` сверяются с ранее закреплённым protobuf SHA; это зеркало SteamTracking, а не принадлежащий Valve репозиторий. Исходные receipt-файлы: [BO2/source](evidence/s1-08-bo2-source.json) и локальный `.tools/s3-01-e1-valve-source.json`.

В этих ответах есть 150 узлов турнирной сетки и 155 записей `series_infos`. Это разные списки, их нельзя считать взаимно однозначными. Для выбранного узла проверяются одновременно:

- `has_started=true`, `is_completed=true`, поддержанный и согласованный формат из двух разных enum;
- точное совпадение списков native Dota map IDs в `node.matches`, `series_infos` и каноническом корпусе;
- числовые league/team IDs с явным переводом canonical teams → внешние команды каждой карты;
- победитель и длительность каждой карты, подтверждённые существующим `OutcomeVerifier` в corpus snapshot;
- итоговый счёт узла равен числу реальных побед в перечисленных картах; нет лишних карт после решающей победы;
- источник получен после завершения карт, не позже даты используемого corpus snapshot.

Связь namespace Valve ↔ OpenDota устанавливается **по пересечению native map IDs и затем проверке полного набора**, не по одинаковому номеру серии, никнеймам или названию команды. Несколько подходящих узлов считаются неоднозначностью. Автоматических записей aliases в БД нет.

После успешной проверки `verifiedSeriesStartAt` берётся из первой по времени канонической карты полного списка. `actual_time` узла и `series_infos.start_time` сохраняются отдельно как сообщённые источником времена: они могут отличаться на секунды и не заменяют начало канонической карты. `known_at` до матча не придумывается; результат явно `historically_reconstructed_not_prestart_known`.

## Покрытие и обнаруженные ошибки

Знаменатель прежнего аудита сохранён: **1112 групп / 2259 карт**, 26 pro-карт без серии остаются вне этой группировки. Source snapshot корпуса: `2026-11-16T01:08:19.915Z`.

| Формат | Локальных групп | Есть подходящий архивный узел | Полнота и исход подтверждены |
|---|---:|---:|---:|
| BO1 | 158 | 5 | 5 |
| BO2 | 225 | 58 | 0 — вне выбранного режима |
| BO3 | 693 | 33 | 30 |
| BO5 | 36 | 2 | 0 |

Для **1014 групп** подходящего узла в двух архивах нет. Это отсутствие свидетельства в выбранных архивах, а не доказательство отсутствия данных у API. Все 35 принятых серий относятся к лиге17765; они уже просмотрены и не являются независимым release holdout. `seriesLabelReady=true` подтверждает только состав/исход/начало серии; `datasetEligible=false` сохраняется до построения и проверки входных признаков.

Два конкретных противоречия источника:

| Лига / source series ID | Итоговый счёт узла | Перечислено карт | Решение |
|---|---|---:|---|
| 17765 / 952116, BO3 | 0:2 | 1 | Неполный список, не использовать как полную серию |
| 17765 / 954819, BO5 | 2:3 | 2 | Неполный список, не использовать как полную серию |

Оба узла отмечены завершёнными, а два source-списка согласованы друг с другом. Именно сверка счёта с фактическими победителями обнаруживает проблему. По этим данным нельзя автоматически решить, была ли причиной смена lobby/series ID, ошибка источника или иной случай; соседние группы не склеиваются по догадке.

Ещё в пяти сопоставленных группах не хватает локальных карт: `903379`, `903582` (BO2), `903863`, `904699` (BO3), `905925` (BO5). У последних трёх по две недостающие карты, их native IDs сохранены в отчёте. Загрузка этих шести карт — возможное расширение development-корпуса, но не выполненная часть текущего среза. Не нужно заново вручную подтверждать игроков для установления этих source-связей.

## Реализация и воспроизведение

- [series-membership-core.mjs](../tools/research/series-membership-core.mjs): разбор ограниченного дерева узлов, проверки соответствия и отдельный результат полноты. Прежний corpus replay проверяется целиком, его файлы не переписываются.
- [series-membership.mjs](../tools/research/series-membership.mjs): явные `build`/`verify`, ограниченные пути/размеры, входные SHA и code manifest, исключающее перезапись создание отчёта. Ни БД, ни сети, ни inference этот CLI не использует.
- [series-membership.test.mjs](../tests/node/series-membership.test.mjs): синтетические случаи правильной/неполной серии, неправильного источника, сторон, формата, времени, дубликатов и неоднозначности.

```powershell
node tools/research/series-membership.mjs build .tools/s309-membership-input.json 7cdeeb060dafd0994ff64b0999d067b564da442b6363ea251451c96e6c702c7d .tools/NEW-series-membership.json
node tools/research/series-membership.mjs verify .tools/s309-membership-r2.json 7a8c4d61ada459e63a9ee42ea08186f3816f46a47b273ea9cf61026650b13067
node --test tests/node/series-membership.test.mjs tests/node/series-corpus.test.mjs
```

Входной manifest связывает прежний corpus, exposure inventory, два raw ответа и pinned protobuf. В выходе сохранены source/node/series IDs, списки недостающих/лишних карт, причины отказа и код проверки. Подмена результата с пересчитанным внешним SHA всё равно отвергается replay. [Evidence и результаты проверок](evidence/s3-09-series-membership.json).

Архивов оказалось достаточно для первого положительного корпуса и проверки общей логики; новых HTTP-запросов и записей в рабочую БД **0**. Live OpenDota field audit того же дня остаётся в [foundation evidence](evidence/s3-09-series-foundation.json); новых provider-клиентов и обходов квот не добавлено. Активное ядро модели карты не менялось.
