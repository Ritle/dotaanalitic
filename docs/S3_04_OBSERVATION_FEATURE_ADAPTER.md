# S3-04 — признаки из сохранённой проверки истории

Дата: 14 ноября 2026. Срез: `player-hero-observation-feature-adapter`.

SQL060 теперь подключена к отдельной offline-подготовке числовых входов H1/H2. Адаптер читает неизменяемые наблюдения истории, SQL058-снимки и SQL059-привязки, проверяет их согласованность и запускает прежние формулы Elo и наблюдаемой практики игрока на герое. Это подготовка признаков, а не расчёт вероятности: `forecastStatus: unavailable`, `teamAWinProbability: null`, `trainingExamples: 0`, `primaryEligible/deployable: false` сохраняются при любом результате.

## Границы и время

- Pending-selection v2 закрепляет scenario/revision/hash независимо от позднего native ID. Старые selection digest не восстанавливаются и не подменяются.
- Наблюдение должно быть сохранено строго раньше decision cutoff. Проверяются реальные времена чтения, завершения проверки, сохранения и связи со снимком с точностью до микросекунд.
- Аккаунты заново сопоставляются по зафиксированным identity evidence. Конфликт, отличие от сохранённого выбора или отсутствие десяти различных подтверждённых аккаунтов останавливает расчёт. Ники не используются как идентификаторы.
- История содержит только проверенные профессиональные карты, завершённые строго до cutoff, с receipt, полученным до чтения истории. Время завершения проверки исхода — `observedAt`, а не искусственно ранняя дата.
- Исторические стороны берутся из native slots; порядок массива игроков не имеет значения. A/B выбранного сценария не приравниваются Radiant/Dire.
- Целевая native-карта исключается до использования её результата. Неизвестная серия исключается; ошибка одной исторической карты закрывает её известную серию для обоих наборов признаков. Само исключение target не удаляет допустимые более ранние карты той же серии.

При отсутствии native-привязки combined inputs остаются `null`: прежний hero builder требует реальный target ID. Диагностика Elo допускает `targetMatchId:null`; фиктивный ID не создаётся. Снимок, сохранённый слишком поздно, может дать диагностические входы на момент выбора владельца, но сохраняет причину `CAPTURE_NOT_BEFORE_PROVIDER_START`. Даже фиксация до provider start не доказывает фактический gameplay start.

## Вычисления и полнота

Используются неизменённые `createV1FeatureBuilder` и `createPlayerHeroFeatureBuilder`. H1: `[ln(10) × eloDifference / 400]`; H2 дополнительно содержит прежний `observedHeroPracticeLog90Delta`. Это наблюдаемый объём профессиональных игр на герое, не винрейт, мастерство или паблик-статистика. Рецепт не меняется по результатам этой проверки.

Hero builder получает ровно те карты, которые принял Elo builder. Неизвестные исторические герои остаются `null`, сохраняются unknown counts и предупреждения. Нулевой наблюдаемый объём не означает доказанное отсутствие опыта. При остановке до запуска builder `coverage.nRaw:null`; при действительно пустой принятой истории — `0`, входы недоступны, вероятность не подставляется.

Compact projection SQL060 явно исключает raw payloads и SQL004 field observations. `factClocks:[]` здесь означает использование другой, явно указанной границы наблюдения; это не утверждение, что в БД нет field observations. Числовой `identityRevision` для совместимости builder равен времени сохранения наблюдения в микросекундах и помечен как **не глобальная ревизия identity ledger**. Полнота внешней истории и серий неизвестна. Неизвестный patch не превращается в известный; признаков патча здесь нет.

Все снимки и попытки привязки остаются в отчёте. Один native map ID учитывается один раз в `distinctActualMaps`/`distinctFeatureReadyMaps`, при этом число диагностических снимков выводится отдельно. Обучающие примеры из снимков не создаются. Orphan observations перечисляются отдельно; legacy-снимки не дополняются задним числом.

## Запуск и воспроизведение

После обычной сборки проекта скомпилировать прежние offline kernels из исходников. Эта команда не требует приватных fit-артефактов старого исследования:

```powershell
node node_modules/typescript/bin/tsc tools/research/player-hero-prospective-features.mts tools/research/player-hero-inference.mts --strict --noUncheckedIndexedAccess --skipLibCheck --target ES2022 --module NodeNext --moduleResolution NodeNext --types node --typeRoots packages/db/node_modules/@types --outDir .tools/s304-prospective-features-runtime
node --env-file-if-exists=.env tools/audits/draft-observation-features.mjs capture .tools/NEW-observation-features.json
node tools/audits/draft-observation-features.mjs verify .tools/NEW-observation-features.json SHA256_ИЗ_CAPTURE
```

`capture` читает локальную БД в read-only repeatable-read транзакции, без API провайдеров и без записи в таблицы. Лимиты: 100 снимков, 1000 привязок, 100 observations/links, 60 MiB исходных текстовых записей, timeout30s. Превышение отклоняет весь экспорт, без незаметного усечения.

Файл создаётся только под `.tools`, эксклюзивно без перезаписи. Он содержит исходные записи, source SHA, результат и SHA окружения: код, built kernels, lockfile и миграции. `verify` проверяет переданный внешний SHA, окружение и полный offline replay; после изменения сборки старый файл может потребовать исходное окружение. SHA обеспечивает воспроизводимость, но сам по себе не удостоверяет происхождение БД или pre-start фиксацию. Файл содержит приватные данные владельца и не предназначен для git.

Код: `tools/audits/draft-observation-features{,-core}.mjs`. Проверки: `apps/api/tests/draft-observation-features{,.integration}.test.ts`, синтетическая фикстура `tests/helpers/draft-observation-features.ts`. Production API/UI, SQL-миграции и прежние research builders этим срезом не меняются.
