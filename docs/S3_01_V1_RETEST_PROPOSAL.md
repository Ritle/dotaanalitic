## Почему ориентир —250 серий

Первый failed test теперь допустим как **pilot для планирования**, но не как untouched подтверждение. Модель, K, калибровка и числовые пороги не меняются. Для каждой из58 старых серий вычислены сумма разниц потерь с baseline и число карт. При среднем отличии `d`, среднем числе карт `m` использована series influence `(sumDelta - d * mapCount) / m`; её выборочное стандартное отклонение —0,05208744 для Brier и0,10755308 для log loss.

Приближённая односторонняя normal-formula `G = ceil((z0.95 + z0.80)^2 * (sigma / abs(d))^2)` даёт224 и242 серии соответственно; ориентир округлён вверх до **250** до нового discovery. Основание формулы и оговорка о неизвестной дисперсии: [NIST: sample sizes](https://itl.nist.gov/div898/handbook/prc/section2/prc222.htm). Здесь единица планирования — серия; карты не считаются независимыми повторениями.

Это лишь приближение для **каждой** метрики при сохранении старого эффекта и дисперсии. Оно не даёт80% вероятности прохождения всех gate и не учитывает полностью общих игроков/события/предыдущую историю. При вдвое меньшем эффекте ориентир достигает965 серий.250 — ориентир достаточности подготовки, не новый числовой quality gate и не причина остановить выборку на удобном результате. В тест входят все пригодные серии фиксированного scope.

## Предлагаемый единственный запуск

1. **Регистрация:** отдельная версия протокола с теми же семью событиями/окнами, exact intent/exposure/discovery SHA и указанием первого FAIL. Старый формат ограничен пятью событиями — требуется additive version; старые protocol/collector/freeze читаются без изменения. Закрепить operational history/attempt/deadline policy до detail capture и model scoring. Повторять уже сохранённые семь запросов не требуется.
2. **Сбор:** отдельное resumable хранилище, верхний предел5 000 уникальных карт, не более3 попыток деталей каждой карты, до50 HTTP-попыток за запуск с прежней общей квотой/Retry-After. Для истории — прежнее детерминированное правило: последние10 завершённых pro-карт каждого установленного аккаунта за730 дней **до1февраля2026,00:00UTC**, аккаунты группами по пять в числовом порядке. Существующий canonical history тоже используется, но только с `completed_at < target.started_at`; warmup lower bound01.01.2024. Достижение cap и отсутствующие игроки раскрываются, история не считается полной. Позднейшие карты августа—ноября не могут попасть в признаки февральских—июньских целей.
3. **Остановка:** все ID получают terminal disposition по ограниченным попыткам, либо сбор закрывается **13ноября2026,00:00UTC /03:00МСК**. Завершить раньше можно, если все работы терминальны. Нельзя продлевать срок, добавлять турниры или догружать удобные карты после просмотра метрик. Перед scoring фиксируются весь ledger, missing/unknown/whole-series exclusions, canonical dataset, identities, outcomes, code/runtime и входной capsule. Плохие/пропущенные данные остаются в denominators.
4. **Оценка:** один запуск после завершения сбора и проверки отдельного frozen bundle. Ждать13ноября при полном завершении не требуется. Прежние Elo1500/K32/scale400, ≥5 earlier completed pro maps/player, десять различных verified accounts. Прежние sample/coverage/Brier/logLoss/calibration/stability/10k whole-series-bootstrap gate; historical quality SHA `f13ddd38c451fa53bae4f37ffaeea4c2ac852a4d50cb7cdd1156f53175737d4b`. Никаких промежуточных метрик, fitted calibrator, отбора лучшего события или попытки.
5. **Результат:** сохранить исходный FAIL и новый результат независимо от исхода; обе попытки видны в итоговом отчёте. Не заявлять familywise95% по нескольким попыткам на основании per-attempt95 bootstrap. Отложенная будущая ветка не используется как альтернативный score для выбора лучшего. Любой PASS означает только допуск к отдельному review/registry adapter, без автоматической активации.

Февраль—июнь раньше августовско-сентябрьского pilot. Расчёт истории внутри каждой карты останется временно корректным, но дизайн второго исследования уже использует сведения из более позднего первого теста. Результат нельзя выдавать за prospective проверку будущих матчей или универсальную точность Tier1. Conditional reconstructed lineups и assumed event-time availability явно сохраняются.
