Флаги без подтверждённой семантики не доказывают причинную связь или возможность исправления новым токеном.

## Решение для работающего сервиса

Самостоятельные hero statistics STRATZ **не включены**. Непустой `player.matches` cohort, его фильтры на непустой выдаче и пагинация остаются непроверенными. Ответы `match(id)` нельзя выдавать за независимый список истории или за дополнительное N поверх тех же карт OpenDota.

Рабочая таблица OpenDota продолжает показывать прежние197 карт/25 героев. История, raw WR и V1 Elo не менялись. Ошибка в production reader этой проверкой не выявлена; менять фильтры на Practice/Unranked или ослаблять eligibility оснований нет.

**Предлагаемый следующий срез — S2-07/STRATZ-enrichment:** дополнение контекста известных карт, не новый источник знаменателя статистики.

1. Взять последние20 карт одного сохранённого OpenDota observation, детерминированно по времени/ID, после повторной проверки canonical account. Запуск только явной кнопкой владельца; существующие auth/CSRF и флаг/token сохраняются.
2. Запрашивать известные ID пакетами до4 карт (такой путь реально проверен), максимум5 HTTP. Повторное открытие/нажатие использует кэш; shared quota, cooldown и single-flight ограничивают повторы. Пропуски и частичные ответы показываются явно.
3. Сохранять отдельные неизменяемые source receipts/context observations с parent observation ID, account/map IDs, actual fetchedAt/raw SHA и knownAt=null. Новая forward-only миграция; прежние ranked observations не переписывать. Точные поля контракта и cache keys определить в реализации.
4. Применять контекст только при совпадении аккаунта, героя, стороны, исхода и времён с parent map. Противоречия сохранять отдельно, исходные факты не заменять. При смене parent/identity повторно проверять применимость; старое evidence остаётся в аудите.
5. Показывать оценку позиции, provider version code и покрытие дополнения отдельно. N/wins/WR считать по прежнему OpenDota cohort; не выводить role-specific WR из выборочно дополненных20 карт и не добавлять эти поля в V1/автораспределение командных ролей. Provider version не становится canonical patch автоматически.

Этот контракт — следующий срез, **обогащение ещё не реализовано**. Ограниченная проверка источника завершена; новый аудит ещё большего числа игроков ради той же гипотезы не требуется. Для реализации: **GPT-6.1 Sol · High**. Реальный V1 collection с20 ноября03:00МСК и evaluation не ранее2 декабря03:00МСК сохраняются.
