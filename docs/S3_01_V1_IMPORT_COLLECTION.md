# S3-01/V1 — импорт собранных пакетов и общая сверка

Срез `collection/import`, 5 ноября 2026. Продолжение [сбора discovery и деталей](S3_01_V1_COLLECTION.md). Используется штатный импортёр из закреплённого runtime; его вход — сохранённые ответы API. Нового HTTP, обучения или активации модели здесь нет. Рабочий план и будущие сроки не меняются.

## Импорт одного пакета

Перед началом должны быть проверены **все** пакеты текущего union. Переменные `$taskCollection`, `$taskCollectionSha`, `$taskUnionSha` берутся из предыдущего шага.

```powershell
node scripts/v1-collection.mjs import-status $taskCollection $taskCollectionSha $taskUnionSha
node --env-file-if-exists=.env scripts/v1-collection.mjs import-batch $taskCollection $taskCollectionSha $taskUnionSha 0 1
```

Последние два числа — индекс пакета (с 0) и номер попытки импорта (с 1, максимум 10 для каждого пакета). Одна команда обрабатывает до 50 карт. Повтор **того же номера** проверяет сохранённый результат, без вызова импортёра и записи карт в БД. Следующий пакет явно запускается с его индексом и попыткой 1.

`accepted`, `partial`, `conflict`, `quarantined`, `not_importable`, `import_failed` показываются раздельно. Завершённый журнал означает, что результат каждой карты учтён; он не означает пригодность всех карт для модели. Непригодные источники и ошибки не исключаются из знаменателя.

До запуска создаётся отдельный intent. Журнал хранится под `details/<union SHA>/imports`: `attempts/NN-MM.json`, `runs/NN-MM/intent.json`, полный результат дочернего импортёра и итоговая запись. Удалённая попытка, изменённый manifest, потерянный результат карты или посторонний файл отклоняют повтор. Все операции используют общую блокировку со сбором источников.

## Прерывание и явный повтор

Импорт отдельных карт может успеть завершиться до сбоя процесса. Отсутствие итогового файла **не доказывает отсутствие записей в БД**. Сначала убедитесь, что дочерний процесс остановлен; зависшая блокировка автоматически не удаляется.

Если `import/manifest.json` полностью сохранён:

```powershell
node scripts/v1-collection.mjs import-recover $taskCollection $taskCollectionSha $taskUnionSha 0 1
```

Восстановление проверяет manifest и результат каждой карты, добавляет отдельный `recovery.json` со ссылкой на первоначальную ошибку. В БД оно не пишет. Проверка журнала и восстановление остаются доступны и после нового discovery; новые импорты, сверка и экспорт требуют актуального union.

Если полного manifest нет, после разбора прерывания можно явно выполнить следующую попытку:

```powershell
node --env-file-if-exists=.env scripts/v1-collection.mjs import-batch $taskCollection $taskCollectionSha $taskUnionSha 0 2
```

Повтор использует те же сохранённые source bytes и идемпотентный импортёр. Предыдущая попытка сохраняется целиком, включая частичные результаты; новая ссылается на SHA списка всех её файлов. Нельзя удалить неудачную попытку или пропустить её номер. Восстановление более ранней попытки после появления следующей запрещено, чтобы не менять закреплённую историю.

Новая попытка также нужна после отдельно подтверждённых numeric identity/series evidence. Совпадение ника не становится подтверждением аккаунта. Неизвестные игроки, команды и серии остаются неизвестными до штатной проверки; никаких персональных фиксов или автоматического объединения историй по имени нет. Исходные `event_at`, `known_at`, `fetched_at` не переписываются задним числом.

## Одна сверка для всех пакетов

Когда учтены последние попытки каждого пакета:

```powershell
node --env-file-if-exists=.env scripts/v1-collection.mjs import-reconcile $taskCollection $taskCollectionSha $taskUnionSha
```

Команда проверяет исходные receipts и читает **один согласованный снимок БД**. Она объединяет оценки всех detail batches для диагностической сверки, включая связанные карты за границами целевого окна. Это отдельное представление `managed-detail-assessment-set-v1`, не поддельный capture увеличенного пакета и не вход модели. Серия между пакетами проверяется целиком; покрытия отдельных пакетов не складываются.

Сохраняются источник, snapshot, причины по каждой карте и исходная версия набора данных. Отчёт различает отсутствие карты, аккаунтов, серии, проверенного исхода и несовпадение canonical receipt с captured source. Нулевая выборка даёт `null` rate. `remoteCompleteness` остаётся `unknown`; `readyForEvaluation:false`. Такой отчёт не считает Brier, точность или вероятность победы.

Каждая сверка получает новый `reviewId`. После новой попытки импорта прежний отчёт остаётся доступным как история, но для нового экспорта нужно повторить сверку. Внешние изменения БД не переписывают снимок: его актуальность видна по `snapshotAt`; после новых проверок аккаунтов или серий выполните импорт и сверку заново.

Синтетический режим определяется только проверенным зарегистрированным планом. Тестовые планы сохраняют `syntheticOnly:true`; рабочий план не принимает синтетические свидетельства. Отдельного переключателя для обхода этого ограничения нет.

## Конфигурация независимой проверки

```powershell
$taskImportReviewId = 'reviewId из результата import-reconcile'
node scripts/v1-collection.mjs import-export $taskCollection $taskCollectionSha $taskUnionSha $taskImportReviewId
```

Новая версия `execution.json` содержит полный список source refs, исходные plan/candidate/freeze SHA и абсолютные пути к закреплённым артефактам. Оригинальный `frozen/config.json` не меняется. Штатная команда закреплённого оценщика `release-execute check` проверяет конфигурацию; она **не** выполняет оценку модели. Все импорты и отчёт сверки остаются привязаны к экспорту.

Ошибки отдельных карт остаются видимыми и не мешают сохранить честный неполный комплект для последующего отказа gate. Успешный экспорт не означает достаточное покрытие, качество или разрешение на прогноз. Реальные источники должны быть получены до зарегистрированного snapshot 2 декабря 03:00 МСК; текущие подтверждения аккаунтов нельзя выдавать за более ранние.
