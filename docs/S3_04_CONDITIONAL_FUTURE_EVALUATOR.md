# S3-04 — численная оценка условного будущего набора

Реализован отдельный evaluator выбранного варианта B: `conditional_future_evaluate.py` и локальный CLI `conditional-evaluator.mjs`. Он потребляет [проверенный evaluation bundle](S3_04_CONDITIONAL_FUTURE_EVALUATION_BUNDLE.md), применяет фиксированные H0/H1/H2 и сохраняет воспроизводимый отчёт. На этом этапе численное выполнение разрешено **только для явно синтетического harness**. Настоящая регистрация будущей проверки ещё не реализована; реальные наборы возвращают `unregistered` без вероятностей и метрик.

## Расчёт

Коэффициенты, порядок признаков и температуры берутся из ранее закреплённого кандидата, без обучения и повторной калибровки. Python inference сверяется с неизменённым TypeScript inference: прежние Python goldens, текущие Python-расчёты на тех же векторах и рассчитанные строки bundle. Для текущей сверки сравниваются logit и вероятность; несовпадение более `1e-12` отклоняет сборку. Старый golden-check сохраняет свой допуск `1e-7`; фактическая максимальная разница обеих сверок — около `1.11e-16`, для двух строк сквозного примера — 0.

Метрики и whole-series bootstrap импортируются из прежних `player_hero_evaluate.py` / `post_draft_evaluate.py`. Сохранены log loss, Brier, accuracy, ECE с 10 корзинами, reliability и 2000 парных bootstrap-повторов PCG64 seed42. Серии — единицы повторной выборки, итог взвешен по картам. H0, H1 raw/cal и H2 raw/cal сравниваются на одном подмножестве.

Критерии не изменены: минимум 50 карт, 25 серий, 10 исходов каждого класса, покрытие не ниже 80%; верхняя граница CI для разницы log loss H2 cal − H1 cal ниже нуля, log loss H2 лучше H0, Brier не хуже обеих базовых моделей, ECE H2 не выше 0.10. Это прежние рабочие критерии исследования, не гарантия точности или достаточной мощности теста.

Отсутствие модели или калибратора не заменяется другим прогнозом. Непригодная карта исключает всю серию из парного сравнения и остаётся в знаменателе. Отдельная H0-диагностика ограничена доступными подготовленными feature-строками bundle; она не заявляется покрытием всех карт с отсутствующими признаками. Provider/patch/month/league и обе группы missingness выводятся отдельно, без выбора модели по подгруппе.

## Сроки и отказ от преждевременной оценки

Для синтетического harness проверяются регистрация раньше начала, окно 28 дней и 7 дней ожидания исходов. `assessedAt` раньше конца ожидания, включая разницу в одну микросекунду, даёт `not_due`; inference/метрики/bootstrap не выполняются. Неполный знаменатель либо превышение 300 возможных целевых карт даёт `insufficient`, покрытие и метрики `null`.

Нулевой образец сохраняет nullable rates. Достаточная синтетика различает `negative` и `positive_synthetic_only`; нехватка выборки — `insufficient`. Все результаты сохраняют `independentTestCompleted:false`, `releaseGatePassed:false`, `activationAllowed:false`, `deployable:false`.

**Реальный набор нельзя разрешить переданным timestamp или boolean:** Python-граница возвращает `DURABLE_CONDITIONAL_REGISTRATION_NOT_IMPLEMENTED`. Времена harness не выдаются за настоящее свидетельство регистрации. Старое prospective ядро и его pre-start требования не менялись; reconstructed B не переименован в прогноз до старта.

## Локальный CLI и воспроизведение

Descriptor содержит `format: conditional-evaluator-files-input-v1`, `bundle: {directory, manifestSha256}` и `schedule`. У синтетики schedule включает `registeredAt/from/until/assessmentAt/assessedAt`; для реальной отрицательной диагностики он `null`.

```text
node tools/research/conditional-evaluator.mjs build SPEC SPEC_SHA OUTPUT_DIRECTORY
node tools/research/conditional-evaluator.mjs verify OUTPUT_DIRECTORY MANIFEST_SHA
```

CLI сначала повторно проверяет всю цепочку source → enrollment → bundle, затем закреплённый SHA кандидата и политики. Записываются `input.json`, `report.json`, `parity.json` и `manifest.json` с версиями Python/пакетов/интерпретатора, threads, Node, кодом и SHA выходов. Каталог должен быть новым, все реальные пути — внутри `.tools`. Входы ограничены по размеру; сообщение об ошибке не печатает содержимое приватных данных.

`verify` требует внешний SHA и заново воспроизводит результат, включая численную совместимость. Изменение исходника, отчёта, среды или манифеста отклоняется. Это локальная неизменяемость файлов; durable first-result journal и регистрация для настоящего окна остаются следующими условиями. Повтор синтетических тестов не считается независимым эмпирическим тестом.

## Проверки и фактический результат

Unit-тесты проверяют положительный/отрицательный/недостаточный результат, сроки, real-refusal, отсутствующий калибратор, общие серии, nullable rates, повреждённые связи и числа. Положительный численный тест использует явно синтетические коэффициенты и данные. Сквозной CLI использует **настоящий закреплённый кандидат на синтетических входах**, не меняя его байты; двух карт недостаточно для положительного gate.

Реальная диагностика переиспользует прежний архив двух уже раскрытых карт. Она должна остаться `unregistered`, `scoringPerformed:false`, без новых вероятностей. Внешние API не вызываются, таблицы приложения не меняются. Результаты, количество тестов и SHA — в [evidence](evidence/s3-04-conditional-future-evaluator.json).
