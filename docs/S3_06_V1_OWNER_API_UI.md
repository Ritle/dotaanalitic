# S3-06 — расчёт одной карты в интерфейсе владельца

Срез `S3-06/V1-owner-API-UI` подключает существующие неизменяемые V1 snapshots к Fastify и Vue. Назначение только `what_if_single_map`: выбранные вручную 5+5, предматчевая оценка одной карты. Это ещё не прогноз, привязанный к реальному матчу, и не журнал его точности.

## Использование

1. Войти владельцем, открыть сценарий и сохранить изменения состава и времени.
2. Нажать «Открыть расчёт одной карты». Указать проверенное событие Tier 1: ID лиги OpenDota, название, период UTC, HTTPS-источник и обоснование. Без проверки попытка сохраняется с причиной недоступности.
3. Нажать «Рассчитать и сохранить попытку». Сервер проверяет редакцию, модель, источники и покрытие; отсутствие активной проверенной модели означает `unavailable` и `null`, а не 50/50.
4. Сохранённая попытка доступна в истории и по URL `/scenarios/:id/prediction?prediction=:requestId`. Старые составы и вероятность не меняются после правки сценария. Для нового расчёта создаётся новый requestId.

После потери ответа страница пытается прочитать сохранённый результат. Кнопка «Повторить тот же запрос» отправляет исходные параметры с прежним requestId; сервер возвращает тот же снимок. При конфликте редакций сначала обновить сценарий. Несохранённые правки нужно сохранить до перехода к расчёту.

## HTTP-контракт

Все пути имеют префикс `/api/v1`, требуют owner session и `Cache-Control: no-store`; POST дополнительно требует разрешённый Origin и CSRF.

| Метод и путь | Запрос и результат |
|---|---|
| `POST /scenarios/:id/predictions` | Strict `{requestId, expectedRevision, purpose:'what_if_single_map', targetScope}`; `200 V1PredictionView` для новой попытки и exact retry |
| `GET /scenarios/:id/predictions?offset=0` | До 20 кратких записей, `hasMore`; offset 0..10000; порядок createdAt DESC, id DESC |
| `GET /scenarios/:id/predictions/:requestId` | Сохранённая проекция; без пересчёта, с проверкой owner и scenario |

`400` — неверный ввод, `401` — нет сессии, `403` — CSRF/Origin, `404` — отсутствующий/чужой сценарий или снимок, `409` — устаревшая редакция либо requestId с другим содержимым. POST ограничен шестью запросами в минуту. Пока другой расчёт выполняется, admission guard отвечает `429` с `Retry-After: 1` до открытия транзакции: ожидающие registry lock запросы не занимают весь пул, необходимый отдельному history reader.

Ответ содержит сохранённый scenario/revision, UTC clocks с точностью исходных полей, статус/nullable probability, причины/ограничения, model/version и SHA, Tier1 review, source fingerprint/период/identity revision, N/n_eff и количество карт каждого игрока. Raw receipts, полный source inventory, исполняемый manifest и байты model artifact в HTTP не выдаются; точный snapshot остаётся в БД и доступен через существующий CLI export. Неизвестное покрытие остаётся null. Фаворит определяется до округления процента.

API фиксирует fingerprint расчётного кода при старте. Если файлы пересобраны при работающем API, новая попытка получает `SERVER_CODE_CHANGED_RESTART_REQUIRED`; требуется перезапуск процесса. Это дополняет совместимость с замороженным evaluator и не меняет его ядро. Новых миграций нет; SQL001–026 сохранены.

## Проверка и границы

Проверяются owner/CSRF/Origin, запрещённые дополнительные поля, rate limit, история/пагинация, strict projection, неизменность редакции, exact retry, admission guard, смена startup fingerprint, завершение сессии и потеря HTTP-ответа после commit. Browser tests используют изолированную БД; числовой результат показан только явной синтетической presentation fixture и не записывается как реальный прогноз. Проверены desktop и ширина 360px.
