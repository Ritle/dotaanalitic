# S3-01/V1-historical/collection — возобновляемый сбор источников

Продолжение [исторического протокола TI 2026 + PGL Wallachia 9](S3_01_V1_HISTORICAL_PROTOCOL.md). Этот срез собирает источники и проверяет готовность данных. Он не рассчитывает Elo, метрики качества или вероятность и не активирует модель.

## Правило сбора

Сначала запрашиваются детали всех 261 наблюдаемой карты, включая ранее просмотренные исключения. Это нужно для проверки связи карт с сериями: отсутствовавший в discovery series ID может появиться в деталях. Если серия связана с ранее просмотренной картой, исключение распространяется на всех её известных участников. Конфликты metadata сохраняются после проверки деталей; неготовая карта не исчезает из знаменателя.

После обработки всего target inventory, включая явно зарегистрированные отказы, определяются уникальные аккаунты пригодных по источнику карт, не исключённых исходным exposure manifest. Для них действует заранее выбранное правило первого набора истории: **до 10 последних завершённых pro-карт на аккаунт за 730 дней перед 1 августа 2026, 00:00 UTC**. Группы по пять аккаунтов упорядочены по числовому ID. SQL формирует существующий ограниченный OpenDota history adapter. Одна карта, найденная у нескольких игроков, требует одного запроса деталей и учитывается один раз.

Это ограниченная выборка, не полная история с 2024 года. Ровно 10 строк на аккаунт отмечаются как возможное усечение; пустой ответ не доказывает отсутствие профессионального опыта. Дополнительно используется новый проверенный экспорт существующей локальной pro-истории; старый development export не изменяется. Итоговая нижняя граница — 1 января 2024 из протокола. Для каждого target учитываются только карты с **`completed_at < target.started_at`**; завершение ровно в момент начала не подходит. Исключение серии из теста не удаляет её пригодные ранние карты из истории.

Правило сбора закрепляется до расчёта качества. Изменение истории после просмотра model errors потребует нового независимого теста; нельзя подбирать количество карт под понравившийся результат. Исходные числовые quality gates и параметры Elo сохранены.

## Надёжность и обращения к API

- `init` привязывает protocol inputs, discovery captures/review, cache manifest и canonical history по SHA; исходный ledger полностью воспроизводится.
- Каждый ответ сохраняется отдельно с исходным `fetchedAt`, `knownAt: null`, payload SHA, происхождением live/cache и fingerprint. Завершённый временный файл публикуется атомарно. Он восстанавливается после прерывания без повторного HTTP; незавершённый JSON остаётся как след попытки.
- Повторный пакет читает успешные ответы с диска. Провайдер создаётся только перед реальным запросом. Файлы сохраняются внутри отдельного каталога; старые наборы и прогнозы не перезаписываются.
- Общий лимит — 50 HTTP-попыток на запуск, включая retries и запросы history adapter. Используется тот же PostgreSQL quota budget, таймауты и Retry-After. Ошибки, их HTTP-статус и возможное время ожидания записываются в `attempts`; успешные ответы сохраняются. При transport/quota/авторизации/HTTP429 или отказе запроса истории пакет останавливается.
- Единичный HTTP404/5xx карты позволяет обработать следующие карты; три последовательных серверных отказа останавливают пакет. HTTP404 или повторный HTTP5xx в двух запусках переводит отдельную карту в явно недоступные источники, без дальнейшего повторного опроса в текущем наборе. Она и её серия остаются неготовыми в знаменателе. Для последующего восстановления недоступной карты нужен новый проверяемый snapshot/каталог с переиспользованием успешных captures; текущие файлы отказов не удалять.
- `lock` исключает параллельный сбор в один каталог. `recover` снимает только блокировку завершившегося процесса, проверив его PID; живой или недоступный для проверки процесс не обходится.
- `status` не создаёт API-клиент и не пишет в рабочую БД. Он проверяет файлы и может завершить атомарную публикацию полностью записанного ответа после прерывания.

Проверки читают только используемые V1 поля: IDs, времена, длительность/завершённый исход, league pro status, турнирное лобби, стороны, series ID, десять различных аккаунтов и native player slots. Герои, роли, patch и telemetry не входят в этот допуск. Длительность/исход используются для проверки завершения и согласованности метки, не как признаки прогнозируемой карты. Публичный отчёт не содержит победителей или счёта.

## Запуск существующего локального набора

После `pnpm build`:

```powershell
$store = '.tools/v1-historical-collection-20261106/store'
$storeSha = '1ee31e309b396ee1d837bf569633a422333513bae6211e0f33f4f2073d28a5b7'

# Сохранённые ответы переиспользуются; максимум 50 попыток за вызов.
node --env-file-if-exists=.env scripts/collect-v1-historical.mjs targets $store $storeSha
node --env-file-if-exists=.env scripts/collect-v1-historical.mjs history $store $storeSha

# Выходной файл должен быть новым. Этот режим работает без API и подключения к БД.
node scripts/collect-v1-historical.mjs status $store $storeSha .tools/historical-status-new.json

# Только если предыдущий процесс завершился, оставив lock.
node scripts/collect-v1-historical.mjs recover $store $storeSha
```

Начальная конфигурация: `.tools/v1-historical-collection-20261106/config.json`, SHA `6a2615703743cc065abdbdd5e2db95a2df2a88bb03b8aafd5aeec29c290a1b70`. Для другого набора `init CONFIG SHA NEW_DIRECTORY` требует новый каталог. Сырые captures и источники остаются локальными; чистого git checkout без файлов с соответствующими SHA недостаточно для их воспроизведения.

## Что означает отчёт

`sourceEligible` подтверждает структуру источника и pro-классификацию, но не запись в canonical `matches.is_pro`. `priorSourceMapsPerPlayer` включает пригодные исходные ответы и локальные проверенные карты; у новых ответов ещё нет canonical OutcomeVerifier/identity resolution для всех участников. Поэтому это предварительное покрытие, не итоговый quality gate.

Текущие canonical identity bindings проверяются существующим `IdentityResolver` по сохранённому экспорту. Ники не участвуют в связывании. Неизвестные аккаунты не становятся новыми игроками автоматически в этом срезе. `provisionalReadyMaps` требует текущих связей target-игроков, минимальной source-истории и целой пригодной серии, но **не разрешает прогноз**. В отчёте всегда `canonicalOutcomeEligibilityVerified: false`, `qualityGateCalculated: false`, `metrics: null`, `deployable: false`.

Следующая необходимая граница — **S3-01/V1-historical/canonical-import**: переиспользовать сохранённые источники через стандартный importer, подготовить проверенные числовые account links и series bindings, выполнить OutcomeVerifier и экспорт точной пригодности всего test inventory и истории. Точечные исправления по нику не нужны. Затем — historical frozen executor/evaluator/registry, независимый quality gate и явная активация при PASS.

## Фактический результат 6 ноября 2026

[Checkpoint с SHA и ограничениями](evidence/s3-01-v1-historical-collection.json). Обработаны все 261 target IDs: 259 ответов сохранены, два источника явно недоступны. Карты `9010993339` / серия `1145377` и `9011023151` / серия `1145411` повторно вернули HTTP 500; каждая прошла два ограниченных запуска с тремя попытками клиента. У первой неудачной попытки счётчик конкретных HTTP-статусов ещё не сохранялся; последующие отказы подтверждены как 500. Эти карты и их серии не удалены из знаменателя 145 кандидатов / 60 серий.

24 запроса ранней истории для 116 аккаунтов вернули 1160 строк; после объединения по map ID получены все 340 уникальных ответов деталей. Два ответа истории не проходят проверку источника и не учитываются как пригодные карты. Все 116 аккаунтов достигли лимита 10 строк: полнота истории не доказана. Неначатых запросов истории и ожидающих деталей нет.

По предварительным источникам минимум пять более ранних завершённых карт на каждого игрока есть у **143 из 145** test maps. Текущие canonical identity links покрывают всех десятерых игроков у **22** карт; после ограничений целых серий предварительно готовы **20**. Это разные проверки, их нельзя выдавать за пройденный quality gate. Требование итогового покрытия 80% означает минимум 116 из 145 карт; отдельные минимумы 100 карт / 40 серий также сохраняются.

В исходном cache manifest найдены 237 прежних карт, но ни одна не совпала с новыми запросами: фактических cache-origin captures здесь нет. Повторные запуски `targets` и `history` после завершения сделали **0 HTTP** каждый, используя собственные сохранённые records. Два независимых `status` отчёта совпали, кроме времени проверки. Параметры Elo, протокол, старые development exports и frozen artifacts не менялись; модель не оценивалась.

QA: offline frozen install, root typecheck/build, 889 unit/CLI + 152 Node tests, включая 16 новых collection cases — PASS. Проверены 49 миграций, 245 protected files, 150 original compiled modules, старые frozen bundle/runtime. Первоначальный sandbox EPERM при rename временного тестового файла не повторился в обычном Windows-запуске; права каталогов не менялись. API/PG/browser/Python/Docker/Linux suites для файлового collector не запускались; сравнение снимков рабочей БД выполнено отдельно и отражено в checkpoint.

Всего этот сбор сделал 635 HTTP-попыток и сохранил 623 ответа (599 map details + 24 history pages); в ранних receipts ещё не было разбивки всех статусов. Объединённый пул предварительной истории — 899 уникальных карт, включая 304 ранее canonical-verified. Две отвергнутые карты истории: `8655406512` без series ID и `8763645947` без team context/series ID. Рабочая БД: **82 из 83 public-таблиц неизменны**, менялась только `provider_quotas`; 340 canonical maps, identities, models и очередь сохранены. Pending team-history job не запускался.
