# S1-16 / BUG_REPORT №7 — герои в истории сценариев

11 ноября 2026. Срез `readable-labels/scenario-history-heroes`.

Откройте сохранённый сценарий и раскройте нужную редакцию в истории.
У назначенных героев и банов показаны названия из текущего локального
каталога. Стороны A/B, выбранные роли, действия pick/ban и их порядок
берутся из сохранённого снимка. ID доступен в «Данные записи».
Фиктивная ссылка на отдельную страницу героя не создаётся: такой страницы
в приложении пока нет. Пустое имя показано как «Герой без названия»;
отсутствующее — «Название героя недоступно» с сохранённым ID.

Эти названия — дополнительные подписи, не историческое доказательство.
Переименование в каталоге не переписывает старый input, inputHash,
подтверждения доступности, дату, роли или результаты модели. Сохранённая
проверка драфта отображается отдельно в первоначальном виде; новое имя
не подтверждает доступность героя в патче или участие игрока.

## Загрузка и совместимость

Используется прежний private read-only `GET /api/v1/catalog-labels`.
Новый необязательный параметр `heroes` принимает до50 локальных ID:
максимум10 назначений и40 банов существующего DraftInput. Дубли удаляются
после проверки границ; неизвестные ID не возвращаются, пустые имена
не заполняются. Источник/UTC-время чтения показаны рядом с подписями.

Один раскрытый снимок читает команды/игроков/героев одним HTTP-запросом.
Закрытая история ничего не подгружает; одинаковые наборы ID используют
общий кэш5min, в том числе между редакциями. По одному запросу на героя
нет. «Обновить подписи каталога» явно перечитывает metadata. При ошибке
прежние доступные подписи сохраняются, исходный снимок не меняется.

Параметр `heroes` и поле ответа появляются только при явном запросе героев.
Прежние вызовы без него сохраняют прежний JSON shape, cache key и пределы
2 команд/20 игроков; без драфта дополнительного hero lookup нет.
Другие потребители ScenarioDisplayLabels по умолчанию героев не запрашивают.
Endpoint выполняет только SELECT: providers, синхронизация, identities,
миграции, protected packages и prediction pipeline не затронуты.

## Проверки

Тест с50 героями проверяет10 пиков/40 банов, одинаковые/пустые названия,
отсутствующую запись, A/B и роль, отсутствие ложных ссылок, скрытые ID,
один lazy batch, повторное раскрытие и общий кэш двух редакций.
Переименование, ошибка обновления и повтор проверены с полным сравнением
трёх исходных ScenarioSnapshot, включая inputHash и draftAssessment.
В фикстуре удаление записи героя допускается только после новой редакции,
снявшей текущий FK; ограничения БД не отключаются.

Дополнительно проверяются401/400, oversized51, повторы/unknown bigint,
прежний ответ без heroes, совместимость истории/отчётов/H2H/Draft Lab и360px.
