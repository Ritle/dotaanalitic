# S3-01/V1-historical/protocol — историческая проверка Tier 1

У двух из 116 ранее доступных карт нет series ID. Они остаются явно учтёнными исключениями; 106 — число известных серий, не оценка полного числа всех сыгранных встреч. В оставшихся 145 картах метаданные серии, времени и двух команд заполнены. **145/60 — кандидаты, а не подтверждённые пригодные примеры.** Полнота API неизвестна, сведения о составах и история ещё не проверены для всего набора.

## Предыдущий доступ к данным

До нового discovery сохранены снимок БД и manifest 1511 локальных JSON/body/JSONL-файлов (371615009 байт). В БД не было карт выбранных событий, но в прежних team-history captures уже присутствовали их карты. Поэтому одной проверки таблицы `matches` недостаточно.

Нормализованный exposure содержит 40625 положительных числовых токенов и 174 явно OpenDota series ID. Токены — консервативный запрет на повторное использование, не утверждение, что каждый токен является картой. Если найден ранее доступный map ID или provider series ID, исключается вся известная серия. Другие пространства ID провайдеров не объединяются. UTF-16 JSON прочитаны повторно; четыре HTML/не-JSON тела учтены числовым сканированием, но не структурным разбором.

Ограничения обязательны в последующем отчёте: это ограниченный локальный аудит, а не доказательство отсутствия любого прежнего человеческого доступа. Публичные результаты прошлых турниров могут быть известны. Исключённые серии связаны с ранее исследованными командами; оставшаяся выборка может хуже представлять некоторых участников Tier 1. Показать состав событий, команд, исключения и покрытие; не обобщать автоматически на весь Tier 1. Не пересканировать уже полученные target captures как «прежний доступ» и не менять исключения после просмотра качества модели.

## Модель и проверка

Первый проход сохраняет фиксированный player-mean Elo: 1500 / K=32 / scale=400, минимум пять ранее завершённых pro-карт на каждого игрока. История разных уровней допустима. Начало исторического окна — 1 января 2024; строгий `completed_at < target.started_at` действует для каждой карты. Предполагаемая доступность исторических исходов должна быть явно записана; современные fetch timestamps не становятся историческим `known_at`. Восстановленные составы дают условную оценку при заданных пятёрках, не проверку точности предматчевых заявок.

Числовые пороги прежней policy сохранены: не менее 100 пригодных карт / 40 целых серий, покрытие карт и известных серий ≥80%, Brier ≤0.245, log loss ≤0.685, верхняя граница paired whole-series bootstrap разницы с baseline ниже нуля, прежние требования calibration/stability. При текущих 145 кандидатах требование 80% означает **не менее 116 пригодных карт**, если знаменатель после проверки источников не изменится. Наличие 100 карт само по себе недостаточно.

Новая версия `conditional-elo-tier1-historical-v1` явно меняет операционную семантику: target pool после заранее зафиксированных exposure-исключений; остальные причины непригодности остаются в знаменателях; freeze кода — до первого расчёта качества, а не задним числом до исторического турнира. Старый prospective-протокол не изменён и не переименован. Ни гиперпараметры, ни fitted calibration не подбираются на этом тесте. Если понадобится подбор, потребуется отдельное более раннее train/validation окно и независимый test.

## Исполняемый срез и воспроизведение

Добавлены отдельный Zod-контракт, файловый CLI и metadata-only классификатор. Проверяются SHA каждого входа, неизменность policy, ID/названия/календарь, возраст каталога, clocks, совпадение request, целые серии, конфликты и лимит 5000 карт без усечения. Победитель, счёт и длительность не входят в ledger. Существующий файл результата не перезаписывается.

```powershell
# После pnpm build; локальные source captures намеренно не коммитятся.
$config = '.tools/v1-historical-20261106/inputs.json'
$configSha = (Get-FileHash -LiteralPath $config -Algorithm SHA256).Hash.ToLowerInvariant()
node scripts/plan-v1-historical.mjs verify $config $configSha docs/evidence/s3-01-v1-historical-protocol.json 80e27f796ff1f97d47422d7120d090dec7dddf7b3df4e88855230e7b62a75739

# Replay в НОВЫЙ файл; без сети и БД, текущий evidence сохраняется.
node scripts/plan-v1-historical.mjs inspect $config $configSha docs/evidence/s3-01-v1-historical-protocol.json 80e27f796ff1f97d47422d7120d090dec7dddf7b3df4e88855230e7b62a75739 .tools/v1-historical-20261106/captures.json 3d790e258d06ffcbb045481c49886b4d46b8a6154643b5e004518baad3953455 .tools/v1-historical-replay-new.json
```

Публичные артефакты: [request](evidence/s3-01-v1-historical-request.json), [protocol](evidence/s3-01-v1-historical-protocol.json), [ledger](evidence/s3-01-v1-historical-discovery.json), [живой аудит](evidence/s3-01-v1-historical-live-audit.json), [итоговая проверка](evidence/s3-01-v1-historical-checkpoint.json). Перенос на другой компьютер требует соответствующих сохранённых source captures и exposure manifest с совпадающими SHA; одних публичных summary недостаточно.

Штатный `audit-prediction-sources.mjs --league 20279 --sample 3` проверил три равномерно выбранные реальные карты PGL: 3/3 имеют pro-классификацию, завершённый исход, стороны, series ID и десять различных source account IDs. Это не проверка всех 145 карт, не подтверждение canonical identity и не проверка покрытия ранней истории. Всего выполнено семь provider HTTP200: два discovery и пять запросов штатного аудита, без retry. Аудит повторно читает catalogue/discovery своим существующим способом; циклического опроса нет.

## Что остаётся

Следующий точный срез — **S3-01/V1-historical/collection**: отдельный возобновляемый collector под этот протокол, детали 261 наблюдаемой карты для проверки полноты серий и происхождения исключений, более ранняя pro-история участников, числовые identity bindings и отчёт eligibility/coverage без расчёта метрик. Переиспользовать подходящие сохранённые источники по SHA, соблюдать бюджет/Retry-After; не запускать общую очередь.

Далее нужны historical-compatible frozen executor/evaluator и registry binding, независимый тест, неактивный артефакт и явная активация только после PASS. Текущий новый формат намеренно **не принимается старым registry**; модель, freeze исполняемого кода, импорт canonical matches и прогнозы здесь не создавались. Старые E0/E1/V1 artifacts, future intent и SQL сохранены; будущие турниры могут использоваться для отдельного мониторинга, но нельзя выбрать лучший результат из нескольких тестов задним числом.
