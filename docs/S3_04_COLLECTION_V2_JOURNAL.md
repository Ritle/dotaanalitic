# S3-04 — журнал запросов v2 с архивом ответов

Внутренний `ConditionalCollectionV2Journal` связывает регистрацию v2 и [архив исходных ответов](S3_04_COLLECTION_BLOB_ARCHIVE.md). Он учитывает попытки до HTTP, фиксирует их исходы и позволяет завершить сохранённый ответ после прерывания. Сам журнал HTTP не выполняет и модель не активирует.

## Правила работы

1. `initialize` проверяет активного владельца, подтверждённую регистрацию, ожидаемый SHA и закреплённые файлы. Архив должен быть пустым при первом подключении к журналу. Инициализация до окна разрешена, начало запроса — нет. Повтор сохраняет прежний заголовок и настройки.
2. `append(..., {kind:'reserve', requestId, endpoint})` проверяет предыдущий SHA, окно, квоты, остановку после 401/403, Retry-After и доступное место под максимальное тело. Попытка сразу расходуется. Одновременно может ожидаться один ответ.
3. Транспорт сохраняет полный ответ через `ConditionalBlobArchive.saveResponse`. Дополнительный SQL-триггер v2 требует ожидающий request ID, тот же endpoint и время получения не раньше начала попытки. Самостоятельные архивы без журнала v2 сохраняют прежний контракт.
4. `complete` проверяет квитанцию и байты, добавляет компактную запись архива и событие завершения **одной транзакцией**. Если запись в журнал не удалась, тело с квитанцией остаются, а новая запись архива откатывается. Повтор завершает попытку без HTTP. Ранее отдельно добавленная запись архива также используется без дублирования.
5. `fail` хранит ограниченный код ошибки, HTTP-статус либо `null` и Retry-After. `recover` явно фиксирует неизвестный исход после двух минут с обязательным пояснением. Ни ошибка, ни неизвестный исход не возвращают потраченную попытку. При наличии квитанции оба действия запрещены: нужно завершить сохранённый ответ. Поздний ответ после закрытия неизвестного исхода отклоняется.
6. `read` проверяет цепочку, квитанции, исходные байты и их связь с попытками. Незавершённая попытка с квитанцией показывается отдельно. Операции записи проверяют текущую цепочку и относящиеся к завершению байты; они не объявляют весь архив повторно проверенным (`archiveVerified:false`). Полная проверка выполняется при чтении.

## Квоты и время

- Закреплённые ограничения:1000 попыток всего,100 в сутки UTC, включая ошибки и неизвестные исходы. Владелец не передаёт часы или увеличенные бюджеты в командах.
- Новые попытки допустимы с20 ноября2026,00:00 UTC до25 декабря2026,00:00 UTC, правая граница исключена. Это существующий срок сбора до оценки. **Окно отбора целевых карт заканчивается раньше —18 декабря,00:00 UTC.** Получение старых результатов после18 декабря не разрешает добавлять карты, начавшиеся вне окна.
- Уже начатую попытку можно завершить после закрытия окна запросов для аудита и восстановления. Это не продлевает отбор карт или срок оценки модели.
- После ошибки действует минимум5 секунд задержки и более поздний Retry-After, если он указан. Ошибки401/403 блокируют новые попытки этой регистрации. Автоматического сброса блокировки нет.
- Перед новой попыткой нужен запас8 МиБ в пределах архива и общего лимита512 МиБ, а также место для квитанции. Это консервативная проверка, не резервирование физического диска. Архив повторно проверяет фактическую ёмкость при записи.
- Все изменения сериализуются общей блокировкой архива при READ COMMITTED. Чтение с полной проверкой также удерживает эту блокировку, чтобы согласовать журнал с архивом. До2000 событий и1000 квитанций; большие тела читаются по одному уникальному SHA.

## Совместимость и границы

SQL068 добавляет две неизменяемые таблицы и дополнительную проверку INSERT квитанции. SQL001–067, прежние модули журнала/архива/регистрации сохранены. Обновлена только очистка зависимых таблиц в трёх старых PostgreSQL-тестах. Рабочая БД остаётся на061; миграция проверяется в отдельных временных базах.

Журнал ограничивает league endpoint зарегистрированными native ID. Положительные map ID и cursor проверяются по формату/BIGINT, но происхождение ID из обхода, порядок страниц, предел300 целевых карт и полнота турниров ещё принадлежат слою сборщика. Резерв записи не является разрешением на удалённый запрос. Общая квота OpenDota для всех функций приложения должна быть подключена транспортом; здесь проверяются бюджеты конкретного зарегистрированного сбора.

`archived` означает сохранённый HTTP-ответ, включая невалидный JSON/UTF-8, а не проверенную pro-карту. `verifiedProMaps:null`, `denominatorComplete:false`; разрешения HTTP/оценки/активации остаются `false`. Исходные признаки и метки модель не получает из этого журнала автоматически.

Перед реальной регистрацией по-прежнему нужны проверенные main-event привязки и актуальный дополнительный список уже изученных карт/серий. Базовый exposure и модель не изменяются.
