# S2-07/hero-summary — практика по героям

Дополнительно реализован [контекст STRATZ по известным картам](S2_07_STRATZ_ENRICHMENT.md): отдельный свёрнутый блок под этой таблицей, ручная загрузка/кэш, estimated position и provider version. Он не меняет N/WR описанного ниже OpenDota summary.

В карточке игрока доступен отдельный описательный блок рейтинговой практики: игры, победы, наблюдаемый WR и последняя игра по каждому герою. Основание — [требования §0.8](../TECHNICAL_SPEC.md), [reader/cache](S2_07_RANKED_PRACTICE_READER.md) и [проверка непустой выборки OpenDota v2](S2_07_RANKED_COVERAGE_CONTROL.md). [Результаты проверки](evidence/s2-07-ranked-hero-summary.json).

## Как открыть

1. Откройте игрока. Проверенный локальный пример: [Dendi](http://localhost:5173/players/61).
2. Под профессиональной статистикой раскройте **«Рейтинговая практика»**, источник **OpenDota**.
3. Сохранённые данные и таблица читаются без внешнего запроса. Если данных нет или нужно обновить период, нажмите кнопку загрузки/обновления. Обновление ограничено прежним бюджетом, двумя страницами по100 строк и cooldown.
4. В **«Практика по героям»** показаны игры (N), победы, сырой WR и последняя игра в UTC. На узком экране таблица прокручивается горизонтально; область доступна с клавиатуры.
5. В **«Покрытие рейтинговой истории»** указаны ограничения выдачи, исключения и число карт с известными патчем, ролью, средним рангом лобби и размером группы. Остальные значения неизвестны; ранг лобби не является личным MMR.

Не требуется заново сопоставлять уже подтверждённый числовой аккаунт. Настройка backend `RANKED_PRACTICE_ENABLED` по умолчанию выключена; в рабочем localhost включена. STRATZ доступен как отдельный reader, но его независимые геройские показатели пока не включены: непустой список player ranked history ещё не подтверждён. [Проверка6 ноября](S2_07_STRATZ_VALIDATION.md) нашла данные4 известных рейтинговых карт через match(id), включая estimated position и provider version, при пустой истории игрока. По этому основанию уже подключено [отдельное дополнение контекста известных карт](S2_07_STRATZ_ENRICHMENT.md); оно не создаёт независимый STRATZ denominator. Одинаковые карты разных источников не складываются.

## Семантика

Политика `ranked-hero-raw-v1`: одна карта учитывается один раз, один verified аккаунт, один источник и одно сохранённое observation. Выборка — ranked lobby7 / All Pick22, начало в `[fromAt, cutoffAt)`, завершение строго раньше cutoff, окно30 суток. Никакого lifetime aggregate, добавления Practice/турнирных карт или объединения с pro-историей.

- `games` — число пригодных карт; `wins` — число наблюдаемых побед; `winRate = wins/games` только при N>0.
- При N=0 `winRate` и `lastPlayedAt` равны null, строки героев отсутствуют. В интерфейсе объясняется отсутствие доступных данных; оно не означает нулевой опыт.
- `lastPlayedAt` — максимальное время начала карты соответствующего героя, а не время загрузки. `fetchedAt`, неизвестный `knownAt` и исходные SHA сохраняются отдельно в observation.
- Строки сортируются по числу игр, затем числовому hero ID без потери bigint-точности. Название берётся из локального каталога; при отсутствии имени остаётся ID и сохраняются счётчики.
- Все роли и доступные патчи за период вместе, без весов, скрытых prior/сглаживания и отсечения по lobby rank. Контекст неполон, полная история неизвестна даже при исчерпанной выдаче.
- 0% при N>0 означает наблюдаемые поражения; 100% — победы в этой выборке. Малое N не доказывает силу/слабость. Паблики не изменяют V1 Elo или вероятность профессиональной победы.

Устаревшее observation остаётся видимым с предупреждением и исходным периодом. Capped/partial выдача даёт частичный описательный отчёт, без заявления о полноте. Source conflicts, неизвестная/конфликтующая identity, legacy v1 и неподдержанный источник не разрешают summary.

## Реализация и совместимость

Чистый `packages/analytics/src/ranked-practice.ts` не зависит от сети/БД и не использует pro-агрегаторы. Отвергает дубли, другую identity и выход за временные границы. DB helper добавляет локальные имена героев. API рассчитывает summary на чтении, без сохранения производного кэша и без новых provider calls.

Прежний owner/CSRF `POST /api/v1/ranked-practice` получает additive `heroSummary` и boolean `statisticsEnabled`. Summary ссылается на неизменяемый `observationId`, содержит policyVersion, totals и hero rows. Контракт проверяет суммы, nullable N=0, уникальность групп, per-hero соответствие исходным картам и source/version/identity gate. Старые отчёты с `statisticsEnabled:false` читаются с `heroSummary:null`. Формат immutable observations не изменён; SQL001–045, lockfile и зависимости прежние.

## Проверка

Фактически выполнены: frozen offline install, root typecheck/build, **867 unit/CLI (11 новых),12 API/PG и8 Chromium — PASS**. Последний browser повтор добавляет проверку реального ArrowRight-scroll; повторные запуски не увеличивают число уникальных тестов. Сохранность45 SQL checksum,245 protected artifacts/150 original modules/frozen bundle/runtime подтверждена. Full Node/browser/Python/Docker/Linux suites не перезапускались. Рабочий API перезапущен, Web/worker сохранены. При первой быстрой health-проверке API ещё запускался; затем тот же процесс прошёл health. В live helper исправлен путь к уже установленному браузеру, без скачиваний. Предупреждения Node о цветах, Rollup annotations и размере bundle не блокировали сборку.

Unit tests покрывают пустую историю, 0/100%, группировку/суммы/recency, порядок входа, дубли, неверный аккаунт, строгий cutoff, bigint-sort и неизменность входа. Contract tests проверяют ratios/counts/source/version/identity/observation binding. Изолированная API/PG проверка включает пустую и непустую v2 выборку, stale/failure/cooldown, legacy v1, STRATZ availability-only и отсутствие pub-карт в pro matches. Chromium проверяет таблицу, источник, cache-only режим, ошибки, cooldown и360px.

Рабочая карточка Dendi проверена через существующую owner session без нового логина/обновления:197 карт,106 побед,25 героев. Все строки сверены с ранее сохранённым настоящим observation; период и source fetchedAt не менялись. Один cache-only запрос блока,0 provider HTTP,0 page errors/overflow; desktop/mobile просмотрены. Все77 public tables и очередь неизменны. Это проверка одной bounded выборки, а не универсальное покрытие игроков. Детальные результаты и хеши проверок находятся в evidence.
