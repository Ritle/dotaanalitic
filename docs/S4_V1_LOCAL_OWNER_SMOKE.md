## Найденное расхождение

В предыдущей редакции `ACCEPTANCE_CRITERIA` фильтр расписания по provider tournament ID ошибочно был описан как существующий. На рабочем экране селектора нет; `GET /api/v1/upcoming` сейчас принимает только пустой query. Это исправлено в статусе документации.

Runtime Tier1 scope gate реализован отдельно и этим наблюдением не отменяется. Общий календарь показывает турниры разных уровней; наличие строки в нём не означает Tier1 membership или разрешение прогнозной модели.

**Следующий точный срез — S4/V1-schedule-event-filter:** явный выбор provider tournament ID среди текущих сохранённых данных, корректные счётчики/пустое состояние и сброс выбранной встречи при смене фильтра. Сохранять исходный snapshot/source timestamps, явно показывать ограничение первой страницы; не присваивать Tier1 автоматически, не смешивать provider/local IDs и не добавлять сетевые запросы ради UI-фильтра. Рекомендуемая модель: **GPT-6.1 Sol · High**.

## Проверки и границы

Frozen offline install, typecheck/build,721 unit/CLI,64 Node fixtures и реальный owner browser flow11 checks — PASS. Новые PostgreSQL/полный synthetic Playwright suites в этом срезе не перезапускались: production code не менялся, его SHA проверен. Preflight подтвердил native PostgreSQL; Docker отсутствует.

Новый cluster/database bootstrap не выполнялся. API/Web запущены для локального использования; автоматическая browser-сессия завершена выходом.

Синтетические записи в рабочую БД не добавлялись. Сохранённые прогнозы/сценарии не создавались ради проверки. Полученные20 встреч не превращались в training targets. Независимый release test, реальная active-model restore и общий V1 release gate остаются открытыми. Home пока проверен в фактическом состоянии `NO_ACTIVE_MODEL`; положительная выдача не заявляется.
