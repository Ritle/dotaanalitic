# Рекомендации по переключению моделей Codex — Model Routing Guide (v6)

**Цель:** Codex должен **вовремя предлагать владельцу сменить модель или reasoning effort**, если сложность этапа выросла, и советовать вернуться к более экономичной модели после завершения критической части. Это **совет в тексте**, а не автоматическое переключение модели, не механизм контроля качества и не изменение P0/P1/P2.

## 1. Короткое правило для каждого задания

До начала реализации выбранной задачи `Sx-yy` оцени риск и выведи **ровно одну короткую строку**, если смена модели может быть полезна:

> 🧠 Рекомендуемая модель: GPT-6 Astra · High — задача S0-05 затрагивает идентичность игроков и историческую корректность; переключите модель в Codex перед сложными изменениями.

Если текущая выбранная модель не известна, **не утверждай, что пользователь работает на определённой модели**. Можно написать «для этой задачи рекомендуется». Если текущая настройка подходит, допускается краткое «выбранная настройка подходит» либо молчание. Не повторять подсказку перед каждым файловым изменением или тестом.

Подсказка не является блокером: если пользователь не меняет модель, продолжай работу в рамках реальных возможностей. Не имитируй автоматическую смену и не утверждай, что она состоялась.

## 2. Матрица решений по задачам

| Ситуация / задача | Рекомендуемая модель и effort | Почему |
|---|---|---|
| Точечный UI, copy, простые тесты, документация | GPT-6.1 Sol · Medium (опционально Luna · Medium) | Ограниченный контекст и проверяемый результат |
| Обычный Vue 3/TS, Fastify, REST API, UX драфта, S0-00, S1-01, S2-01/02, обычный S4 | GPT-6.1 Sol · Medium/High | Хорошее соотношение качества и скорости |
| Интеграция API, DB и фоновых задач, S0-01/02/03, аналитика S1/S2 с нетривиальной выборкой | GPT-6.1 Sol · High; при системном риске Astra · High | Неизвестные данные, идемпотентность, корректность SQL |
| Трёхвременная семантика, identity/roster, патчи, составы: S0-04/05/06/07, S1-03/05/07 | GPT-6 Astra · High | Высокая стоимость ошибки, сложные инварианты |
| Датасеты, as-of feature builder, temporal split, ML pipeline, калибровка, model registry: S3-00..06 | GPT-6 Astra · Extra High (если доступно) | Протечки будущих данных, некорректная валидация, неверные проценты побед |
| Архитектурная переделка >3 модулей, необратимые миграции, безопасность, противоречия требований | GPT-6 Astra · High/Extra High | Требуется системный аудит допущений |
| После утверждения архитектуры — реализация узких подзадач, исправления и тесты | GPT-6.1 Sol · Medium/High | Можно вернуться на более экономичный режим |

Это **эвристика**, а не измеренная гарантия лучшего результата. Если в аккаунте нет указанной модели/уровня, выбрать наиболее сильную доступную и явно это указать. Никогда не пытаться сменить модель через правку репозитория или использовать несуществующий API агента.

## 3. Триггеры для повторной рекомендации в середине задачи

Выдать дополнительное **однократное** предупреждение, если после начала работы возникло хотя бы одно:

- Выявлена вероятная **утечка будущих признаков**: `known_at`, lineup hindsight, серия в разных folds, неверное использование патча.
- Изменение SQL потребовало удаления или переписывания существующей migration, отката несовместимой схемы, риска потери данных.
- Несколько провайдеров противоречат друг другу по `team_id`, `steam_id`, `winner`, `is_pro` или `draft`.
- Проектирование модели или статистического метода оказалось неоднозначным; перестали выполняться исторические инварианты.
- После **двух разных осмысленных попыток** исправления тесты продолжают падать по одной системной причине; дальнейшие локальные фиксы опасны.
- Из узкой задачи вырос архитектурный рефакторинг, затрагивающий больше трёх пакетов или миграции + обучение + API одновременно.

Если рекомендуешь усилить модель, коротко укажи **конкретный обнаруженный риск** и по возможности подготовь summary для продолжения задачи в новом чате/модели. Не убеждай переключаться без подтверждённой сложности.

## 4. Когда рекомендовать обратное переключение

После завершения трудного этапа (например, зафиксирована и протестирована схема `as_of`, модель прошла quality gate), если следующая задача ограничивается UI/контрактами/тестами, один раз напиши:

> 🧠 Следующая задача S2-02 — локальные изменения Draft Lab. Можно вернуться на GPT-6.1 Sol · Medium/High.

Не прерывать текущую задачу только ради экономии. Учитывать P0 как **важность достоверности**, но не считать, что каждая P0-задача автоматически требует Astra; выбрать модель по реальному объёму и риску.

## 5. Формат handoff, если переключение делается между задачами

Если попросили краткое резюме для смены модели/чата, перечислить:

1. Текущая задача `Sx-yy` и статус.
2. Проверенные факты, принятые архитектурные решения, инварианты.
3. Изменённые файлы, миграции (только новые, не редактировать применённые), тесты и реальные результаты проверок.
4. Точный следующий шаг + риск, ради которого нужна более сильная модель.

Не включать секреты, токены, полный дамп БД или данные не по текущей задаче.

## 6. Как вручную переключить модель

- **Codex в VS Code:** открыть селектор модели под полем ввода; выбрать модель и reasoning effort, если доступны в вашем аккаунте.
- **Codex CLI (интерактивно):** `/model` и `/reasoning`, если поддерживается установленной версией.
- **CLI при запуске:** `codex --model gpt-6.1-sol` (для доступной модели).

Эти команды меняют настройки Codex, а **не модель ML-прогнозирования Dota 2**. `AGENTS.md` не может программно переключить модель Codex.

Справка: [Models](https://learn.chatgpt.com/docs/models), [Codex commands](https://learn.chatgpt.com/docs/developer-commands), [Codex IDE settings](https://learn.chatgpt.com/docs/ide/settings).

## 7. Acceptance criteria

- В начале S3-00..S3-06 при прочих равных звучит предложение Astra · Extra High **до критических кодовых правок**.
- Для простого CSS/текстового изменения нет навязчивого предложения переключаться на Astra.
- Если текущая модель неизвестна, сообщение не утверждает, что она определённая.
- После завершения сложного gate Codex может предложить вернуться на Sol.
- Смена модели никогда не трактуется как выполненная без участия пользователя; пользователь может игнорировать рекомендацию.
- Подсказки не меняют план, приоритеты, критерии приёмки и не заменяют тесты.
