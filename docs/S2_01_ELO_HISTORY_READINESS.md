## Причины исключения 48 карт

1. **У всех 48 не заполнена локальная связь с серией.** В сохранённых receipts у 43 карт есть положительные provider series IDs: 23 серии. Существующий `SeriesProvisionRepository.preview` вернул `ready` для всех 23 групп, без конфликтов. Повторный сетевой запрос для этих source references не нужен. Importer связывает карту только с уже существующей локальной серией; personal-history job эту подготовку пока не выполняет.
2. **У 43 карт не подтверждены все участники в каноническом каталоге.** В совокупности обнаружено 75 разных unresolved аккаунтов прежних партнёров/соперников. Среди 43 карт с проверенным исходом таких аккаунтов 60; лишь пять из этих карт уже имеют все десять подтверждённых идентичностей. Importer сохраняет `source_account_id`, но не создаёт проверенную личность по одному факту участия.
3. **Пять карт не проходят действующий OutcomeVerifier.** В источнике `series_id=0` и отсутствует ID одной исторической организации: `8829975493`, `9036406856`, `9040119007`, `9040197051`, `9045164434`. Их нельзя исправить угадыванием по названию команды или текущему ростеру. `TEAM_SIDES_UNKNOWN` здесь означает требование исторических организаций в текущем verifier, а не отсутствие native Radiant/Dire slots. Это ограничение существующего замороженного пути проверки, а не математическая необходимость Elo.

У всех 48 карт есть десять различных числовых аккаунтов. Их slot/account пары совпадают со **всеми 66 сохранёнными receipts**. Код `ROSTER_RECEIPT_MISMATCH` у пяти карт — вторичное следствие: adapter не читает `receiptPlayers`, когда outcome недоступен. Он не доказывает противоречие фактических составов. Счётчики причин пересекаются.

15 остальных карт корпуса лежат до warmup; вместе с этими 48 это объясняет 281 − 218 = 63 исключения. Историческое подтверждение будущей пятёрки, роли, патчи и драфт причиной исключения не являются. Поздно полученная текущая проверенная связь того же Steam32 разрешена политикой V1 без изменения реальных evidence clocks.

## Следующий общий срез

**S2-01/role-owner-check/history-evidence-enrichment** — соединить personal-history загрузчик с существующими границами подготовки evidence:

1. Из выбранных map receipts собрать уникальные отсутствующие числовые аккаунты. Использовать общий актуальный кэш каталога; для отсутствующих записей — ограниченный numeric profile fallback, общий quota/retry budget и явные состояния conflict/unavailable. Не искать и не объединять игроков по нику. Сначала определить, какие профили действительно нужны; не делать запрос на каждый слот каждой карты.
2. Подготавливать и идемпотентно применять непротиворечивые серии из уже сохранённых receipts через существующий проверяемый preview/apply. Не считать неполную локальную серию полностью загруженной.
3. После новых proofs/references повторно обработать сохранённые payloads с исходными source SHA/clocks и новой контекстной ревизией; не скачивать те же детали автоматически заново. Сохранить старые receipts, datasets и predictions.
4. Показывать отдельно raw N и eligible Elo N. При недостатке eligible N разрешить ограниченное продолжение истории в выбранном окне с дедупликацией и видимым пределом; не повышать глубину бесконечно и не заменять неизвестные данные.

Это план следующей реализации, **не уже работающая автоматизация**. После заполнения связей нужен повторный аудит. Минимум пять карт, frozen kernel, независимая release validation и явная активация сохраняются. История всех подтверждённых pro-уровней допустима; будущие прогнозы V1 по-прежнему ограничены проверенным Tier 1 scope.
