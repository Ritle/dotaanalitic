# Общий каталог игроков

Owner-approved S2-01/unified-player-catalogue, 2026-11-04. Общая схема вместо персональных исправлений для отдельных игроков.

## Использование

1. Выберите будущую встречу и загрузите заявку. [Автоматическая подготовка](S2_01_AUTOMATIC_ROSTER_PREPARATION.md) покажет аккаунты и причины незавершённого выбора прямо в карточках команд. Для расширенного поиска используйте «Подготовить составы», затем **«Подготовить игроков»**.
2. Сохранённые связи по PandaScore player ID подставляются независимо от команды и текущего ника. Затем ищутся локальные подтверждённые аккаунты/наблюдавшиеся ники, реестр OpenDota и кандидаты общего поиска.
3. Проверьте подсказки. Единственный проверенный числовой кандидат заполняет черновик; при нескольких аккаунтах нужен выбор. Результат общего поиска сначала требует нажатия на кандидата и проверки числового профиля. Совпадение ника не становится verified identity.
4. При заявке больше пяти отметьте пятерых. Счётчики участников и аккаунтов разделены. Подтвердите соответствие и сохраните пятёрку. Можно исправить аккаунт обычным поиском по нику, ID или ссылке на профиль.
5. Проверьте роли и локальную pro-историю. Подготовка аккаунтов не импортирует карты и не активирует модель. При отсутствии истории показывается0; без активной проверенной модели прогноз остаётся unavailable.

Статусы: сохранённая связь, новый кандидат, неоднозначность, не найдено, источник недоступен/поиск отложен, конфликт. Повторная подготовка сохраняет ручной выбор и снимает подтверждение. Для локальных игроков видны канонический ID, наблюдавшиеся ники, дата проверки и число завершённых локальных pro-карт. Организация из заявки предлагается автоматически; её можно сменить на профиль OpenDota.

При сохранённой пятёрке подготовка сохраняет уже выбранную организацию и её namespace. Прежнее числовое подтверждение организации переиспользуется с исходными SHA/clock; оно не выдаётся за свежий ответ API. Это предотвращает дублирование организации и повторные запросы при неизменном team ID.

## Идентичности и исправления

SQL040: append-only `provider_player_links` хранит owner, PandaScore player ID, canonical player ID, Steam32, ссылку на immutable binding и серверное время. Старые связи читаются из последних пятёрок каждой команды; несколько различных аккаунтов означают конфликт, а не выбор последней команды. Новое подтверждённое решение становится общей связью и сохраняет ник заявки с текущими clocks. Ники не объединяют разные канонические личности.

`linkToken` защищает от изменений в другой вкладке. Legacy apply без token может исправить лишь последнее решение той же команды с совпадающей optimistic revision. Global locks и запись пяти связей находятся в одной транзакции с immutable binding. Исправление не сливает истории разных Steam-аккаунтов и не переписывает старые сценарии; противоречащая исправлению старая пятёрка перестаёт считаться пригодной для повторного использования.

Локальная проверенная пятёрка сохраняется с `registrySha256:null` без OpenDota. В source заморожены `localCards`, по которым вычисляется локальный source SHA. Для смешанной пятёрки сохраняются отдельные profile proofs и локальные карточки. Все числовые идентичности перепроверяются сервером. Это текущие решения владельца, не историческое доказательство опубликованного состава или явки.

## API и бюджет

- Owner/CSRF `POST /upcoming/:id/catalogue/prepare`, body `{}` либо `{externalSearch:false}`: roster SHA, nullable registry SHA, время подготовки, статус/linkToken/кандидаты каждой строки и optional reason для отложенного поиска/сбоя источника. Подготовка не создаёт игроков и не сохраняет выбор. Автоматический UI отдельно переиспользует только ранее проверенные общие связи; новые пары подтверждает владелец.
- `/search` теперь включает локальные aliases и bounded OpenDota `/search?q=…`. `localPlayerId` обозначает проверенный локальный аккаунт; `discovery:true` требует проверки профиля перед выбором. Частичный сбой возвращается отдельным warning, не пустым успешным поиском без объяснения.
- `/apply` сохраняет проверенные numeric identities и общие связи после подтверждения пятёрки; исторические snapshots не меняет. Частично завершённый identity provisioning остаётся повторяемым; окончательная пятёрка публикуется только после проверок.
- Внешний поиск: фиксированный host, shared quota, timeout6s, максимум2 попытки, Retry-After, response cap1MiB и до25 видимых результатов. [Официальный контракт OpenDota](https://raw.githubusercontent.com/odota/core/master/svc/api/spec.ts).
- Кэш нормализованного запроса1h, включая пустые ответы; failure cooldown1min; process coalescing и PostgreSQL lease. В подготовке максимум3 отдельных внешних name-search; остальные строки ищутся отдельно. Локальная найденная запись не вызывает внешний HTTP.
- Регистронезависимый поиск локальных имён использует PostgreSQL ICU collation `und-x-icu`; она должна быть доступна на хосте. Это проверено на рабочей Windows БД и временных тестовых БД. Системная C locale сама по себе не выполняет lowercase кириллицы. Проверка отдельного Linux-хоста остаётся отложенной.

Поиск не гарантирует нахождение каждого игрока: скрытый/неиндексированный профиль, одинаковые ники или ошибка провайдера могут потребовать однократного ручного выбора по ссылке/ID. Такой выбор сохраняется в общем каталоге и не требует правок кода.
