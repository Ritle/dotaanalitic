# S3-04 — автоматическая фиксация драфта в интерфейсе

После успешного сохранения редакции с десятью разными героями Draft Lab автоматически читает снимок и, если его ещё нет, вызывает owner capture. Дополнительное подтверждение или новая форма не нужны. Неполная редакция сохраняется обычным способом, без capture.

При открытии существующего сценария выполняется только чтение. Просмотр старого драфта не создаёт новый снимок задним числом. Для ещё не зафиксированной полной редакции интерфейс объясняет, что снимок появится при следующем сохранении. Существующая ссылка `scheduleTarget` передаётся серверу при создании; её проверяет прежний API. Сохранённый снимок читается и без этой ссылки в URL.

В боковой панели показываются загрузка, фиксация, готовность или сохранённые ограничения. Причины отображаются по-русски. В раскрываемом блоке — время записи, срез истории, число аккаунтов и локальных pro-карт. Эти сведения не объявляются прогнозом, полной историей или доказательством фактического старта.

Ошибка capture не отменяет сохранение сценария и не удаляет правки. Повтор сначала читает готовую запись: если первоначальный ответ потерялся после commit, второй POST не нужен. Сохранённый `unavailable` также неизменяем: исправленные данные требуют новой редакции. При конфликте предлагается загрузить сохранённую редакцию; действие явно предупреждает о замене локальных правок.

Vue Query хранит серверные снимки по сценарию и ревизии; пустой результат допускает повторное чтение при возвращении. Компонент привязан к редакции, отменяет запрос при уходе и не переносит результат в другую карту. Во время редактирования статус явно относится к сохранённой редакции; повтор фиксации при несохранённых правках отключён. Только владелец видит блок. Повторного фонового polling и запросов к провайдерам нет.

Файлы: `apps/web/src/components/DraftCapture.vue`, `apps/web/src/draft-capture.ts`, подключение в `apps/web/src/views/ScenariosView.vue`, браузерные проверки в `apps/web/tests/e2e/draft-capture.spec.ts`. API, SQL058 и модельные shared packages не меняются. [Серверный контракт](S3_04_PLAYER_HERO_OWNER_CAPTURE.md) сохраняется.

Прогноз после драфта остаётся недоступен. Следующая задача **S3-04/player-hero-capture-target-resolution**: проверить связь снимка с фактической картой по серии/номеру, аккаунтам и героям, сопоставить время фиксации с подтверждённым стартом; хранить результат отдельно, не изменяя снимок. Рекомендуемая модель: **GPT-6 Astra · High**.
