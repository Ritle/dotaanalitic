# S3-04 — ограниченный запуск и возобновление сбора

Реализован [локальный сборщик](../tools/research/conditional-collection-runtime.mjs), который выполняет последовательность разрешённых запросов из закреплённого журнала. Он использует прежние контракт, транспорт и SQL063–065. Новых миграций и изменений работающего API нет. Реальный удалённый сбор и модель после драфта этим не включаются.

## Как работает запуск

Перед изменениями проверяются владелец, подтверждённая регистрация и ожидаемый SHA пакета. Манифест должен содержать исходные исследовательские зависимости, entry points сборщика/CLI, клиент и квоты, все `.js` из `dist` пяти shared packages и их `package.json`, а также `pnpm-lock.yaml`. Проверяются SHA всех объявленных файлов, границы репозитория, исходный exposure ledger и зафиксированная Node/Python-среда. Отсутствующий файл в манифесте или несовпадение останавливают запуск. Корневой формат регистрации не расширялся: CLI расположен в допустимом `tools/research/`.

Это проверка объявленного кода и сборок при старте, не удалённая подпись и не проверка каждого файла установленных сторонних зависимостей. Во время запуска транспорт дополнительно проверяет собственные закреплённые файлы. Выпуск удалённого режима требует отдельной проверки исполняемого пути и реальных источников.

На одну регистрацию берётся PostgreSQL session advisory lock через выделенное соединение. Второй сборщик получает `busy`, не создавая резервов. Каждая HTTP-попытка по-прежнему защищена CAS-вершиной журнала и общей квотой; потеря процесса не даёт права повторно отправить незавершённую попытку. Блокировка освобождается в `finally`, отмена передаётся транспорту.

Затем сборщик:

1. До начала окна возвращает `collection_not_started`, не создавая журнал/обход.
2. Если есть незавершённый резерв и сохранённый ответ, завершает его по прежней квитанции без HTTP. Это возможно и после окончания окна, но не разрешает новые отправки.
3. Если ответа нет, возвращает `inflight_outcome_unknown`. Автоматического recovery через 120 секунд нет: истечение срока не доказывает завершение запроса.
4. Если в любой квитанции есть ошибка сохранения квоты, возвращает `quota_observation_failed`. Перезапуск не снимает остановку.
5. Последовательно берёт `nextRequest` из проверенного отчёта: зарегистрированные лиги, подробности наблюдённых карт, глобальные страницы с уменьшающимся BIGINT-курсором.
6. Останавливается на лимите запуска, закрытом окне, cooldown, ошибке/неверном ответе или отсутствии следующего запроса. Встроенного ожидания до Retry-After и автоматического цикла повторов нет.

По умолчанию разрешены **5 запросов за запуск**, максимум **20**. Временной бюджет после проверки манифеста — до **60 секунд**; он отменяет HTTP и запрещает следующие отправки. Это не обещание мгновенного завершения процесса при зависшем SQL/OS: сохранение результата и освобождение соединения остаются обязательными.

Новый запуск продолжает текущий обход и не повторяет завершённые страницы. После исчерпания страниц возвращается `scan_complete_not_denominator_verified`; это **не** доказательство полноты выборки и не verified pro data. Для повторного полного обхода нужен явный `newScan:true`; незаконченный обход этим флагом сбрасывать нельзя.

Перед новым запросом проверяется ёмкость журнала: к текущему сериализованному размеру добавляется запас `6 × 1 MiB + 64 KiB`. Он покрывает максимальное JSON-экранирование ответа транспорта и новые события. При недостаточном месте до лимита **64 MiB** возвращается `journal_capacity_low` без отправки. Лимиты прежнего формата не увеличиваются. Достаточность этих размеров для реальных карт пока не подтверждена.

## Локальная CLI

```powershell
node --env-file=.env tools/research/run-conditional-collection.mjs --request .tools/local-collection-request.json
```

Запрос содержит `mode: "local-synthetic"`, `ownerId`, `registrationId`, `registrationSha256`, `localOrigin` и необязательные `maxRequests`, `maxDurationMs`, `newScan`. Источник — только буквальный loopback `http://127.0.0.1:<port>`; redirects и токены не принимаются. **Обычная рабочая `.env` для этого режима не подходит:** CLI принимает только заранее созданную временную локальную базу `codex_ingest_<12 hex>`, с подготовленной синтетической регистрацией. Она не создаёт владельца, не регистрирует реальный план и не применяет миграции сама. Полный воспроизводимый стенд создают тесты ниже.

CLI выводит компактный JSON: причина остановки, текущая вершина, наблюдаемые счётчики, число возобновлённых квитанций и `retryAfterAt`. В нём нет сырых ответов, токенов и сообщений исключений провайдера/БД. Код завершения: `0` — штатный результат, включая busy/ожидание; `2` — блокировка с отчётом; `1` — неверный запрос или ошибка до отчёта. SIGINT/SIGTERM отменяют дальнейшую отправку.

При неопределённой ошибке шага возвращается `runtime_step_failed_inspect_journal`; неизвестные вершина/суммарные счётчики остаются `null`. Число подтверждённых результатов в текущем вызове не выдаётся за точное число фактических сетевых отправок. Исход определяется по журналу и квитанциям при следующем запуске.

Остановка из-за ошибочного ответа или квоты не снимается флагом `newScan`. Исправление причины и решение о следующем обходе — отдельное действие, не скрытый повтор. Прямой вызов отдельного транспорта другим кодом не заменяет блокировку runner; журнал защищает резервирование независимо.

## Проверка и готовность

[PG/HTTP/CLI-тесты](../packages/db/tests/conditional-collection-runtime.integration.test.ts) используют отдельную тестовую БД, синтетическую регистрацию и локальный сервер:

```powershell
node --env-file=.env node_modules/vitest/vitest.mjs run packages/db/tests/conditional-collection-runtime.integration.test.ts --maxWorkers=1 --testTimeout=30000
```

Проверяются порядок запросов, лимит/продолжение, квитанция после сбоя, неизвестный исход, сохранённая ошибка квоты, 429, неверный JSON, окно, конкуренция, отмена, новый обход, ёмкость, манифест и ограничения CLI. Прошли18 новых PG/HTTP/CLI-сценариев(16 +2 отдельных целевых),52 Node и1053 пакетных теста/8workspaces. Frozen offline install,typecheck,build,65SQL — PASS. [Машинный отчёт и SHA](evidence/s3-04-conditional-collection-runtime.json). Прежние код/SQL сохранены; рабочая БД остаётся на061. Интерфейс/API200,приватный маршрут без сессии401; активная V1 и7 прежних SHA прогнозов сохранены.

Рабочая модель V1 и её прогнозы остаются отдельным действующим путём. `collectionAllowed`, `remoteCollectionAllowed`, `realEvaluationAllowed`, `activationAllowed`, `deployable` здесь всегда `false`; observed maps не становятся обучающей выборкой автоматически.
