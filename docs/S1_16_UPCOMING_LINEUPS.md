# S1-16 — сравнение подтверждённых пятёрок

В ручной форме `/upcoming` после явного выбора двух canonical организаций, десяти разных игроков и подтверждения ролей доступна кнопка «Сравнить выбранные пятёрки». Само подтверждение запрос не запускает. Сценарий при сравнении не сохраняется.

Используется существующий защищённый stateless `POST /teams/compare` с owner session / Origin / CSRF. В запрос уходят только вручную выбранные организации, игроки, роли и stand-in flags. По умолчанию reader берёт последние 90 дней до серверного среза запроса, все патчи и турниры. Запланированная дата встречи не становится будущим cutoff. Ответ показывает фактические from/cutoff/snapshot/source. Сводка организации S1-15 сохраняет свой отдельный cohort последних20 локальных карт за всё время; он явно подписан.

## Что видно

- Organization WR/N отдельно от точной выбранной пятёрки в этой организации и от exact-five в любых организациях. Raw observed win rate с N; N0 → неизвестная частота побед. Без verified identity exact-five N остаётся null, даже если canonical запись выбрана вручную.
- Даты совместных карт, время обновления данных, sample evidence и количество подтверждённых identities. Отсутствие совместных карт не объявляется плохой сыгранностью.
- Раскрываемые десять unordered пар: ID, N/победы/raw WR и последняя карта через любые организации. Сумма N пар не называется уникальным числом карт пятёрки.
- Личная история пяти игроков через переходы между организациями, выбранная роль, количество подтверждённых/совпавших исторических ролей, stand-in marker и дата/время обновления. Роль не угадывается по lane_role; замена не даёт фиксированного штрафа.
- Видимое предупреждение о пропусках, подробные coverage/source timestamps и глобальные exclusions. Current retrospective evidence не доказывает известность состава до начала исторической карты. Это описание, модель/вероятности не добавлены.

## Актуальность формы

`UpcomingScenario.vue` передаёт comparison input только для валидной подтверждённой формы. `UpcomingLineupCompare.vue` хранит отдельный applied input; изменение формы или снятие подтверждения синхронно его сбрасывает. Vue Query key включает весь applied input, fetch использует AbortSignal. Отложенный ответ старого состава не показывается. Повторное подтверждение требует нового явного запуска, автоматического выбора пятёрки нет.

Во время запроса и при ошибке прежний результат скрыт. Для error есть retry; WINDOW_TOO_LARGE показывает unavailable без вымышленного N0. В [S1-17](S1_17_UPCOMING_FILTERS.md) добавлены даты UTC и patch/league filters прямо здесь, отдельно от формы сохранения сценария; ссылка из S1-15 на полное сравнение организаций остаётся доступной.

История обновляется через S1-14; нужен `pnpm worker:dev`. Terminal status инвалидирует существующий prefix `compare`, поэтому пересчитывается только ещё активный подтверждённый запрос. Новое чтение получает актуальный серверный cutoff. Неактивный applied input не запускается; сохранённые report versions не изменяются.
