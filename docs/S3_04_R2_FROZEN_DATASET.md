## Неизменность R1

Для всех1252train и398validation строк проверены прежние eligibility, причины исключения, входы, стороны, порядок игроков, рейтинги, использованные более ранние карты и метки.881/306пригодных примеров совпали точно; словарь героев и параметры остаются прежними. Любое содержательное отличие останавливает подготовку.

Меняется только явно перечисленное происхождение нового снимка: общий source fingerprint, identity revision, snapshot time и зависимые fingerprints. Их исключают из сравнения семантики, но сохраняют в новой выборке и manifest. Не игнорируются даты событий/получения фактов, порядок признаков, рейтинги, ID игроков, выбор истории или результаты карт.

Повторная проверка outcomes в более свежем сохранённом snapshot имеет новое `labelVerifiedAt`. Сами исходы, source receipts и факты прежних2232карт совпали. R2 сохраняет исходные label/verifiedAt из R1; новые реальные времена проверки записаны отдельно в `labelReverifications`. В исходных файлах и clocks ничего не исправлялось задним числом.

Все243файла прежнего capture manifest сохранены. Между снимками добавились только уже существовавшие к началу задачи SQL055/056/057 (Live и аудит импорта), привязанные к SHA нового capture. Новые миграции в этой задаче не создавались; произвольное добавление executable или изменение старого файла запрещены.

## История, серии и происхождение

Новый `tools/research/post-draft-r2-dataset.mjs` вызывает прежние `prepareV1PerMapFeatureHistory`, `buildPostDraftPlan` и `buildPostDraftDataset`. Он проверяет source/plan/artifact SHA, точные28импортированных ID, verified outcomes, canonical identities, native slots и сохранённый import plan. Герои history-only строк берутся из проверенной импортированной проекции с её отдельным SHA, а не угадываются по команде или нику; они не добавляются в training vocabulary.

Для проверки границ используется внутренний расширенный реестр всех2260известных карт с собственным derived fingerprint. Исходные2232цели сохраняют прежние окна и исключения;28исторических строк не становятся целями. Все известные соседи из import plan должны присутствовать и иметь согласованную series identity. Проверки временных границ и непригодных соседей распространяются на целую серию. На реальных данных новых изменений исходного series disposition не потребовалось.

Это проверка **известного локального корпуса**. Полнота удалённого списка карт серии остаётся unknown и не выводится из BO-формата. Происхождение составов/финальных героев остаётся `actual_lineup_reconstructed`, доступность — `event_time_assumed`. Новые данные не получают выдуманного раннего known_at. История для каждой цели строго завершена до её старта; сама цель и будущие результаты в её признаки не входят. Каждая карта представляет одну Dota-карту, не серию.

## Артефакт и воспроизведение

Локальный файл `.tools/s304-r2-dataset-r1.json` —34,4MB; суффиксr1 означает первую ревизию **датасета R2**. Он содержит отдельные rows/labels, sample/exclusion ledger, source hashes, early parity hashes, comparison IDs, real verification timestamps и manifest. Исходные R1 capture/dataset/fit/evaluation/protocol не перезаписаны. R2-коэффициенты и калибраторы не создавались.

```powershell
node tools/research/post-draft-r2-dataset.mjs verify .tools/s304-r2-dataset-r1.json
node --test tests/node/post-draft-r2-dataset.test.mjs
```

`create` пишет только новый файл (`wx`); `verify` заново строит результат из закреплённых локальных источников и сравнивает весь fingerprint. БД и сеть для этих операций не нужны. Синтетические входы отвергаются рабочей CLI; синтетика используется только в тестах.

## Проверки

Девять новых Node-тестов прошли: восстановление карты, точное совпадение старых данных, provenance, дубликаты/identity/receipt/hero errors, недостающие соседи, пересечение границы серии, equal-time/future cutoff, независимость input от target outcome, tamper train/labels/vocabulary, допустимые additive SQL и исходный SQL JSON порядок полей.

Первый реальный запуск остановился на различии manifests из-за трёх additive миграций; разрешены только эти известные SHA-привязанные добавления, старые executable не менялись. Второй запуск обнаружил, что schema parse переставлял JSON keys в lineup перед проверкой сохранённого byte hash. Ошибка воспроизведена отдельным RED-тестом, исправлена сохранением исходного wire representation; весь целевой набор GREEN. Неудачные запуски не создали dataset; R1 и source evidence не правились.

HTTP к провайдерам, business writes, новое обучение, scoring и активация —0. Перезапуск сервиса не требуется. Предыдущая эмпирическая проверка источников сохранена; новые данные взяты из закреплённых реальных import receipts, тестовая синтетика не считается покрытием.
