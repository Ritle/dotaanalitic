## Что непосредственно блокирует вероятность

1. **Нет независимой прошедшей проверки и активной модели.** Зарегистрированный неизменный release plan использует BLAST Slam IX main event 20–30 ноября; `evaluateNotBefore = 2026-12-02T00:00:00Z` (2 декабря 03:00 МСК). До этого данный протокол не разрешает финальную оценку. Наступление даты само по себе не гарантирует N, coverage, метрики или активацию.
2. **Утверждённый охват V1 — проверенные события Tier 1.** EPL Masters не включён в текущий зарегистрированный BLAST evaluation scope. Аналитика этой встречи разрешена; реализация процентов для любого турнира не считается уже утверждённой.
3. **Перед реальной активацией остаётся gap свежести расписания.** `scheduleTargetReasons` проверяет статус/время/двух участников, но не максимальный возраст наблюдения. Предыдущий [API audit](evidence/s1-09-api-usage-reliability-audit.json) описывает это ограничение; текущий код его подтверждает.

Дата проверки — свойство выбранного зарегистрированного протокола, а не обязательное математическое свойство Elo. Более ранний выпуск потребует отдельного заранее закреплённого независимого плана с неиспользованными при разработке результатами; старые plan/report/freeze нельзя переписать или объявить исследовательскую выборку новым независимым тестом. В этом аудите такой переход не выполнялся.

## Дальнейший порядок

1. **Текущий точный открытый срез: `S2-01/role-owner-check/history-enrichment-resume`.** Общий ограниченный повтор проверки недостающих numeric evidence по уже сохранённым map IDs, новый immutable report и свежие raw/eligible N; без повторной discovery/detail загрузки и специальных правил для отдельных игроков. Для текущей YeS — GL этот путь уже не является блокером минимальной истории; он закрывает общий пробел загрузчика.
2. **Перед активацией: отдельный schedule-freshness guard.** Явное состояние устаревшего расписания, ограниченный refresh и тесты; дополнение к S4 приёмке, ранее выявленное audit finding A01. Не реализовано этим документом.
3. **S3-01/V1-evaluation → S3-03/V1-candidate → S3-05/V1 activation.** По зарегистрированному окну собрать/проверить реальные карты, выполнить независимую оценку, сверить фиксированные N/series/coverage/Brier/log loss/calibration gates. Активация только при passed; при insufficient/failed сохранить unavailable.
4. **S4/V1 acceptance:** полный пользовательский путь с passed active model, reviewed Tier 1 событием и реальным pre-start single-map forecast → immutable snapshot → проверенный исход → журнал. Активную модель также проверить в backup/restore.

До этого не добавлять ради первого прогноза patch/hero/pub features, logistic/post-draft модель, автообучение или series forecasts. Linux deployment остаётся отложенным по выбору владельца.
