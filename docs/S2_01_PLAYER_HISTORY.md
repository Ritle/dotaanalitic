# Личная pro-история выбранной пятёрки

S2-01/role-owner-check/player-history + player-history-depth. Загрузка по проверенным Steam32 не требует OpenDota ID текущей организации. История игрока включает его прежние команды. Она не подтверждает будущую явку и не активирует прогнозную модель.

## Как пользоваться

1. В будущей встрече подготовьте составы и подставьте сохранённые пятёрки либо выберите пять игроков вручную.
2. В блоке **«Личная pro-история A/B»** выберите период90/180/365/730 дней и глубину10/25/50 карт на пятёрку, затем нажмите **«Загрузить историю игроков»**. По умолчанию интерфейс предлагает365 дней и25 карт. Все пять аккаунтов должны быть однозначно подтверждены в каталоге.
3. Дождитесь завершения. Показаны принятые, повторные, исключённые карты, ошибки и конфликты; в раскрываемом покрытии — отдельные числа для каждого игрока.
4. Откройте сравнение выбранных пятёрок. Открытые показатели и подсказки ролей перечитываются после загрузки. Ручной состав остаётся прежним.

Одна загрузка проверяет выбранное число **уникальных карт на всю пятёрку**. Поиск ограничен той же глубиной на каждого игрока; кандидаты выбираются поочерёдно из последних подходящих карт каждого. Общая карта скачивается и импортируется один раз. Это ограниченная выборка, не полная карьера и не гарантированные25/50 карт каждому. При достижении лимита поиска показано предупреждение: более ранние карты могут остаться. Нулевая выборка не означает отсутствие опыта. Существующая история организации остаётся отдельной.

Период загрузки не меняет фильтры аналитики. Для просмотра старых карт задайте соответствующее начало периода в сравнении. Подсказки ролей по-прежнему используют90 дней; для игрока с майскими картами нулевая недавняя выборка остаётся корректной.

Одинаковые пятёрки **с одинаковыми периодом и глубиной**, включая переставленные роли, используют одно задание и готовый результат15 минут. При других параметрах прежний результат скрывается; запрос за год не выдаёт кэш за90 дней. Одновременная загрузка одной пятёрки с разными параметрами возвращает409 с пояснением. Ошибка разрешает повтор не раньше минуты, с учётом Retry-After. Поиск/импорт не запускаются при обычном просмотре блока.

## Обработчик

После сборки и применения SQL041–042 стандартный `pnpm worker:dev` обслуживает и новую очередь. Для обработки **только личной истории**, без ранее поставленных задач организаций и карт:

```powershell
pnpm shared:build
node --env-file-if-exists=.env scripts/player-history-worker.mjs
```

API ставит задания атомарно в PostgreSQL/pg-boss; без обработчика они остаются в очереди. Состояние переживает перезапуск API. Потерянное/отменённое задание отмечается ошибкой. Отдельный обработчик использует `opendota-player-history`, не очередь Aurora `opendota-team-history`.

## Источник и ограничения

Проверены первичные источники OpenDota: [API matches/explorer](https://github.com/odota/core/blob/master/svc/api/spec.ts), [схема matches/player_matches/leagues](https://github.com/odota/core/blob/master/sql/create_tables.sql). Общая история может содержать непрофессиональные матчи; `lobby_type=1` сам по себе не pro-доказательство.

Фиксированные read-only запросы Explorer: максимум5 Steam32, только числовые значения, выбранное временное окно, завершённые карты, лиги `professional`/`premium`. Страница содержит до10 строк на аккаунт; максимум5 страниц/250 строк при глубине50. Курсор хранит пару start_time/match_id, ID сравниваются как bigint, OFFSET не применяется. Аккаунты с короткой страницей больше не запрашиваются; повторная, обратная или чужая страница отвергается. Произвольный SQL, endpoint и ID организации не принимаются от владельца. Ответ ограничен1MiB и валидируется; API key не попадает в URL. Общая PostgreSQL-квота OpenDota, timeout и Retry-After действуют для discovery и деталей. Полнота удалённого корпуса не гарантируется.

Справочник лиг и детали каждой выбранной карты проверяются заново: pro-статус, исход, завершение до среза, соответствие discovery времени/длительности/исхода/лиги, Steam32 и player_slot. `excluded`/`amateur`/неизвестная лига не становятся pro. Связи аккаунтов проверяются при постановке и исполнении; конфликт/изменение останавливает задание. Неизвестные историческая организация, патч, серия и draft не выдумываются.

Используется существующий `IngestionService`, прежняя идемпотентность и правила source evidence. `event_at`, `known_at`, `fetched_at` не подменяются друг другом. Текущие сведения не объявляются известными перед историческим матчем. Синтетические данные применяются только в изолированных тестах. Frozen runtime, training datasets и модели не изменяются.

## API и хранение

- `GET /api/v1/players/history-refresh?playerIds=ID,ID,ID,ID,ID&windowDays=365&maxMaps=25` — доступность и последнее задание для текущих проверенных связей и параметров.
- `POST /api/v1/players/history-refresh`, тело `{ "playerIds": ["1", "2", "3", "4", "5"], "windowDays": 365, "maxMaps": 25 }` — создание либо повторное использование задания. Owner session, origin и CSRF обязательны;202 означает постановку, не завершённый импорт. Для старых клиентов пропущенные параметры означают90/10.
- SQL041 добавляет `player_history_runs`; SQL042 добавляет options с прежними90/10 для старых строк. Старые SHA ключей и report v1 сохраняются. Новые report v2 содержат options, число страниц и отдельные sourceLimitReached; source audit сохраняет все страницы и их clocks/hash/attempts. SQL001–041 не меняются.

Штатный пакет использует не более13/30/57 методов для глубины10/25/50: до1/3/5 страниц +2 справочника +до10/25/50 деталей. Сетевые повторы расходуют общую квоту отдельно. Бюджет detail-клиента104 попытки, не более2 попыток на метод; Retry-After сверх5 секунд завершает соответствующую попытку загрузки явной ошибкой. Job expiry1800 секунд задаётся и на конкретном новом задании. Повтор готового результата с теми же параметрами в пределах cooldown не обращается к провайдеру.

Это не проверка пригодности данных для Elo и не допуск модели.

Для просмотра уже загруженной истории выберите встречу, проверьте подставленные пятёрки, подтвердите5+5 и задайте **«Период сравнения» → «Последний год»**. Нажмите **«Сравнить выбранные пятёрки»**. Заново загружать карты для этого не нужно. [Краткая инструкция](S1_16_COMPARISON_UX.md). Период загрузки и период сравнения независимы. При необходимости пополнить историю откройте ручной редактор и личную pro-историю; при достигнутом лимите поиска можно явно выбрать50 карт, новая загрузка имеет собственный кэш.

Проверки:801 unit/CLI,74 Node,8 PG/API,4 Chromium, real UI/mobile; сохранность исходных фактов, старых заданий и frozen runtime подтверждена. [Evidence](evidence/s2-01-player-history-depth.json). ## Последующая подготовка истории

После импорта теперь автоматически проверяются аккаунты остальных участников и связи серий, затем выполняется replay тех же ответов без дополнительных detail calls внутри задания. В report v3/UI отдельно показаны raw N и eligible Elo N, partial/budget warnings и время проверки. [Контракт и ограничения](S2_01_HISTORY_ENRICHMENT.md). Для живой A-пятёрки проверено365/50, B365/25; история достаточна у9/10, модель не активирована. Продолжение только недостающих evidence без новой загрузки карт — следующий срез, пока отсутствует.
