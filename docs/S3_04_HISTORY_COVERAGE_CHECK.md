# S3-04/history-coverage-check — эффект добавленных 28 карт

13 ноября 2026. Диагностика выполнена на сохранённом снимке рабочей БД после [импорта](S3_04_HISTORY_IMPORT_APPLY.md). [Сводка и SHA](evidence/s3-04-history-coverage-check.json). Это подсчёт покрытия прежней исследовательской выборки: новые вероятности, обучение и активация не выполнялись.

## Результат

| Показатель | До | После |
|---|---:|---:|
| Карты в исходном снимке | 2232 | 2260 |
| Пригодные карты истории по прежнему builder | 2158 | 2186 |
| Проблемные сочетания «игрок × целевая карта» | 98 | 60 |
| Сумма недостающих участий до минимума 5 | 272 | 183 |
| Целевые карты с недостаточной историей | 39 | 24 |
| Аккаунты с оставшимся дефицитом | 34 | 20 |

Все 28 добавленных карт внесли вклад хотя бы в одну из 39 целевых карт. История выросла у 242 из 390 сочетаний «игрок × целевая карта». Числа 272 и 183 — сумма дефицитов по этим сочетаниям, **не число уникальных карт**, которые требуется скачать.

15 целевых карт теперь достигают прежнего минимума истории. Пять из них остаются исключёнными из-за других карт той же серии; дополнительно снимается зависимое исключение одной соседней карты. Поэтому потенциальное восстановление — **11 карт**, а верхняя граница покрытия исходного позднего блока — **186/223 (83,41%)** вместо 175/223 (78,48%). Знаменатель 223 сохранён; причины исключений не удалены из исходного dataset.

Это только верхняя граница по устранённому дефициту, а не результат нового dataset builder. Превышение прежнего порога покрытия 80% не означает прохождение остальных quality gates или улучшение точности. [Исходная оценка R1](S3_04_OFFLINE_EVALUATION.md) остаётся неизменной.

## Доступность на момент прогноза

Добавленные события произошли до соответствующих целевых карт, но их локальное получение и проверка состоялись 13 ноября. Число новых связей «историческая карта × игрок × цель», для которых доказана доступность до целевого cutoff, — **0**. В подсчёте сохранён прежний условный режим `actual_lineup_reconstructed` / event-time-assumed. Текущая подтверждённая идентичность не превращается в исторически известную пятёрку.

Отдельная проверка доступности требует ранних clocks карты, проверенного исхода, всех фактов и идентичностей всех десяти участников. Отсутствие доказательства не объявляется доказанной недоступностью источника в прошлом. Новый снимок содержит реальные данные, но не доказательство возможности тогда получить такой прогноз.

## Реализация и воспроизведение

Новый `tools/research/post-draft-history-coverage.mjs` использует неизменённые `prepareV1PerMapFeatureHistory` и `createV1FeatureBuilder`. Он сохраняет прежние карты, добавляет ровно 28 ID из frozen import report, сверяет canonical players, native slots, verified outcomes и SHA. Для каждого игрока независимый recount по использованным ID проверяет строгие start/completion cutoffs. Проверка изменения identities не позволяет незаметно пересчитать исходный baseline.

`capture` читает локальную БД через существующий repository; business writes и provider HTTP отсутствуют. `audit` и `verify` работают по локальным файлам без БД. Выход создаётся только новым файлом; существующий результат не перезаписывается. Исходные capture/dataset/evaluation/import evidence остаются неизменными. Исследовательский код находится вне frozen `scripts/` и shared packages; API, UI, SQL и зависимости не менялись.

```powershell
# Уже выполнены capture и audit. Для повторной проверки:
node tools/research/post-draft-history-coverage.mjs verify
node --test tests/node/post-draft-history-coverage.test.mjs
```

Снимок: `.tools/s304-history-coverage-source-r1.json`; итог: `.tools/s304-history-coverage-r2.json`. Суффикс r2 относится к версии отчёта аудита, **не к новому обучающему dataset R2**. Предварительный r1 сохранён; итоговая версия дополнительно проверяет historical identity clocks и привязку import plan. Локальные файлы содержат подробные списки; публичная сводка хранит SHA и оставшиеся 20 аккаунтов.

Семь новых Node-тестов проверяют отсутствие мутаций, границы времени, незавершённые карты, целые серии, поздние identity clocks, bigint IDs, дубликаты, старый baseline, identity conflicts, перестановку сторон, независимость покрытия от исходов и пустую выборку. Они прошли. Frozen offline install, typecheck и все 978 пакетных тестов прошли с первого прогона. Проверены 57 контрольных сумм миграций, ссылки документации, offline replay с недоступной БД и отказ повторной записи. Финальный offline replay после сборки прошёл с тем же результатом. Сборка прошла; прежние предупреждения Zod-аннотаций и web chunk >500 kB сохраняются. API/Web отвечают 200, приватный endpoint без сессии — 401; прежняя модель остаётся `model_eligible` с теми же model ID/report SHA. Отдельные браузерные и PostgreSQL integration suites не запускались: UI/API/SQL не менялись; новый снимок прочитан из реальной локальной БД.

## Границы следующего R2

1. Сохранить R1 как опубликованный отрицательный/недостаточный исследовательский результат. Поздний блок уже изучен; повторный расчёт на нём не станет независимым тестом.
2. До нового fitting зарегистрировать отдельную ревизию протокола: источник и SHA, временные блоки, целые серии, неизменённые или явно обоснованные заранее признаки/пороги, сравниваемые варианты и правила остановки.
3. Старый блок допустим только для разработки с соответствующей маркировкой. Для независимой оценки нужен отдельный ранее не использованный период после фиксации исполняемого кода; наличие достаточного корпуса ещё предстоит проверить.
4. Сохранить разницу между условной реконструкцией и доказанной stage availability. Дополнительная история не решает неизвестность ролей/патча и преддрафтовой доступности героев/составов. Release требует отдельного решения этих gates.
