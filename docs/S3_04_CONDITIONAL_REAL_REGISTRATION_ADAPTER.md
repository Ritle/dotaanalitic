# S3-04 — журнал проверенного плана условного теста

15 ноября 2026. Реализован внутренний адаптер хранения плана: проверка сохранённых источников, кода и среды, неизменяемая запись PostgreSQL и подтверждение её фиксации другой транзакцией. Реальные турниры в этой задаче не регистрировались. Сбор карт, оценка качества и включение post-draft модели остаются отдельными незавершёнными шагами.

## Что реализовано

- [Контракт пакета](../tools/research/conditional-real-registration.mjs) требует точные SHA прежней политики, кандидата и базовых исключений; два основных выпуска турниров с разными числовыми ID; сохранённые документы и их SHA; проверку владельцем и консервативную нижнюю границу начала. Квалификация вместо main event, совпадение имени без числовой ссылки, неподтверждённый флаг готовности, изменение окна или бюджета отклоняются.
- [Адаптер](../tools/research/conditional-real-registration-store.mjs) допускает только действующего владельца. Перед записью проверяет фактические файлы объявленного исполняемого набора и Python/Node-среду. Входного параметра для замены серверного времени или проверки среды нет.
- [SQL063](../packages/db/migrations/063_conditional_real_registration.sql) добавляет отдельные таблицы плана и квитанции. Часы задаёт PostgreSQL; квитанция должна наблюдать запись из другой завершённой транзакции. UPDATE/DELETE/TRUNCATE запрещены. Один policy SHA получает один пакет; идентичные параллельные запросы и повтор после успешной фиксации возвращают прежнюю запись.
- Перед каждой из двух записей исключения сверяются с объединением прежних 5674 карт / 1768 серий и текущих локальных карт/известных OpenDota-серий. Блокировка таблиц не позволяет импорту изменить этот набор до commit. Потеря старого ID, дубликат, произвольное добавление или устаревший пакет отклоняются. Если импорт произошёл между транзакциями, квитанция не создаётся.

План и подтверждённый commit различаются: `commit_unconfirmed` и `registered_plan_only`. Оба состояния возвращают `collectionAllowed:false`, `realEvaluationAllowed:false`, `activationAllowed:false`, `deployable:false`. Сохранение плана не является допуском модели.

## Граница доказательств

Пакет содержит документы, проверенные владельцем. SHA доказывает неизменность сохранённых байтов; JSON pointer связывает числовой ID и URL организатора в сохранённом документе. Это **не цифровая подпись API и не автоматическая проверка истинности сайта**. Подготовка достоверного пакета источников остаётся обязательной; синтетические документы тестов не подходят для реальной регистрации.

Нижняя граница начала — явно записанное консервативное решение владельца, а не выдуманное точное время старта карты. Регистрация должна произойти раньше этой границы, окна и срока решения. Прежние сроки не менялись: решение до 19 ноября 18:00 UTC, окно 20 ноября–18 декабря UTC, итоговая оценка не ранее 25 декабря UTC.

Проверка файлов фиксирует существующий объявленный набор. Она не доказывает готовность ещё не реализованного реального сборщика/численного consumer. Перед реальной регистрацией необходимы законченный исполняемый путь, его полный манифест, проверенные main-event bindings и источники. Структурно корректный тестовый пакет не закрывает эти требования.

Список исключений включает прежний архив и локальную БД; полнота всех внешних архивов не заявлена. До регистрации новые внешние наблюдения требуют отдельного проверяемого обновления базового перечня. После завершённой регистрации новые наблюдения не переписывают её. Незавершённый пакет с изменившимся набором остаётся заблокированным; изменение первого пакета через повтор запроса не допускается.

## Проверки и эксплуатация

Новые [Node-тесты](../tests/node/conditional-real-registration.test.mjs) проверяют пакет и отказы. [PostgreSQL-тесты](../packages/db/tests/conditional-real-registration.integration.test.ts) работают только в случайно названных временных базах, включая права, конкуренцию, rollback, сроки, восстановление после прерывания, неизменяемость и обновление исключений. Подмена часов применяется только тестовым DDL в этих базах. [Фикстуры](../tests/fixtures/conditional-real-registration.mjs) помечены синтетическими.

Это внутренняя библиотека без HTTP/CLI-интерфейса регистрации. SQL063 в рабочую БД не применялась; прежние SQL001–062 и синтетический журнал не менялись. Активная V1 и её прогнозы не затрагиваются. Итоги реально исполненных проверок и SHA файлов перечислены в [машинном отчёте](evidence/s3-04-conditional-real-registration-adapter.json).

Повтор целевых проверок из корня проекта после сборки shared packages и подготовки прежних S3-04 исследовательских артефактов:

```powershell
node --test --test-concurrency=1 tests/node/conditional-real-registration.test.mjs tests/node/conditional-registration-preflight.test.mjs tests/node/conditional-registration.test.mjs
node --env-file=.env node_modules/vitest/vitest.mjs run packages/db/tests/conditional-real-registration.integration.test.ts packages/db/tests/conditional-registration-storage.integration.test.ts --maxWorkers=1 --testTimeout=30000
```

Отсутствие закреплённых исследовательских файлов или PostgreSQL вызывает ошибку, а не пропуск проверки. При первом прогоне исправлены конфликт синтетической фикстуры с ограничением одного владельца и приоритет JSONB-операторов SQL. Тест замороженного V1-манифеста пришлось повторить после окончания редактирования миграции, входящей в его SHA. PG-прогон с ошибочно оставленным стандартным лимитом 5 секунд повторён с принятым в проекте интеграционным лимитом 30 секунд; отдельная проверка Python-среды занимает больше пяти секунд.
