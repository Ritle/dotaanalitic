# S3-07 — повторное использование выбранных Tier1-событий

Продолжение выбранной владельцем разработки после [назначений с разных страниц](S3_07_SCHEDULE_PAGE_TARGETS.md). Срез реализует небольшую управляемую библиотеку конкретных событий/сезонов по ТЗ §0.7. Список содержит решения владельца и не заявляет автоматическую или официальную классификацию всех турниров.

## Как пользоваться

В расчёте сохранённого сценария или назначенной первой карты выбрать «Ввести новое событие». Указать внешний ID лиги **OpenDota**, название, период UTC `[начало, конец)`, HTTPS-источник и обоснование. Подтвердить принадлежность карты основному событию Tier 1. Кнопка «Сохранить событие для следующих матчей» добавляет запись в общий список без запуска прогноза.

Для следующей карты выбрать «Сохранённый турнир Tier 1». Период, источник, обоснование и время сохранения видны без повторного ввода. Выбор после открытия страницы требует подтверждения владельца. При сохранении только что подтверждённого нового события подтверждение сохраняется, если входные данные и контекст не изменились. Затем нажать обычную кнопку расчёта.

Раннее предупреждение показывает неизвестный/несовпадающий внешний ID лиги и карту вне периода события. Полная проверка остаётся в существующем runtime: валидная по форме ошибочная область может сохраниться в unavailable-попытке с причиной. Отсутствие активной проверенной модели также оставляет вероятность недоступной. Выбор турнира не означает прохождение проверки качества.

«Создать копию для исправления» открывает ручной ввод; сохранение создаёт отдельное событие. «Убрать из быстрого выбора» сохраняет выключенную редакцию и убирает запись из списка. Это управление удобным списком, не отзыв выпущенных прогнозов и не новая блокировка ручных запросов. Для другого ID OpenDota нужна отдельная запись. До 20 актуальных включённых записей показаны на странице; остальные доступны явными кнопками навигации.

## Хранение и границы

Forward-only миграция **049_owner_tier1_scopes.sql** добавляет только `owner_tier1_scopes`. Запись включает полный scope, scope/request UUID, номер редакции, предыдущий SHA и фактическое server recordedAt. UPDATE/DELETE/TRUNCATE запрещены; выключение и последующие изменения — новые редакции. Exact request/hash retry и CAS защищают повтор/конкуренцию. Старые SQL и model/release artifacts сохраняются.

Owner/session/CSRF защищают `GET/POST /api/v1/tier1-scopes`. GET читает только локальную БД; optional `localLeagueId` разрешается через canonical leagues.opendota_league_id, без сопоставления по имени или PandaScore ID. Unknown остаётся null. POST использует существующий runtime scope Zod-контракт: только OpenDota, tier=1, main_event, положительный string ID, период, источник и обоснование. Никаких provider HTTP, автоматического обхода событий или фонового обучения нет.

Общий Vue-компонент используется в обоих видах расчёта. В prediction request копируется **полный scope**, а не изменяемая ссылка на каталог. Предыдущий снимок не переписывается при выключении/коррекции записи. Время сохранения решения владельца не выдаётся за время объявления турнира или историческую availability. Библиотека не меняет зарегистрированный BLAST release-test, Elo-признаки или независимые quality gates.

## Проверка

Контракты проверяют числовую точность, запрет tier2/qualifier и полуоткрытую границу периода. API/PG — auth/CSRF, строгую схему, owner isolation, retry/CAS, конкуренцию, immutable revisions, пагинацию, локальный mapping и сохранность frozen forecast после выключения события. Browser — сохранение без расчёта, повторный выбор после reload, оба вида расчёта, потерю POST-ответа, выключение и 360px. Синтетические события находятся только в отдельных тестовых БД. Рабочий каталог не заполняется придуманными событиями.

Результаты реально выполненных проверок дописываются после QA. Следующий release gate остаётся **S3-01/V1-evaluation/collection**, начало 20 ноября 2026 в03:00МСК, оценка не ранее 2 декабря в03:00МСК; до него активная модель и реальные показатели качества отсутствуют.
