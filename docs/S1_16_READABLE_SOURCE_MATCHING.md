# S1-16 — понятное сопоставление источников

Срез №7 BUG_REPORT: `S1-16/BUG_REPORT/readable-labels/source-matching`.

В блоке «Автоопределение ролей A/B» раскройте «Сопоставление источников».
У каждого выбранного игрока показаны ник и текущая роль формы. Локальная
команда подписана именем и открывается в карточке. Локальные ID доступны
в «Данных выбранной команды/игрока», внешние ID команды STRATZ и
команды/турнира PandaScore — в «Идентификаторах источников A/B».

В списке PandaScore остаются имя, внешний ID и позиция источника: они
нужны для различения записей. Роль источника может отличаться от выбранной
роли формы. При повторяющихся никах появляется просьба сверить записи.
Выбор по имени не подтверждает личность; сохраняются прежние числовые
ключи и явное подтверждение владельца. Изменение выбора снимает это
подтверждение. Показ имён не включает автоматическое назначение ролей.

Если сохранённого ID нет в загруженной заявке, он остаётся выбранным с
соответствующей пометкой. До загрузки заявки текст отличается. Никакой
ближайший ник вместо него не выбирается. Пустое и недоступное имя
различаются; резервная подпись профиля допускается только через прежнюю
проверенную числовую связь. Неоднозначные или устаревшие сведения не
создают новую личность.

Сводка времени получения источников подписана «Профиль STRATZ: ник»
при однозначном проверенном аккаунте либо общим названием профиля;
PandaScore — «Заявка турнира PandaScore». Полный ключ источника доступен
в подробностях. Ответ API не содержит названий внешней команды и турнира:
локальное имя не подставляется вместо них.

## Границы изменения

Подписи берутся из существующего выбора формы и ответа role-profiles.
Новых API-запросов, миграций или зависимостей нет. Формат binding,
expectedRevision, requestId, подтверждение, роли, аккаунты, eligibility и
refresh/cooldown механизмы сохранены. Общие пакеты и исполняемый код
активной V1-модели не менялись. Снимки сценариев не переписываются.

Изменены RoleProfiles.vue, новый чистый source-matching-labels helper и
его unit-тесты, браузерные проверки role-profiles/role-editor-priority.
Временная API-фикстура изолирует HTTP-бюджет каждого случая перезапуском
сервера, сохраняя тестовые bindings/cache и ограничения провайдера в БД.
Production лимиты не менялись. Синтетические источники используются
только в тестах, не являются проверкой живых STRATZ/PandaScore профилей.
