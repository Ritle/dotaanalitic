# S3-01/V1-retest/collection — сбор источников второго исторического теста

6 ноября 2026. Реализован отдельный сборщик для [зарегистрированного протокола семи турниров](S3_01_V1_RETEST_PROTOCOL.md). Он сохраняет детали карт и более раннюю pro-историю для последующей проверки данных. Импорт в основную базу, расчёт Elo, оценка качества и активация модели в этот этап не входят. Первый исторический FAIL сохраняется.

## Границы и сохранность

Новый формат `retest-source-collection-v2` не меняет старые collector, importer или frozen executable. Используются прежние чистые проверки источников, whole-series exclusions и история только завершённых pro-карт. Исходные 967 target IDs сохраняются; неудачная загрузка не удаляет карту из знаменателя. Первоначальный test denominator — 670 карт / 333 известные серии. Уточнение series ID может распространить ранее установленное исключение на всю серию; недостаток состава или истории не является основанием убрать неудобную карту.

Параметры сбора закреплены до первого запроса деталей:

- До 3 HTTP-попыток на карту суммарно за все перезапуски, включая retries; HTTP 404 завершает загрузку этой карты раньше.
- До 50 HTTP-попыток на запуск. Общие PostgreSQL-квоты OpenDota и `Retry-After` действуют дополнительно.
- История: до 10 завершённых pro-карт на аккаунт за 730 дней до 1 февраля 2026, 00:00 UTC, числовой порядок аккаунтов, группы по 5. Каждый запрос истории также ограничен 3 HTTP-попытками.
- До 5 000 уникальных source maps, без молчаливого усечения.
- Остановка после завершения всех работ либо 13 ноября 2026, 00:00 UTC / 03:00 МСК. При раннем завершении ждать этой даты не требуется.

Перед каждым HTTP сохраняется отдельная запись допуска и выполняется fsync. После аварии попытка без ответа считается израсходованной. Успешный ответ, статус ошибки, время ожидания и причина отказа записываются отдельно. Счётчик не обнуляется при следующем запуске. Отказ общей квоты до HTTP не расходует попытку карты.

Файлы публикуются эксклюзивно через временный файл и hard link. Завершённый временный файл восстанавливается с проверкой SHA и привязки; неполный или конфликтующий не принимается за источник. Одновременный запуск закрыт process lock. Снять оставшуюся блокировку можно только по точному SHA коллекции и после проверки отсутствия её процесса. Команда не завершает чужие процессы.

Кэш проверяется по SHA исходного ответа, сохраняет настоящий `fetchedAt` и не вызывает HTTP. В отдельный manifest перенесены 836 прежних наблюдений, из них с target IDs совпали 5. Это не 836 новых карт для теста. Сырые ответы и история попыток хранятся локально в `.tools`.

Deadline проверяется перед квотой, перед записью допуска, непосредственно перед fetch и перед принятием ответа. Поздний ответ остаётся в журнале, но не становится пригодным источником. Closure сохраняет итоговый отчёт и fingerprint всех принятых записей/попыток/запусков; повторный вызов после closure не обращается к API. Частичный сбор до deadline нельзя принудительно выдать за завершённый.

## Команды

После сборки workspace:

```powershell
$collection = '.tools/v1-retest-collection-20261106/store'
$collectionSha = '916da747453e2bdb02bf58dc3c7b6aaa07991b20e214c5f9646bdbc98fd5378d'
node --env-file-if-exists=.env scripts/collect-v1-retest.mjs targets $collection $collectionSha
node --env-file-if-exists=.env scripts/collect-v1-retest.mjs history $collection $collectionSha
node scripts/collect-v1-retest.mjs status $collection $collectionSha .tools/retest-status-new.json
```

`targets` и `history` выполняют один пакет до 50 HTTP; повторять после завершения предыдущего пакета, учитывая `resumeNotBeforeAt`. `history` разрешён после получения либо terminal-отказа всех target details. `status` пишет только новый отчёт; существующий файл не заменяется. Источники повторно проверяются без сети. Квоту не увеличивать для обхода остановки.

На коллекции более тысячи ответов полная офлайн-проверка занимает несколько минут. Отсутствие промежуточного вывода `status` в это время не означает зависание; не запускать второй collector и не снимать блокировку работающего процесса.

`init CONFIG SHA NEW_DIRECTORY` создаёт только новую коллекцию. Конфигурация этого сбора: `.tools/v1-retest-collection-20261106/config.json`, SHA `5efe9bf805ff0c59c706df4c9da21db0bff725f46845f02e632577763cd7020a`. Она связывает неизменные protocol/inputs/canonical history/cache. Команда `close DIRECTORY SHA` допускает closure только по terminal/deadline. `recover DIRECTORY SHA` предназначена для оставшегося lock уже завершившегося процесса.

## Проверки реализации

19 новых Node-проверок покрывают кэш и повтор без HTTP; накопительный предел попыток; аварию после допуска; лимит 50; квоту до запроса; 429 и Retry-After; внутренние retries истории; deadline и поздний ответ; 404; подмену SHA/scope; восстановление pending; конфликт эксклюзивного вывода; подмену закрытой коллекции; live/dead process lock. Отдельный перебор переходов часов воспроизвёл и закрыл ошибку принятия cache record после deadline: момент принятия теперь проверяется и записывается одним значением.

Проверка источника не заменяет каноническую проверку личности, исхода, полного состава и достаточной истории. Метрики качества и вероятности остаются `null`. После полного сбора следующий этап — **S3-01/V1-retest/canonical-import** с отдельным v2 adapter, воспроизведением source plan до записи и повтором импорта без изменений данных. Следующая модель: **GPT-6 Astra · Extra High**.
