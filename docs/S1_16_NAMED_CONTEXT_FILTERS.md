# S1-16 / BUG_REPORT №7 — фильтры патчей и турниров

В сравнении организаций и будущих пятёрок, списке pro-карт, истории игрока
на героях, парах героев и форме отчёта патч/исторический турнир можно выбрать
по названию из локального каталога. Нажмите «Найти», уточните название,
при необходимости перелистните страницы по20 записей и выберите результат.
Пустой поиск показывает первую страницу. Одинаковые названия не объединяются:
ключи каждой записи доступны в «Данные записи».

Поисковая строка не меняет текущий фильтр. Неподтверждённый текст поиска,
отсутствие результатов и ошибка каталога не расширяют выборку. «Сбросить»
явно снимает ограничение. Режимы «все патчи»/«на дату среза» и даты UTC прежние.
Положительный неизвестный ID сохраняется: он не подменяется режимом «все».
При необходимости старый числовой ввод доступен в «Технический ID»;
при наборе цифр названия не запрашиваются, lookup выполняется после blur.
В запрос анализа уходит исходная числовая строка, без Number-преобразования.

Используются именно **локальные ключи** leagues/patches. Выбор названия
не преобразует ID в OpenDota/PandaScore, не подтверждает Tier1, участие,
release timestamp или доступность героев. Внешние поля сопоставления не менялись.
Названия в применённых фильтрах читаются по ключам ответа отчёта, отдельно
от редактируемых фильтров и immutable snapshots. Источник/время чтения
доступны в подробностях. N/WR, pro-only/cutoff, weighting и модель прежние.

Новый приватный `GET /api/v1/context-catalog` выполняет только SELECT
локальных названий patches/leagues. Zod ограничивает kind, query80, offset10000,
точный bigint ID и несовместимые режимы поиска. Страница до20 записей,
hasMore по21 строке; ID-lookup до1. Поиск literal substring, включая `%_`.
SQL параметризован, таблица/колонка — из закрытого mapping. Providers,
автосинхронизация, новые SQL, frozen packages и prediction pipeline не затронуты.

ContextPicker и ContextFilterLabel используют общий cache точной выбранной
записи. Выбор результата сразу наполняет этот cache, без дополнительного
per-result GET. Поиск явный, без запроса на каждую букву; retry/refocus выключены,
сигнал отмены передан. Срок свежести5min, явный повтор поиска обновляет названия.

**Рабочие данные:** каталог патчей пуст (HTTP200,0 записей), турниры доступны.
Это показано честным empty state; патчи не создавались. Выбор именованного
патча и его точные фильтры проверены на временной PostgreSQL-базе.
Рабочий UI проверен с «Все патчи» и локальным турниром1786 «1win Essence II».
Изменение поисковой строки сохранило выбранный ключ/сводку, сравнение было одно;
business writes/provider HTTP/page errors/5xx нет, desktop/360px PASS.

Проверки и сохранность: [evidence](evidence/bug-report-named-context-filters.json).

Frozen offline install, общая типизация,914 unit/CLI при одном worker и сборка
PASS без unit-повторов.20 уникальных Chromium/PG PASS, включая10 финальных
повторов после уточнения статусов/подписи старого теста и проверки blur lookup.
Проверены точный JSON запроса и N=1, namespace local/provider, дубли, literal
поиск, pagination, unknown ID/N=0, reset/UTC и сохранённые версии/отчёты.
52 SQL и ссылки документации проверены. Есть предупреждения Vite о размере
chunk и удалении комментария-аннотации Zod; ошибок сборки нет. Отдельные
full-PG/Node-fixture/Python/Linux наборы не повторялись. Финальная сверка:
83/85 public-таблиц неизменны, только auth изменились;2232 карты,12 точных
строк очереди,9703 защищённых файла и активная `model_eligible` сохранены.
