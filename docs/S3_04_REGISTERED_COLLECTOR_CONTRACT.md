# S3-04 — учёт запросов и карт по зарегистрированному плану

15 ноября 2026. Реализован локальный контракт сборщика и его read-only связь с PostgreSQL-журналом регистрации. Он воспроизводит историю запросов, проверяет бюджет и формирует перечень наблюдавшихся карт с причинами неопределённости. Сетевой транспорт и постоянное сохранение журнала запросов в этом срезе не включены.

## Реализованное поведение

[Чистый обработчик](../tools/research/conditional-registered-collector.mjs) принимает пакет с подтверждённой регистрацией и журнал событий, закреплённый внешним SHA. Пакет должен включать оба новых файла сборщика в манифест кода. Подменить scope, окно, кандидата или лимиты через параметры сборщика нельзя. [Адаптер PostgreSQL](../tools/research/conditional-registered-collector-store.mjs) читает запись через прежний owner-only store, проверяет commit-квитанцию и фактические SHA новых файлов. Схема БД и прежние frozen-файлы не изменялись.

Журнал различает начало обхода, начало одной HTTP-попытки и её завершение. Незавершённая попытка уже расходует бюджет и блокирует следующую. Retry-After и короткая задержка после ошибок сохраняются между обходами; ошибка авторизации останавливает дальнейшие запросы. Скрытых повторов нет: каждый будущий транспортный retry должен стать отдельной попыткой. Допустимы только `/leagues/:registeredId/matches`, последовательный `/proMatches` и `/matches/:observedTargetId`.

Один журнал охватывает все повторные обходы: новая scan-запись сбрасывает только курсор текущего обхода. Общие 1000 попыток, 100 попыток в сутки UTC и ранее обнаруженные карты сохраняются. При превышении 300 возможных целевых карт сохраняются все полученные ID и запрещаются новые запросы; первые 300 не выбираются молча. Известные карты вне `[from, until)` сохраняются как исключённые и не расходуют лимит целевой выборки. Неизвестная дата или конфликт метаданных не становятся доказательством исключения.

Ответы проверяются по SHA, JSON-схеме и числовым ID. Неисправный JSON, дубли внутри страницы, ответ о другой карте и неубывающий курсор сохраняются как невалидные попытки. Исправный короткий список не означает полноту. Одна карта с несколькими наблюдениями остаётся одной картой; несовместимые даты, лиги, серии или стороны видны как конфликт. Время карты и время получения ответа раздельны. Ранее известный участник серии исключает наблюдавшихся соседей по этой серии. Исходы, kills и другие показатели сыгранной карты не попадают в discovery-признаки отчёта.

## Что означает отчёт

- `observedPossibleMaps` — число наблюдавшихся возможных целевых ID, **не число проверенных профессиональных карт**.
- `detailCaptured` означает только сохранённый JSON с подходящим ID и discovery-метаданными. Проверка pro-статуса, игроков, героев и исходов выполняется отдельной существующей границей источников.
- `globalStatus: exhausted` означает наблюдавшийся пустой ответ последовательного обхода, **не доказанную полноту турнира**.
- `denominatorComplete:false`, `verifiedProMaps:null` сохраняются всегда: ещё нужны сверка с проверенным реестром основных турниров, фактических серий и отдельно подтверждённых карт. Существующий enrollment-verifier не ослаблялся.
- `nextRequest` — диагностическая рекомендация. `collectionAllowed:false`, `realEvaluationAllowed:false`, `activationAllowed:false`, `deployable:false`; функция не выполняет HTTP и не выдаёт прогноз.

Чистая функция явно помечает основание как проверку предоставленного снимка: она не способна доказать, что снимок прочитан из PostgreSQL. Адаптер добавляет отдельную `registrationRead` с результатом настоящего owner-only чтения. Выводы чистого replay нельзя использовать как разрешение сетевого сбора.

`appendRegisteredCollection` сохраняет прежние события, проверяет внешний SHA предыдущей версии и запрещает дописывать события задним числом относительно предыдущего snapshot. Это пока **локальная операция без постоянного хранилища и блокировки конкурирующих авторов**. Без внешне закреплённой текущей вершины можно предъявить старую ветку; такой файл не доказывает учёт всех реальных запросов. Следующая задача устраняет это ограничение в PostgreSQL.

Лимит текущего контракта: 3000 событий, 64 MiB журнала, 8 MiB тела одного ответа. История игроков, справочники и другие provider endpoints пока не подключены; будущий реальный транспорт обязан включить все свои обращения и retry в общий бюджет. Даты и численные критерии проверки модели не менялись.

Лимиты плана не заменяют общий provider limiter. При подключении транспорта сохраняется существующий [OpenDotaClient](../packages/ingestion/src/opendota/client.ts) с `ProviderBudget.beforeRequest`, задержками и общими квотами. Один вызов клиента по умолчанию допускает до трёх попыток: будущая обвязка должна либо использовать `attempts:1`, либо регистрировать каждую фактическую попытку, а не считать весь вызов одной.

## Проверки

[21 Node-сценарий](../tests/node/conditional-registered-collector.test.mjs) проверяет бюджеты, сроки, BIGINT ID, повторные обходы, сбои, полноту, исключения, размер UTF-8 и неизменность предыдущих событий. [4 интеграционных теста](../packages/db/tests/conditional-registered-collector.integration.test.ts) используют отдельную временную PostgreSQL-базу: действующая регистрация, права владельца, отсутствие квитанции, подмена кода и отсутствие записей при диагностическом чтении. [Фикстуры](../tests/fixtures/conditional-registered-collector.mjs) явно синтетические; это не свидетельство реального сбора или качества модели.

```powershell
node --test tests/node/conditional-registered-collector.test.mjs
node --env-file=.env node_modules/vitest/vitest.mjs run packages/db/tests/conditional-registered-collector.integration.test.ts --maxWorkers=1 --testTimeout=30000
```

Нужны собранные shared packages, прежние закреплённые S3-04 артефакты и PostgreSQL с правом создания временной базы. При их отсутствии проверка завершается ошибкой. [Машинный отчёт](evidence/s3-04-registered-collector-contract.json) содержит фактически исполненные проверки и SHA файлов.
