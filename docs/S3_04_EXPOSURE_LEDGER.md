# Реестр ранее просмотренных карт и серий

## Общая исследовательская база для двух ПК

Подключение нового ПК, обмен файлами и порядок восстановления описаны в [руководстве общего реестра](SHARED_RESEARCH_REGISTRY.md).

Модель серии и Draft Lab могут записывать списки просмотренных карт в одну приватную PostgreSQL. Владелец один раз применяет миграции проекта к предназначенной для исследований базе, включая `075_shared_research_exposure.sql`. Для рабочих подключений достаточно доступа к базе и схеме, а также `SELECT` и `INSERT (sha256, snapshot_text)` на таблицу `research_exposure_snapshots`. В локальном `.env` обоих ПК задайте `RESEARCH_DATABASE_URL` для этой базы. У каждого ПК может быть своё приватное подключение к одному хосту. Локальная `DATABASE_URL` обозначает базу, из которой команда модели серии читает историю.

На Windows запустите [скрипт SSH-туннеля](../tools/research/start-research-vps-tunnel.ps1) в отдельном окне PowerShell. Передайте адрес VPS в `-ServerAddress` и сверенный публичный ключ сервера в `-HostPublicKey` в формате `ssh-ed25519 <ключ>`. Скрипт использует локальный ключ клиента в `.tools/research-vps-client-ed25519` и открывает порт 55433 на компьютере. Окно остаётся открытым, пока команды обращаются к реестру. В `RESEARCH_DATABASE_URL` укажите адрес базы через `127.0.0.1:55433`.

На машине с локальной историей выполните первую команду. На машине, где лежит пакет DreamLeague r1, выполните вторую. Каждый новый файл отчёта требует свободного пути. При одинаковых входах повтор записывает в реестр ту же ревизию. Флаг `--shared` требует настроенного подключения. При ошибке подключения команда завершается с ошибкой. Если переменная задана, обе команды используют общую базу и без флага.

```powershell
node --env-file=.env tools/research/review-series-exposure.mjs .tools/series-shared-01.json --shared
node --env-file=.env tools/research/reconcile-dl30-pc-inventories.mjs .tools/draft-shared-01.json --shared
```

После записи любой из этих команд с другого ПК можно проверить конкретную серию. Порядок аргументов после `check-series` — ID серии OpenDota, ID встречи PandaScore и один или несколько ID карт. Укажите `-` для неизвестного ID серии или встречи. Пример проверяет только известную карту Wallachia и работает без локальных архивов.

```powershell
node --env-file=.env tools/research/reconcile-dl30-pc-inventories.mjs check-series - - 8345450484
```

При `known_overlap` поле `matches` показывает конкретные совпадения. Достаточно одной ранее просмотренной карты для исключения всей серии из независимой проверки. `no_known_overlap` означает, что среди переданных ID совпадений в этом срезе реестра не найдено. Пустой реестр возвращает `registry_empty`. Ответ содержит серверное время чтения и SHA ревизий. Для решения о независимости нужны полный список карт серии и учёт старых материалов обоих ПК.

Общий реестр хранит ID, отпечаток кода и SHA исходных данных. Команда модели серии добавляет локальную историю и закреплённые источники. Команда Draft Lab добавляет ID из пакета r1 и архивов Wallachia. В отчёты обеих команд входит объединение всех зафиксированных ревизий. Снимки добавляются одной транзакцией, а проверка квитанции и `check-series` только читают общий срез. До переноса старых материалов доступна прежняя сверка по локальным отчётам и SHA. Общий отчёт нельзя использовать как подтверждение содержимого отдельного ПК. Сырые ответы API и файлы моделей пока хранятся по прежним путям. ### Резервное копирование реестра

На первом ПК задача Windows `Dota Research Registry Backup` запускается ежедневно в 04:30 МСК в сеансе пользователя. Для пропущенного времени включён запуск при первой возможности. Команда открывает свой SSH-туннель на локальном порту 55434. Она использует учётную запись реестра из `.env` и сохраняет архив и JSON с SHA-256, составом ревизий и контрольными суммами пакетов в `.tools/research-vps-backups`. Последний вывод доступен в `.tools/research-vps-backup.last.log`. Таблицы `research_exposure_snapshots` и `research_artifacts` копируются из одного снимка базы. Для восстановления нужна отдельная PostgreSQL с миграциями проекта по 076 включительно. [Команда резервного копирования](../tools/research/backup-shared-registry.ps1)

Для проверки по запросу запустите `Start-ScheduledTask -TaskName 'Dota Research Registry Backup'`. После завершения код последнего запуска доступен через `Get-ScheduledTaskInfo`. Проверенный запуск с двумя таблицами завершился с кодом `0`. После восстановления во временной PostgreSQL совпали обе ревизии, весь список идентификаторов и точные байты пакета Draft Lab r1.

## Реальные источники и ограничения

- 19 источников: прежние E0/V1/H1/H2 выгрузки и метаданные, readiness r3, исторический discovery ledger и новый read-only снимок локальной БД.
- 1919 сохранённых ответов OpenDota: исходные байты, их контрольная сумма, известный endpoint и явное поле native match_id. Всего в итоговом плане **1938 источников**.
- Исследованы имена/структуры 14401 JSON-файла в объявленных исследовательских каталогах .tools. 58 дополнительных raw-ответов отдельно проверены: это справочники героев/лиг и профили игроков, а не история карт. Они не добавляют карты.
- 73 дополнительные карты: 67 из discovery истории игроков; ещё 6 уникальных — из архивов V1. Одна карта может встречаться в нескольких архивах. Дополнительные series keys: opendota/1164196 и opendota/1164261.
- У **93 карт** нет native-серии в проверенных источниках, включая 26 из прежнего реестра. Неизвестность сохранена. 1096 локальных alias IDs имеют известные native keys; конфликтов карт/aliases в проверенной выборке не обнаружено.

**Полнота всего проекта не удостоверена.** У 12423 просмотренных файлов нет поддерживаемой оболочки raw-ответа: среди них также manifests, отчёты, конфигурации и отдельно включённые датасеты. Это не означает 12423 неизвестных датасета, но и не доказывает отсутствие других раскрытых карт. Другие рабочие архивы, bare payloads и документированные наблюдения требуют отдельной сверки. Наличие файла в discovery-обзоре не означает, что его содержимое включено в реестр.

Дата capturedAt — время составления реестра, не историческое known_at данных и не момент первого просмотра каждой карты. Ссылки на неизменённые исходные файлы и SHA сохраняют исходные временные сведения; они не переписываются.

## Реализация

- [exposure-ledger-core.mjs](../tools/research/exposure-ledger-core.mjs): явные адаптеры схем, объединение карт, происхождение каждой записи, local/native series keys, неизвестные связи и конфликты.
- [exposure-source-discovery.mjs](../tools/research/exposure-source-discovery.mjs): ограниченный read-only обзор исследовательских архивов; private-owner, зависимости, runtime/QA и символические ссылки исключаются. Сырые данные и секреты в отчёт не копируются.
- [exposure-ledger.mjs](../tools/research/exposure-ledger.mjs): read-only SQL-снимок, исключительное создание отчёта и offline replay по внешнему SHA, плану, исходным байтам и версии кода.
- [План источников r2](evidence/s3-04-exposure-source-plan-r2.json) фиксирует конкретные пути/SHA и оставшиеся вопросы. Промежуточный r1 сохранён; итоговый проверяемый checkpoint — r2.

IDs передаются строками, включая значения больше Number.MAX_SAFE_INTEGER. Числовые ID из raw JSON принимаются только при безопасном целочисленном представлении. Один и тот же match_id у нескольких игроков в explorer считается одной картой. ID PandaScore не преобразуется в native map ID или series key по числовому совпадению.

Если источники расходятся, все обнаруженные series keys сохраняются для исключения, конфликт виден отдельно. Равный local alias не используется для скрытого объединения серий или заполнения неизвестной серии другой карты.

screenExposure исключает уже раскрытую карту **или любую карту известной раскрытой серии**. Для остальных возвращает unresolved: отсутствие пересечения ещё не доказывает независимость при неполном глобальном реестре. Функция не подключает публикацию вероятностей и не меняет frozen evaluator/пороги.

Ограничения: до 5000 источников, до 100000 строк на источник, до 1000000 проекций суммарно, до 128 MiB на файл/отчёт; обзор до 20000 файлов и 3 GiB. При превышении нет тихого усечения. Только локальные файлы; внешних API-запросов в этом срезе нет.

## Воспроизведение

Исходные raw bytes и итоговый отчёт остаются в приватной .tools. Команды выполняются из корня dotaanalitic:

```powershell
node tools/research/exposure-ledger.mjs verify .tools/s304-exposure-ledger-r2.json 7727f5671c3ff78dd44ff068fe44fc99fc012198178b7392268c6c535354fca7
node --test tests/node/exposure-ledger.test.mjs tests/node/exposure-ledger-file.test.mjs
```

Для новой версии сначала capture-db в новый путь, затем новый план источников и capture в новый путь. Не перезаписывать r2 и старые snapshots. Проверка повторно читает конкретные источники; изменение файла или кода отклоняет replay.
