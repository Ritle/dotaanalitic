# S1-16 / BUG_REPORT №7 — подписи общего выбора

`CatalogPicker` используется в сравнении команд, ручном редакторе будущей
встречи и назначении первой карты. Результаты поиска и выбранное значение
теперь подписаны именем/ником и доступным тегом команды. Основные подписи
и имена кнопок для скринридера не содержат служебных ID. Поиск по прежним
числовым ключам поддерживается.

Рядом с результатом есть «Проверить аккаунт» / «Карточка команды», рядом
с выбранным значением — ссылка на его карточку. Ссылка открывается в новой
вкладке; незавершённая форма сохраняется. У совпадающих имён остаются разные
записи и появляется подсказка проверить карточку. Steam32 и состояние
подтверждения аккаунта доступны в карточке; ник не считается доказательством
личности. Технический ключ раскрывается в «Данных записи» / «Данных выбранной
записи». Выбор требует явного нажатия кнопки.

Пустое имя имеет подпись «Игрок без ника» / «Команда без названия». При сбое
чтения выбранной записи показано «Имя недоступно», числовой выбор сохраняется;
в его подробностях есть повторное чтение имени. Ручной сброс и исключение
уже выбранных игроков/команды работают по прежнему ключу. Имя не подставляется
в API вместо ID; подтверждение состава после правки по-прежнему сбрасывается.

Новых автоматических запросов нет. Список использует прежний каталог;
карточки всех результатов заранее не читаются. Название известного выбранного
элемента берётся из имеющихся метаданных. Прежний lookup выполняется только
для выбранной записи без имени; кнопка повторения запускает явный GET.

В настольном сравнении поле игрока занимает полную строку; роль и stand-in
идут следом. Это исправляет найденное при визуальной проверке сжатие имени
до вертикального текста. Кнопка сброса переносится при недостатке ширины.

Изменены `CatalogPicker.vue`, раскладка `CompareView.vue` и потребляющие
браузерные тесты. Проверки выбирают точный ключ через невидимые атрибуты
`data-catalog-id` / `data-selected-id`, а не через удалённые ID в подписи.
Сохранение сценариев/назначений, ограничения дублей и числовые snapshots
проверяются прежними тестами. Backend, SQL, contracts, providers и V1 не меняются.
