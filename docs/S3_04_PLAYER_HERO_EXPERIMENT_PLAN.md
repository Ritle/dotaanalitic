## Три заранее заданных варианта

| Модель | Входы | Обучение |
|---|---|---|
| H0 | Прежний хронологический Elo logit | Без обучения и fitted calibration |
| H1 | Тот же Elo logit | L2 logistic regression |
| H2 | Elo logit + `observedHeroPracticeLog90Delta` | L2 logistic regression |

H1 и H2 получают **одинаковые карты, labels и общие входы**. H2 не включает signed hero identity coefficients старого M2, пабы, предполагаемые роли, организационные рейтинги или новые патчевые веса. Это отдельная гипотеза о наблюдаемом объёме практики, не продолжение fitting старого M2. Старые коэффициенты/результаты не переписываются. H1 обучается заново в отдельном run для сопоставимости; гиперпараметр старого M1 не подставляется по памяти.

Признак сохраняет окно 90 дней, `ln(1+N)` и разницу средних пяти игроков A−B. Положительный признак не гарантирует победу; коэффициент не ограничивается положительным знаком. Изменение признака потребует отдельной версии до дальнейшего сравнения, а не подбора по поздним ошибкам.

## Обучение, выбор C и калибровка

- Коэффициенты обучаются только на train. Solver lbfgs, L2, C из **[0,01; 0,1; 1]**, max_iter2000, tolerance1e-8, seed42, один поток, без intercept/class weights. Одна карта — одна строка, равный вес; sign-swap augmentation нет. Порядок признаков закреплён; centering, scaling и imputation отсутствуют.
- C выбирается отдельно для H1/H2 по минимальному validation log loss. Равенство в пределах1e-12 разрешается в пользу меньшего C. После выбора train+validation не объединяются для refit.
- Nonconvergence/nonfinite коэффициенты делают конкретный вариант недопустимым; нельзя молча увеличить iterations или изменить grid.
- Температура обучается отдельно на calibration для каждого выбранного замороженного logit: positive temperature, bounds[0,25;4], scipy bounded scalar minimization, xatol1e-8, maxiter1000, без intercept. Попадание в предел bounds с epsilon1e-6 или nonconvergence → insufficient. Поздний блок не выбирает C, температуру или raw/calibrated вариант.
- Python environment, зависимости, code/config/seed, артефакт JSON/SHA и TS inference будут закреплены перед fit. Обязательная Python↔TS parity ≤1e-7, включая обычные входы, A/B swap, нулевую практику, пропуски, крайние logits и отсутствующую калибровку. Пока fitter и новый fitted artifact не созданы.

Эти настройки наследуют ранее использованную исследовательскую процедуру, кроме единственного нового входа H2. Они не выбраны по новой точности: она ещё не рассчитана.

## Пропуски и область выводов

Нулевой observed count сохраняется как точный ноль найденных карт, не как выдуманное отсутствие мастерства или фиксированный штраф. При неизвестных героях в части ранней истории считаем зарегистрированную наблюдаемую нижнюю границу и сохраняем missing-map IDs; эти флаги не становятся дополнительными числовыми признаками. В отчёте заранее предусмотрены срезы «есть/нет unknown hero history» и «есть/нет нулевого hero count». Их нельзя использовать для выбора победившего варианта или ослабления общего gate; при пустом срезе rate/метрика null.

Минимума hero N нет. Неполное объявленное 90-дневное окно либо нечисловой признак → unavailable, без нулевой подстановки. Прежний минимум5завершённых **pro-карт игрока вообще** относится к существующему Elo, а не к пяти играм на выбранном герое; он не изменён.

Patch/role/as-of ограничения остаются явными. Реконструированные герои не доказывают их известность до карты, event time не переносится в known_at. Provider patch не заполняет canonical patch; положительный исследовательский результат не закрывает patch-transfer/role/hero-eligibility gates. Это допустимый **ограниченный исследовательский** срез, не выпуск полной post-draft модели. Смешанный проверенный pro-корпус не подтверждает автоматически качество на Tier1. Ручное подтверждение Tier1 в интерфейс не возвращается.

## Как будет оцениваться результат

Основной контраст — **H2_cal − H1_cal по log loss на точном общем наборе карт**. Вторично: сравнение с H0, Brier, raw/calibrated ECE/reliability, accuracy, N, покрытие, baseline-only/unavailable, заранее заданные срезы пропусков/provider patch/дат/лиг. Все варианты публикуются в исследовательском отчёте, но не в UI прогнозов.

Положительный исследовательский сигнал требует одновременно:

1. Sample/provenance/parity checks и paired coverage≥80% исходного позднего знаменателя223.
2. Верхней границы95% парного series-bootstrap интервала Δlog loss ниже0.
3. Log loss H2_cal ниже H0; Brier H2_cal не выше H0 и H1_cal.
4. ECE H2_cal≤0,10 на10равных probability bins, с null rate пустых bins.

Bootstrap:2000повторов целых серий, PCG64seed42, веса по числу карт, percentile95 linear. Интервалы exploratory: старый период уже использован. Отсутствие нужного количества данных/калибратора даёт insufficient, провал метрик — negative. Переключиться на raw как на «прошедший» вариант нельзя. Первый результат сохраняется неизменно; исправления получают связанную revision, а не замену отрицательного результата.
