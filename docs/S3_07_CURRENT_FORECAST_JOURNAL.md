# S3-07/current-forecast-journal — запись сразу после расчёта

По уточнению владельца журнал должен показывать рассчитанную вероятность по пятёркам без отдельного создания отчёта.

Причина дефекта: расчёт уже сохранялся в `v1_runtime_snapshots`, но `/forecast-journal` открывал последний **замороженный отчёт**. Расчёты, созданные после этого отчёта, не могли появиться в его неизменяемом содержимом. Дополнительной записи прогноза не требуется.

## Изменение

- По умолчанию открывается текущий список сохранённых предматчевых и what-if расчётов. После получения прогноза в предстоящей встрече показана прямая ссылка на журнал.
- `GET /api/v1/forecast-journal/current` читает записи текущего владельца: 50 на страницу, курсор `(createdAt, id)`, порядок от новых к ранним. Проверяются SHA полных снимков, схема отображаемых метаданных и сохранённая сверка; полные снимки/манифесты наружу не выдаются. Большие внутренние JSON-манифесты не копируются повторно для формирования карточки.
- Открытие страницы запрашивает свежие данные, список обновляется раз в 30 секунд в активной вкладке; есть ручное обновление. Чтение не создаёт отчёты, исходы или новые прогнозы и не обращается к внешним API.
- Выданная вероятность без проверенного исхода отображается как «Ожидает результата». Нет вероятности — «Прогноз не выдан», what-if — «Условный расчёт». Отмена не превращается в проигрыш; известная проверенная связь с картой имеет приоритет над отменой.
- Сохранённая сверка результата перепроверяется существующим локальным верификатором. Если источник изменился, показывается необходимость повторной проверки, старый итог не объявляется актуальным. Первичная связь со сыгранной картой не угадывается.
- В текущем списке показан итог каждого расчёта, без суммирования пересчётов в точность. Общая статистика с выбором основного прогноза остаётся в явно открываемых сохранённых отчётах (`?report=…`). Старые URL и содержимое отчётов сохранены.

Это отдельная проекция существующих данных: новые модули contracts/db и их additive exports; старые inference/registry/journal modules и миграции не меняются. Модель, допуск, вероятности и рабочие данные не пересчитываются. Live-оценки после старта остаются отдельными условными оценками в истории Live.

## Проверки

Сценарии: появление выданной вероятности без нового отчёта; повтор запроса без дубля; пустой/недоступный расчёт; изоляция владельцев; курсор при добавлении новой записи; проверенные победы A/B и изменение источника; сохранность архивов; переход из предстоящего матча; мобильная ширина 360px. Синтетические данные — только в тестах и временных базах. Результаты запуска фиксируются в `PROGRESS.md`.
