# Сверка остальных архивов с реестром использованных данных

14 ноября 2026 · S3-04/exposure-ledger/remaining-archives/structured-source-reconciliation.

Реестр исключений расширен с **2333 до 5506 карт**, с **1098 до 1743 известных серий**. Добавлены 3173 ранее просмотренные карты и 645 серий из сохранённых источников. Это не импорт в рабочую БД, не обучающая выборка и не подтверждение пригодности карт для модели.

## Что проверено

Зафиксирован план из 13760 JSON-файлов: 12421 файл прежней категории non-wrapper, 997 файлов вне прежних исследовательских семейств и 342 файла доказательств документации. Два файла из прежних 12423 пропущены из-за чувствительных имён. Всего 269 записей исключений перечислены в плане: приватные файлы, зависимости, QA и собственные выходные файлы. Проверка ограничена этим перечнем; она не утверждает просмотр всех файлов компьютера.

Проверены SHA исходных файлов, явные поля map/series IDs и JSON внутри текстовых полей. Имена игроков/команд не используются как идентификаторы. Учтены старые series keys opendota:ID, массивы match_ids и большие ID строками. ID встречи PandaScore и ID серии STRATZ не объявляются ID карты/серии OpenDota по числовому совпадению. Явный native ID внутри объекта другого провайдера остаётся предметом разбора.

Итоговая классификация:

| Категория | Файлов |
|---|---:|
| Явные ссылки учтены либо относятся к другому пространству ID | 9608 |
| Явных ссылок на карты/серии не обнаружено | 4019 |
| Требуется дополнительный разбор | 131 |
| Синтетика явно помечена на верхнем уровне | 2 |

Отсутствие явного поля не доказывает отсутствие любых сведений в произвольном тексте. Неизвестные форматы не дают положительного допуска.

## Откуда появились новые карты

Добавлено 1405 логических блоков источников из 1357 файлов:

| Основание | Блоков |
|---|---:|
| Raw OpenDota, совпали SHA исходного тела и сохранённого источника | 1366 |
| Старые discovery receipts, дополнительно связанные SHA с манифестом | 3 |
| Сохранённые live OpenDota audit reports | 31 |
| Сохранённые live OpenDota league-discovery cohorts | 5 |

У нормализованных audit reports проверены native endpoint/ID, версия адаптера и сведения источника. Они доказывают ранее сохранённое наблюдение для **исключения из новой проверки**; raw bytes не считаются повторно удостоверенными, если их нет в этом отчёте. Никакого повышения training eligibility из этой информации нет.

В расширенном реестре 3343 записи происхождения: 1938 прежних источников и 1405 новых блоков. Это число не равно количеству уникальных физических файлов. У каждой добавленной записи сохранены путь файла, SHA, JSON pointer, основание и при необходимости связь с манифестом. Одна карта при повторных наблюдениях считается один раз.

У 1787 карт native-серия неизвестна; конфликтов native keys не обнаружено. Неизвестные связи не заполнены соседним ID, именем команды или local alias другой карты.

## Что осталось неоднозначным

После сверки осталось 389 новых числовых ID в ссылках. Отдельная проверяемая классификация установила:

- 200 ID имеют подтверждение в raw-ответах рейтинговой практики: каждый исходный ряд содержит lobby_type=7, сохранены совпавшие SHA страниц. Они не включены в профессиональные статистики или обучающие цели.
- 8 ID встречаются только в проверенных синтетических файлах: у всех случаев capture.syntheticOnly и history.syntheticOnly равны true.
- **181 ID остаётся неоднозначным.** Среди источников — bare Valve payloads, старые отчёты истории, ссылки UI/расписания и материалы STRATZ. Это 181 числовое упоминание, а не 181 подтверждённая профессиональная карта.

Классификация не переписала исходные файлы или реестр автоматически. При одинаковом числе в неоднозначных пространствах имён не заявляется установленная идентичность.

В 131 файле для дальнейшего разбора также есть 16 неразбираемых JSON-файлов, три срабатывания ресурсного ограничения и неизвестные/текстовые поля; категории пересекаются. Пять cohort-записей из docs/evidence/s0-08-manifest.json не соответствуют адаптеру payloads и не приняты как новые источники. Все эти ограничения сохранены в отчёте, а не скрыты как пустые данные.

## Код и воспроизведение

- [exposure-archive-core.mjs](../tools/research/exposure-archive-core.mjs): обнаружение и классификация ссылок, nullable и namespace guards, JSON pointers, лимиты.
- [exposure-archive-sources.mjs](../tools/research/exposure-archive-sources.mjs): проверка вложенных raw receipts и нормализованных архивных наблюдений.
- [exposure-archive-review.mjs](../tools/research/exposure-archive-review.mjs): фиксированный план файлов, SHA/code-bound capture/replay, консервативное расширение прежнего реестра.
- [exposure-archive-triage.mjs](../tools/research/exposure-archive-triage.mjs): отдельная проверка ranked/synthetic evidence для оставшихся ссылок.

Ранние r1/r2 — промежуточные планы и диагностический отчёт до поддержки старых форматов. Итоговый checkpoint — r3; реестр предыдущей задачи r2 не изменён и успешно воспроизведён.

```powershell
node tools/research/exposure-archive-review.mjs verify .tools/s304-archive-review-r3.json 01e4b85f3658ba912ae28f3b150bfe039bdc44149e1f2861a86f31d44c6437cc
node tools/research/exposure-archive-triage.mjs verify
```

Расширенный список находится в result.extendedLedger этого отчёта. Его нельзя выдавать за новый файл старого формата exposure-ledger-file-v1: новые основания источников проверяются новым replay. Родительский реестр и старые модели не переписаны.

Действуют лимиты: 20000 файлов / 4 GiB суммарно, 128 MiB на файл/отчёт, 2 млн узлов и глубина 64 на JSON. Превышение остаётся явной причиной разбора, а не тихим усечением.
