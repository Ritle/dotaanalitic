Подтверждённые завершённые исходы читаются из PostgreSQL без автоматического TTL; повторная сверка — отдельный CSRF POST, незавершённые встречи обновляются раз в5мин. Дата: 2026-11-16. Запрос владельца: разобраться с постоянным ожиданием исходов, проверить доступность результатов и заменить карточки таблицей.

## Причина и проверенные данные

В рабочей БД было 12 сохранённых расчётов, 2 архивных отчёта, **0 связей с картами и 0 проверенных исходов**. Поэтому прежнее «Ожидает результата» означало отсутствие сверки, а не то, что игра продолжается.

Выполнено 9 ограниченных запросов `GET /matches/{id}` PandaScore через серверный клиент с общей квотой. Все успешны: 7 встреч завершены, 2 ещё не начались. Для семи завершённых встреч доступны `games[].position = 1`, идентификатор карты, числовой победитель и время начала/окончания. Повторное применение нормализатора к сохранённым ответам не обращалось к провайдеру.

## Реализация

- Текущий журнал и строки архивного отчёта отображаются таблицей: время расчёта, встреча, фаворит/вероятность, победитель карты, итог проверки, раскрываемые сведения. На узком экране прокручивается таблица, а не вся страница.
- Защищённый `GET /api/v1/forecast-journal/results/:requestId` читает только расчёт текущего владельца. Проверяет SHA снимка и назначения, соответствие локальных и внешних числовых ID команд. Приватные ключи не возвращаются.
- Для текущих ожидающих PandaScore-прогнозов результат запрашивается автоматически. Вердикты явно разделены: верен, неверен, карта не началась, первая карта идёт, перенесена, отменена, источник недоступен, требуется сверка. Отмена владельцем сохраняется и не запускает автоматическую сверку.
- Требуется ровно одна явно обозначенная первая карта; проверяются участники, согласованность ID, завершение, отсутствие технического исхода, времена и выдача расчёта до старта. Нет вероятности, равные вероятности или расчёт после начала — нет оценки «верен/неверен».
- Кэш процесса: максимум 100 встреч, успешный ответ 5 минут, ошибка 60 секунд; совместные запросы одной встречи объединяются. Обращения идут последовательно через существующую общую квоту PandaScore. Незавершённые проверки повторяются через 5 минут только при активной вкладке; завершённые автоматически не опрашиваются. Повторная ручная проверка также соблюдает серверный кэш.
- Архивы не обращаются к провайдеру и сохраняют прежнее состояние отчёта. Составы и подробности расчёта доступны по раскрытию строки.

## Границы

Это отдельная **текущая сверка результата PandaScore**. В строке явно указан источник. Она пока не записывает канонический исход, не меняет статистику точности сохранённых отчётов и не участвует в обучении. Ответ хранится в ограниченном оперативном кэше; при перезапуске API будет прочитан заново. Корректировки провайдера могут изменить текущую сверку при следующем чтении.

Повторные расчёты одной карты показаны отдельными строками, но не превращаются в дополнительные независимые карты для оценки качества. По этой небольшой выборке точность модели не заявляется.

Миграций, изменения модели/активации, переписывания прогнозов и архивов нет. Запросы провайдера обновляют только штатный учёт квоты. Контрольное чтение сохранило счётчики 12/0/0/2 (расчёты/связи/исходы/отчёты).
