# S3-04 — ограниченный локальный сборщик v2

16 ноября 2026. Срез `S3-04/conditional-collection-v2-runtime`.

Новый runtime связывает [discovery v2](S3_04_COLLECTION_V2_DISCOVERY.md), [транспорт v2](S3_04_COLLECTION_V2_TRANSPORT.md), общую квоту и архив в один возобновляемый проход. Он не регистрирует эксперимент, не импортирует карты в профессиональную историю и не оценивает модель.

## Порядок работы

1. Проверяется строгий вход: режим `local-synthetic`, владелец, регистрация и её SHA, буквальный `http://127.0.0.1:<port>`, лимит1–20 новых попыток и100–60000мс. По умолчанию5 попыток и60с. Нельзя передать произвольный endpoint, разрешение реального сбора, время, токен или сброс прохода.
2. До записей и HTTP проверяются полный манифест исполняемых файлов, SHA и локальная среда. Используются прежние проверки регистрации v2; новый манифест включает runtime/CLI, discovery, транспорт, архив, журнал, shared JS и lockfile.
3. Неблокирующая session advisory lock допускает одного runner на регистрацию. Проигравший вызов возвращает `busy` и не снимает чужую блокировку. До открытия окна архив не создаётся; после закрытия пустой сбор не инициализируется.
4. Уже существующие неизменяемые параметры архива сохраняются. Для нового синтетического архива предел512МиБ; общий лимит архива продолжает действовать. Перед новой попыткой нужен запас под максимальный ответ8МиБ и свободная квитанция.
5. Ожидающая попытка с сохранённой квитанцией транспорта завершается без HTTP. Это допустимо после окна сбора. Если квитанции нет, результат неизвестен: автоматической повторной отправки или возврата бюджета нет.
6. Проверенный discovery-отчёт выбирает следующий endpoint. Сверяется head журнала, проверяются лимиты, связь session lock и сигнал отмены; транспорт отдельно повторяет проверку состояния и получает общую квоту. Сам runtime не вводит дополнительных повторов или ожидания квоты.
7. После ограничения числа попыток следующий запуск продолжает с сохранённого состояния. После полного прохода повторный запуск не загружает те же ответы снова. Завершение прохода означает только отсутствие следующего запроса по текущему архиву, а не полноту турнира.

## Остановки и восстановление

- Ошибка JSON/структуры discovery, неизвестный исход, ошибка сохранения наблюдения квоты или несогласованность снимка останавливают runner. Общие коды ошибок не раскрывают тела ответов, SQL или секреты.
- HTTP429/5xx и Retry-After обрабатывает прежний транспорт и общий лимитер. Неуспешная попытка остаётся учтённой. После отказа транспортного вызова новые запросы в этом запуске не выполняются.
- При неопределённом результате записи runtime не пытается угадать состояние. `journalHeadSha256` и общий счётчик становятся `null`, `countsComplete:false`; счётчики с `Acknowledged` отражают только подтверждённые операции этого вызова. Следующий запуск проверяет журнал и сохранённые квитанции.
- Отмена во время HTTP передаётся транспорту; его сохранённый результат остаётся доступным для восстановления. Нормальный выход и ошибка освобождают session lock.
- Лимит времени начинается до проверки манифеста. Он ограничивает новые действия и прерывает HTTP; уже выполняющаяся SQL-проверка или транзакция может закончиться позже. Это не жёсткий таймаут всей работы БД.

`denominatorComplete:false`, `verifiedProMaps:null`, разрешения remote/evaluation/activation остаются `false`. Исходные тела и вычисленные вероятности в CLI-отчёт не включаются.

## CLI и тестовый режим

Новая команда:

```powershell
node --env-file=.env tools/research/run-conditional-collection-v2.mjs --request <локальный-json-запрос>
```

CLI требует PostgreSQL на loopback и базу с именем `codex_ingest_<12 hex>`. Рабочую БД он отклоняет до подключения. JSON ограничен16КиБ, повторяющиеся ключи и неизвестные поля запрещены. SIGINT/SIGTERM инициируют отмену. Это тестовый инструмент, а не команда запуска реального сбора на текущей `.env`.

Ни старый runner v1, ни прежние v2-модули, SQL001–069, модель V1 и политики не изменены. Новых миграций нет. Рабочая БД остаётся на061; API и UI этим срезом не меняются.

Ошибка несогласованных часов тестового стенда исправлена; исходные проверки времени сохранены. Один прежний сценарий повторён отдельно после превышения10с на подготовку БД, с30с для тестового hook; проверки данных не изменены. SHA, журналы и ограничения — в [машинном отчёте](evidence/s3-04-collection-v2-runtime.json). HTTP выполняется только против локального сервера с синтетическими ответами. В успешных тестовых проходах сбрасывается только промежуток между запросами в отдельной тестовой квоте, чтобы результат не зависел от скорости ПК; реальные счётчики, Retry-After и ошибки квоты проверяются отдельно. Production-лимиты не меняются.
