# S1-16 / BUG_REPORT №7 — подписи истории и сохранённых отчётов

В «Сохранённых редакциях» откройте нужную редакцию. Названия команд,
ники выбранных и ожидаемых игроков загружаются одним ограниченным запросом
локального каталога. Роли и stand-in сохраняются. Закрытые редакции не
загружают подписи. Повторное открытие использует кэш по точному набору ID.

В сохранённом отчёте ники видны в личной статистике по ролям и исторической
сыгранности пар. Названия команд и героев, уже входящие в снимок отчёта,
сохраняются. Ссылки игроков/команд открывают карточки в новой вкладке,
внутренние ключи доступны в «Данные записи». Пустой ник и отсутствующие
метаданные имеют явные подписи; одинаковые ники не объединяются.

Дополнительные подписи прочитаны из **текущего** локального каталога.
Это не подтверждение исторического ника, доступности состава или участия.
Время чтения показано отдельно. Они не входят в ScenarioInput, сохранённые
редакции, тело отчёта или resultHash и не влияют на N/WR, фильтры и прогнозы.
Обновление ника в каталоге меняет подпись при явном «Обновить подписи каталога»;
полный сохранённый ответ API остаётся прежним.

Новый приватный `GET /api/v1/catalog-labels` читает максимум две команды и
двадцать игроков. Числовые строки проверяются до SQL, сохраняются как строки,
запросы параметризованы; дубли возвращаются один раз, отсутствующие записи
не подменяются. Внешних API, обновлений профилей, поисков по нику и записей в БД
нет. Контракт принадлежит API и повторно используется UI, как существующий
team-activity contract. Пакеты contracts/db/analytics/prediction и SQL неизменны.

Клиент использует Vue Query с пятью минутами свежести, без автоматического
повтора и refetch при фокусе окна. Сигнал отмены передан запросу. Каждая
редакция/отчёт использует собственный scope; поздний ответ не дописывает имена
в снимок. Ошибка подписей не скрывает отчёт, ключи или статистику. Если есть
предыдущее чтение, его подписи и время остаются видны вместе с предупреждением.
