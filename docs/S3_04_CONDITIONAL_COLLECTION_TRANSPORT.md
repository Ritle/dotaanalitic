# S3-04 — транспорт сбора: локальная интеграция

Реализован локальный синтетический путь **PostgreSQL-журнал → общий бюджет OpenDota → существующий OpenDotaClient → HTTP → неизменяемая квитанция → завершение журнала**. Это проверка механизма сбора, а не сбор реальных карт или допуск post-draft модели.

## Исполнение одной попытки

[LocalConditionalCollectionTransport](../tools/research/conditional-collection-transport.mjs) принимает идентификаторы владельца, регистрации, операции и запроса, исходный SHA журнала и разрешённый endpoint. Проверяет активного владельца, регистрацию, закреплённые SHA кода журнала, транспорта, исходного и собранного клиента/квоты. Журнал обязан быть `syntheticOnly:true`.

Отправка доступна только при результате нового резервирования `recorded`. `already_recorded` возвращает `already_reserved` без списания общей квоты и без HTTP. Потерянное подтверждение commit не означает разрешения повторить отправку. Для повторного вызова нужны прежние request/operation IDs и исходный SHA.

Используется существующий `PostgresProviderBudget`: общие лимиты минуты/дня/месяца, паузы и сведения из заголовков. Затем повторно проверяется, что резерв всё ещё последний, окно не закрыто и возраст резерва меньше 30 секунд по серверным часам и монотонному времени процесса. Одна попытка клиента, без скрытых повторов. По умолчанию общий тайм-аут после commit — 15 секунд, максимум 30; отмена повторно проверяется после ожидания квоты и БД, перед отправкой и при чтении тела. Ожидание самого SQL не превращается в разрешение позднего HTTP.

Транспорт принимает только явный `http://127.0.0.1:<port>` без пути, credentials, query и fragment. Redirect запрещён. API key не принимается. У OpenDotaClient сохранён штатный адрес провайдера; его внедрённый fetch перенаправляет только проверенный endpoint на локальный стенд. Удалённого режима, CLI и API endpoint в этом срезе нет.

## Сохранение и восстановление

[SQL065](../packages/db/migrations/065_conditional_transport_receipts.sql) добавляет `conditional_transport_receipts`: одна неизменяемая квитанция на резерв/request, FK на операцию журнала, SHA точного JSON и серверное время сохранения. Триггер проверяет синтетический журнал, владельца и связь request/endpoint/reservation head. Изменение, удаление и TRUNCATE запрещены. SQL001–064 сохранены.

Квитанция содержит результат, SHA полного тела, размер, HTTP-статус, код проверки клиента, ошибку сохранения общей квоты и часы вызова fetch / получения заголовков / завершения тела. Эти часы явно обозначены как **часы процесса**, а не историческое `known_at` или подтверждённое время получения пакета сервером. Сохранение квитанции предшествует отдельному commit завершения журнала.

- Если завершение журнала не удалось, возвращается `transport_completion_pending_receipt_saved`. `finalize(owner, registration, request)` читает квитанцию и завершает прежнюю попытку, не отправляя HTTP. Повтор после потерянного подтверждения завершения идемпотентен.
- Если не подтверждено сохранение квитанции, возвращается `transport_receipt_persistence_unknown`. Резерв остаётся незавершённым; повторная отправка по нему запрещена. Отсутствие сохранённого ответа не выдается за отсутствие HTTP. Прежнее восстановление после 120 секунд сохраняет расход попытки.
- Если попытку уже закрыли через recovery, поздняя квитанция не заменяет этот результат. `finalize` отказывает из-за изменения вершины журнала.
- Отказ квоты до отправки также завершает уже созданный резерв как неуспешный. Бюджеты консервативны: резерв/claim не доказывают отправку, возврата расхода нет.

Полные UTF-8 тела успешных HTTP-ответов сохраняются даже при неверном JSON/схеме: replay помечает их непригодными. Неверная кодировка, превышение размера, незавершённый поток и сетевой сбой не сохраняются как полные ответы. Тела HTTP-ошибок и неполные байты не архивируются; сохраняются статус и причина. Retry-After пересчитывается консервативно от серверного снимка при подготовке записи, поэтому задержка сохранения не сокращает паузу.

## Границы

В этом транспорте тело ограничено **1 MiB**, чтобы даже максимальное JSON-экранирование помещалось в прежний лимит команды/квитанции 9 000 000 байт. Это отдельное ограничение локального среза; оно не доказывает достаточность для реальных `/matches` ответов. Полный поток ограничивается при чтении независимо от Content-Length.

Сохраняется и прежний лимит replay-журнала 64 MiB. Квитанция не отменяет его: если суммарный журнал перестаёт помещаться, завершение попытки останавливается с сохранённой квитанцией. Перед реальным сбором требуется проверить суммарный объём; бюджет 1000 попыток не гарантирует вместимость 1000 полных ответов. Этот срез не меняет закреплённый формат журнала ради обхода лимита.

`quotaObservationFailed` сохраняется и возвращается явно. Будущий автоматический runner должен останавливаться при такой ошибке, до проверки/восстановления общего cooldown. Текущий класс исполняет только одну явно запрошенную локальную попытку. Сам факт 120-секундного recovery не доказывает остановку удалённого HTTP или процесса, приостановленного ОС. Реальный транспорт требует отдельного допуска.

Никакие `collectionAllowed`, `realEvaluationAllowed`, `activationAllowed` или `deployable` не включаются. Metadata из ответа не становится verified professional map автоматически. Модель V1, её пороги, ранее сохранённые прогнозы и рабочая схема БД не меняются. Новый SQL применяется только во временной тестовой базе. Права администратора БД могут обойти триггеры; SHA не является внешней подписью.

## Проверка

[Интеграционные тесты](../packages/db/tests/conditional-collection-transport.integration.test.ts) создают отдельную `codex_ingest_*` базу, применяют SQL001–065 и поднимают HTTP-сервер на случайном loopback-порту. Регистрация, карты и ответы синтетические. Проверяются конкуренция, квоты, 429, JSON/UTF-8, размер, зависший поток, отмена, редирект, права, stale reserve, потерянный commit, неизменяемость и завершение после рестарта без повторного HTTP.

node --env-file=.env node_modules/vitest/vitest.mjs run packages/db/tests/conditional-collection-transport.integration.test.ts --maxWorkers=1 --testTimeout=30000

Результаты, ограничения и SHA: [машинный отчёт](evidence/s3-04-conditional-collection-transport.json). Прежняя тестовая очистка журнала обновлена для новой FK-таблицы; старые исполняемые файлы и SQL сохранены. Рабочая БД061,V1,2260карт и7 прежних SHA прогнозов не изменены.
