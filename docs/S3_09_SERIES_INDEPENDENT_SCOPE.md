### Проверка времени записи в PostgreSQL

19 ноября добавлена проверка на отдельной временной БД с миграциями проекта и искусственными данными. Запись привязывается к сохранённому снимку расписания по SHA, ID встречи и издания, формату BO3, соперникам и времени старта. Для первичной записи штатный читатель проверяет актуальность наблюдения. Успешный повтор возвращает тот же SHA и серверную отметку даже после смены расписания. Другие входы для уже сохранённой серии вызывают конфликт. [Журнал и отбор](../tools/research/series-forecast-postgres.mjs), [схема для тестовой БД](../tools/research/series-forecast-postgres.sql).

Прогноз фиксируется в первой транзакции. Во второй PostgreSQL сохраняет время, к которому запись уже была доступна для чтения. После сбоя между транзакциями повторная попытка получает новую отметку, если прежняя отсутствует. Это консервативная верхняя граница времени фиксации. Для проверки она должна предшествовать как плановому старту, так и фактическому началу карты с позицией 1 в проверенном результате серии. Сравнение строгого неравенства выполняется в PostgreSQL с точностью до микросекунд. Смена издания, отсутствие доказанного старта, отсутствие прогноза или поздняя запись сохраняются как причины исключения.

Для воспроизведения из корня:

```powershell
node --env-file=.env node_modules/vitest/vitest.mjs run tests/integration/series-forecast-postgres.test.mjs --maxWorkers=1 --testTimeout=30000
```

Все четыре интеграционных сценария прошли, включая конкурентный повтор, досрочное начало матча, равенство времён и прерывание между транзакциями. Команда сама создаёт и удаляет тестовую БД. [Проверки](../tests/integration/series-forecast-postgres.test.mjs).

### Возобновление загрузки с тестового HTTP-источника

Команда сохраняет каждую прошедшую проверку страницу отдельным файлом. Повторный запуск с тем же планом читает сохранённые страницы и запрашивает первую недостающую с идентификатором исходного снимка. HTTP 429 с допустимым `Retry-After` приводит к паузе и повтору текущей страницы. Для репетиции заданы максимум три попытки на страницу, пауза до 30 секунд и до 100 страниц. При длительной паузе, исчерпании попыток или смене снимка команда завершает запуск с ошибкой и сохраняет уже проверенные страницы. После завершения загрузки она записывает файл для команды расчёта покрытия и выводит его SHA-256. [Загрузка страниц](../tools/research/collect-series-edition-pages.mjs).

Сценарии воспроизводятся командой `node --test tests/node/collect-series-edition-pages.test.mjs`. В первом тесте локальный сервер разрывает соединение на странице 2. Отдельный процесс возобновляет загрузку со страницы 2, соблюдает секундную паузу после HTTP 429 и получает все шесть встреч. Ещё два сценария проверяют смену снимка и исчерпание повторов при HTTP 429. [HTTP-тесты](../tests/node/collect-series-edition-pages.test.mjs).

Для ручной репетиции структура плана совпадает с тестовым файлом страниц: вместо поля `pages` укажите поле `endpoint` с HTTP-адресом тестового сервера на `127.0.0.1`. Сервер отвечает объектом одной страницы на запрос с параметрами `page` и `per_page`. Начиная со второй страницы запрос содержит также `snapshot`. Укажите существующий родительский каталог для итогового файла. [Пример страниц](../tests/fixtures/bo3-edition-pages.json).

```text
node tools/research/collect-series-edition-pages.mjs PLAN.json CHECKPOINT_DIR PAGES.json
```

### Что можно сверить по контракту PandaScore

PandaScore документирует нумерацию с 1, максимум 100 строк на странице и заголовки `X-Page`, `X-Per-Page`, `X-Total` и `Link`. Эти данные позволяют сверить число страниц, объём ответа и признаки его окончания для заданного запроса. В опубликованном контракте пагинации гарантию единого снимка между запросами найти не удалось. `snapshot` в репетиции моделирует такую гарантию. [Пагинация PandaScore](https://developers.pandascore.co/docs/pagination).

Для проверки полноты предлагается сопоставить два перечня по ID встреч: ответ для издания и объединение ответов по заранее проверенным этапам. После этого следует сверить состав и число встреч с перечнем организатора. Сумма строк PandaScore сама по себе характеризует выдачу API. [Встречи издания](https://developers.pandascore.co/reference/get_series_serieidorslug_matches), [этапы издания](https://developers.pandascore.co/reference/get_series_serieidorslug_tournaments), [встречи этапа](https://developers.pandascore.co/reference/get_tournaments_tournamentidorslug_matches).
