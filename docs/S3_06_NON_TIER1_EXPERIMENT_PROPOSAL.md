## Что установлено

V1 использует player-mean Elo по выбранным десяти проверенным аккаунтам. Tier не является числовым признаком/множителем. Следовательно, математический расчёт для другой профессиональной встречи возможен, если есть подходящая история игроков. Это не доказательство переноса качества и калибровки с проверенного Tier1-набора на новый домен.

Обычный runtime прямо требует reviewed Tier1 scope: `packages/db/src/v1-runtime.ts`, `runtimeTargetReasons` возвращает `TIER1_SCOPE_NOT_REVIEWED` или `TARGET_OUTSIDE_REVIEWED_TIER1_SCOPE`. Проверка есть и для what-if. Нельзя назвать другой турнир Tier1, снять gate SQL-флагом или изменить frozen scorer/порог ради числа. Список runtime admission включает root scripts и ingestion dist; добавление/изменение таких файлов может отключить совместимость активной модели.

## Ограниченный следующий срез

1. Перепроверить кандидата, уровень события, ожидаемые5+5 и current identities; проверить eligible earlier history прежним feature builder.
2. Для первого частного испытания подготовить отдельную **диагностическую Elo-оценку/фаворита**, явно вне проверенного Tier1-домена. Не выдавать диагностический скор за валидированную/калиброванную вероятность; обычный production runtime остаётся с прежним gate.
3. До выдачи числового win probability на новом домене зафиксировать отдельный контракт допустимости и воспроизводимую temporal/series-aware проверку этого домена. Результат Tier1-теста не переименовывается в доказательство Tier2-качества.
4. Экспериментальные входы/версию/UTC cutoff/источники сохранять отдельно; не включать их в основную Tier1-статистику и не превращать предположение в training label. Реальный исход позже связывать только по verified pro map. Переобучение для каждой игры не требуется.
