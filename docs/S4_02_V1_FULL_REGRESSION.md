# S4-02 — общая локальная регрессия, 6 ноября 2026

Владелец выбрал эту проверку до начала сбора V1. Область: существующие unit/Node, все API/PostgreSQL integration и весь Chromium suite после изменений составов, истории игроков и рейтинговой практики. Рабочие данные и закреплённая модель не используются как тестовые фикстуры. Linux deployment остаётся отложенным.

## Исправления

Базовый PostgreSQL-тест ожидал ровно 20 миграций. На новой временной БД с 46 файлами воспроизведено `46 !== 20`. Теперь список берётся из каталога SQL; проверяются порядок, полное совпадение журнала миграций, SHA всех файлов и контрольные суммы 001–005 из golden fixture. Повтор мигратора должен оставить журнал вместе с `applied_at` неизменным. Весь baseline создаёт собственную `codex_bootstrap_*` БД и удаляет только её; рабочий `DATABASE_URL` используется для подключения администратора и создания тестовой базы.

Тест восстановления резервной копии также содержал устаревшее число 34. Теперь он сравнивает полный журнал миграций исходной тестовой БД и восстановленной копии, включая контрольные суммы и время применения, до и после повторного запуска мигратора. Число `SKIP` должно совпасть с фактическим исходным журналом. Все три проверки восстановления прошли после исправления; SQL и код восстановления не изменялись.

CI использовал устаревающий ручной список отдельных API/БД команд. Новая `pnpm test:postgres` собирает API/worker с зависимостями, выполняет baseline и автоматически находит все `*.integration.test.ts` в тестах API, worker, db и ingestion. На момент проверки это 66 файлов. Один Vitest worker, без автоматических повторов; существующие индивидуальные timeout сохранены, общий `testTimeout=30000` соответствует прежним интеграционным командам. PostgreSQL 16 client нужен для существующих restore-тестов; `PG_BIN` задаёт каталог с `pg_dump`/`pg_restore`. CI подготовлен для этого полного набора; его запуск на Linux этой локальной проверкой не подтверждается. Unit/Node в CI выполняются последовательно, Node — после сборки, необходимой для импорта скомпилированных контрактов.

Полный запуск также обнаружил переполнение старого E1 формата code references: 263 файла при максимуме 256. Замороженный контракт не расширялся. Исследовательский CLI сохраняет крупный полный список файлов и SHA в отдельный `research-executable-file-manifest-v1`, ссылаясь на него через существующие `path`/`sha256`. Список не обрезается. При числе файлов до 256 сохраняется прежний прямой формат. Список нормализуется по пути; дубликаты, некорректные хеши и превышение размера отвергаются. После включения нового helper в собственный список он содержит 264 файла.

Манифест хранится в `.tools/research-code-manifests/<SHA>.json`: временный файл записывается и синхронизируется, затем публикуется атомарной файловой ссылкой без перезаписи. Конкурирующие записи проверяют одинаковое завершённое содержимое; повреждённый существующий файл не исправляется молча. Этот каталог нужно сохранять вместе с новыми E1 captures/reports для полного аудита кода. Старые отчёты и схемы читаются как раньше. V1 frozen executor, сроки, датасеты и качество модели не менялись; реальная исследовательская оценка не запускалась.

Браузерные тесты первоначального состава теперь раскрывают свёрнутый список участников источника и явно подставляют синтетический catalogue provider. Ранее отсутствие этой подстановки позволяло тестовому серверу обратиться к внешнему каталогу OpenDota и мешало своевременному завершению сервера. Для первого запуска нулевое число внешних запросов не заявляется. Последний повтор использует явную подстановку. Сценарий из семи последовательных действий с каталогом состава объявлен `serial`, поскольку использует ранее сохранённые составы; ожидание истории привязано к `finishedAt` ответа, а не предположению о завершении фоновой работы за несколько секунд.

## Результаты

Локальная регрессия завершена. Машинный [отчёт](evidence/s4-02-v1-full-regression.json) содержит список всех интеграционных файлов, итоговые количества, SHA журналов и данные сверки рабочей БД. Повторные выполнения одного сценария не увеличивают число уникальных проверок.

| Проверка | Фактический результат |
| --- | --- |
| Установка `--offline --frozen-lockfile`, root typecheck, root build | PASS; после последней правки restore-теста также повторён API typecheck |
| Workspace unit/CLI | 884 уникальных теста PASS с целевыми повторами |
| Node | 112 PASS, 0 пропусков; четыре новых теста полного манифеста кода |
| PostgreSQL/API | 519 уникальных тестов в 66 файлах + 4 baseline = 523 PASS с целевыми повторами |
| Chromium | 101 уникальный сценарий в 36 файлах PASS по полному запуску и целевым повторам, без автоматических retries |
| SQL / frozen V1 | 46 миграций проверены; 245 защищённых файлов, 150 исходных модулей, frozen bundle и совместимость runtime сохранены |
| Доступность рабочего приложения | API `/health`: `ok`; Web: HTTP 200 |

Первый полный PostgreSQL-запуск: 516 PASS / 3 FAIL, 63 успешных файла из 66. Ошибки: устаревшее число миграций в restore-тесте, лимит E1 code references, изменение исходных файлов во время синтетической проверки V1 freeze. После исправлений и стабилизации файлов три затронутых файла повторены: 6/6 PASS. Это не один полностью зелёный первоначальный запуск. Проверка freeze корректно отклонила изменившееся содержимое; её guard не ослаблялся.

Первый полный Chromium-запуск: 94 PASS / 7 FAIL. После исправления раскрытия состава, последовательности сценария каталога и ожидания завершённой истории повторены два файла: 8/9 PASS. Оставшийся afterEach timeout устранён явной подстановкой каталога в initial-rosters; последний повтор этого файла — 2/2 PASS. По именам сценариев проверено покрытие всех исходных 101 случаев. Визуально просмотрены два синтетических мобильных снимка истории и уточнения аккаунтов: новых дефектов не обнаружено; полный визуальный аудит всех экранов не заявляется.

При одновременном запуске нескольких тяжёлых наборов CLI discovery и две unit-проверки restore достигли прежних тайм-аутов 60/5 секунд. При последовательных целевых повторах неизменённые проверки прошли. Тайм-ауты не повышались. Первые проверки атомарного манифеста упирались в `EPERM` для файловой ссылки внутри Windows sandbox; все четыре прошли при разрешённом обычном выполнении. Настройки разрешений пользователя не менялись.

## Сохранность данных и ограничения

До и после проверки сняты хеши 93 таблиц: все 80 public и 10 из 13 pg-boss совпадают полностью. Сохранены 340 pro-карт, прогнозы/модели, аккаунты, составы, история и рейтинговые наблюдения. Хеши строк заданий совпадают; ожидающая командная история остаётся в `created`, 12 прежних заданий завершены. Новых оставшихся тестовых БД нет; одна существовавшая до проверки сохранена.

Различаются `pgboss.instance`, `pgboss.queue`, `pgboss.version`, без изменения числа строк. Проверка строгого равенства всех 93 таблиц поэтому вернула FAIL, сохранённый в исходном after-снимке. Дополнительное чтение установило свежий heartbeat прежнего worker PID 9904, отметки monitor/cron и неизменные задания; это согласуется с фоновой работой pg-boss. Исходный снимок содержит хеши, поэтому точное различие каждого столбца за весь интервал не восстановлено. Полная неизменность служебных таблиц не заявляется. API/Web/history-only worker не перезапускались; общий worker не запускался.

Linux CI подготовлен, но не исполнен. Docker/Linux deployment остаётся отложенным владельцем. Python-набор не повторялся. Реальные сбор, оценка качества, активация модели и публикация прогнозов не выполнялись; результаты синтетических тестов не подтверждают точность V1.
