Результаты завершённых карт сохраняются в БД и читаются без повторной загрузки PandaScore; для ручного обновления есть «Сверить с источником». Это прежние прогнозы первой карты. **Draft Lab: проверка сохранённых расчётов.** Доступен приватный экспорт исследовательских записей с offline-проверкой входов, модели и результата. Привязка к сыгранной карте хранится отдельно; повторные попытки не увеличивают число карт. [Команды и ограничения](docs/S3_04_COMMITTED_SHADOW_EXPORT.md). Прогноз после драфта пока не активирован.

**Draft Lab: автоматическое сохранение расчёта.** При фиксации полного драфта сервер сам сохраняет исследовательский расчёт по выбранным игрокам и героям. Интерфейс показывает статус и время подтверждения записи; после сбоя доступна кнопка «Завершить сохранение расчёта». Повторы не меняют прежний результат. Публичный прогноз после драфта пока не допущен. [Использование и ограничения](docs/S3_04_DURABLE_SHADOW_PERSISTENCE.md). [Отдельный offline-расчёт и replay](docs/S3_04_POST_DRAFT_SHADOW_RUNTIME.md) также сохранены.

**Draft Lab: состояние истории.** В сохранённой редакции показаны проверенные прошлые исходы, пропущенные карты, время проверки и причины недоступности. Старый лимит подробного снимка вынесен в детали. [Использование и ограничения](docs/S3_04_HISTORY_READINESS_UI.md).

**Draft Lab: подготовка признаков.** Сохранённую проверку истории можно использовать для offline-расчёта входов Elo и практики на героях. Отчёт сохраняет причины исключения карт и не публикует вероятность. [Команды, проверки и ограничения](docs/S3_04_OBSERVATION_FEATURE_ADAPTER.md).

**Draft Lab: проверенная история.** При фиксации нового драфта сервер автоматически сохраняет проверку прошлых исходов до cutoff. Повтор той же редакции использует прежнюю запись. [Устройство и ограничения](docs/S3_04_HISTORY_OBSERVATION_CAPTURE.md). Прогноз после драфта пока не активирован.

**Draft Lab: экспорт диагностики.** Снимки и привязки к сыгранным картам можно выгрузить для повторяемой offline-проверки. ## Локальный запуск

[Подписи драфта и турнира](docs/S1_16_READABLE_DRAFT_CONTEXT.md): Draft Lab показывает ники игроков, проверка доступности — названия героев/патча/лиги. В «Турнир карты» и «Локальный турнир назначения» можно выбрать запись по имени. Сохранённые решения eligibility не пересчитываются при обновлении подписей.

[Распределения и prior](docs/S1_16_READABLE_ANALYTIC_BREAKDOWNS.md): названия патчей и героев рядом с исходными числами; отдельное обновление подписей и повтор недоступных пакетов. Текущие названия не меняют сохранённые отчёты, исторические выборки или веса.

[Неизвестное имя героя](docs/S1_16_HERO_NAME_FALLBACKS.md): пустое и отсутствующее имя различаются, ID доступен в подробностях. Поиск и ошибка каталога сохраняют уже прочитанные имена и выбранных героев в Draft Lab.

[История игроков и сила соперников](docs/S1_16_READABLE_HISTORY_STRENGTH.md) показывают ники и названия организаций. Steam32 и точные локальные ID доступны для проверки; обновление подписей не загружает карты и не пересчитывает Elo.

ID доступны в «Данных записи». В журнале раскройте «Команды и ожидаемые составы A/B»
в нужной строке. Обновление подписей каталога сохраняет исходный расчёт и статистику.

видимыми. При одинаковых никах проверьте аккаунт в карточке.
[Подробности](docs/S1_16_READABLE_CATALOG_LABELS.md).

появится в другой вкладке, форма сохранится. Служебный ключ доступен в

**Отдельный ручной сценарий:** «Сохранённые сценарии» → «Создать сценарий» →

**Архив команд:** на главной выберите «Архив: неактивные» или «Все команды».
В карточке команды → «Изменить статус команды» можно убрать её из обычного
списка либо вернуть, сохранив основание. Неизвестный статус не скрывает команду;
история матчей остаётся доступна. Для выбора архивной команды в сравнении
включите «Искать также в архиве команд». [Подробности](docs/S1_16_TEAM_ACTIVITY.md).

**Роли в карточке команды:** в «Составе по OpenDota» рядом с игроками показаны
текущие подсказки Carry–Hard support. Раскройте «Основания роли», чтобы увидеть
источник, число карт и ограничения. Неизвестные роли сохраняются; исправление
доступно при выборе пятёрки для сравнения. Просмотр карточки не обновляет
внешние профили. [Как это работает](docs/S2_01_ROSTER_CARD_ROLES.md).

**Шаблоны владельца:** «Подтвердить пятёрки и роли» сохраняет ожидаемые назначения для этой команды и точной пятёрки. При повторном открытии роли подставляются без нового ввода; карточки показывают автора, время и редакцию. Другой состав требует проверки владельцем, ручные правки сохраняются. [Как пользоваться и границы прав](docs/S2_01_OWNER_LINEUP_TEMPLATES.md).

**Быстрое сравнение:** выберите встречу → проверьте автоматически подставленные сохранённые пятёрки → проверьте роли под именами → **«Подтвердить пятёрки и роли»** → выберите период → **«Сравнить выбранные пятёрки»**. Если пригодных сохранённых пятёрок ещё нет, аккаунты **подготавливаются автоматически**. Проверенные общие связи переиспользуются сразу; новые соответствия видны в карточке. Проверьте аккаунты и роли под именами, затем нажмите одну кнопку **«Подтвердить пятёрки и роли»** для обеих сторон. При шести участниках отметьте нужных пятерых. Причины незаполненных мест показаны рядом с именами; расширенный поиск открывается через «Уточнить аккаунты A/B». [Единое подтверждение и восстановление после ошибки](docs/S2_01_UNIFIED_LINEUP_CONFIRMATION.md), [автоматическая подготовка](docs/S2_01_AUTOMATIC_ROSTER_PREPARATION.md), [ручной порядок и исправления](docs/S2_01_UNIFIED_PLAYER_CATALOGUE.md).

В редакторе сценария и форме будущей встречи доступны [роли из PandaScore/STRATZ и pro-истории](docs/S2_01_ROLE_PROFILES.md). В «Сопоставление источников» один раз свяжите команду и записи игроков, затем нажмите «Обновить профили API». Редактор назначает роли выбранной пятёрке по одной однозначной подсказке на игрока: PandaScore → STRATZ → pro-история. Источник и расхождения видны; неизвестные/повторяющиеся роли остаются для ручного уточнения. Ручная правка сама выключает авто; сохранённый сценарий открывается с выключенным авто. В будущей встрече подсказки могут дополнить неизменённую пятёрку до её подтверждения. Карточки пяти игроков остаются на месте: выберите роль под именем. Занятая роль обменивается с текущей ролью другого игрока; герой и отметка замены сохраняются за игроком. В будущей встрече роли доступны сразу в выбранных составах; в сценарии и сравнении поиск выбранного игрока открывается кнопкой «Заменить». [Назначение ролей](docs/S2_01_PLAYER_ROLE_CARDS.md). Роли не входят в V1 Elo. Ники в подсказках показаны без внутренних ID; ключ доступен в раскрываемых основаниях. [Аудит оставшихся числовых подписей](docs/S1_16_READABLE_LABEL_AUDIT.md).

[Сопоставление источников](docs/S1_16_READABLE_SOURCE_MATCHING.md) показывает ник и выбранную роль под каждым игроком. Внешние ID команды/турнира находятся в «Идентификаторах источников», локальный ID игрока — в «Данных выбранного игрока». При одинаковых никах проверьте числовые записи; имя само по себе не подтверждает аккаунт. Сохранённая запись PandaScore не заменяется автоматически, если её нет в загруженной заявке.

Если сохранение связей вернуло409: «Перечитать связи» → проверить сохранённый ручной выбор → подтвердить пятёрку заново → сохранить. При недоступном чтении используйте «Повторить чтение составов». [Восстановление после конфликта](docs/S1_16_CATALOGUE_CONFLICT_RECOVERY.md).

В pro-картах соперника и игрока для фильтра роли, а в истории игрока — героя можно выбрать по имени: «Найти» → выбрать запись → применить фильтры. Поиск сохраняет действующий выбор; числовой ввод доступен в «Технический ID». [Именованные фильтры](docs/S1_16_NAMED_REFERENCE_FILTERS.md).

В раскрытой истории сценария пики и баны показаны по именам из текущего каталога; ID — в подробностях. «Обновить подписи каталога» перечитывает только имена. [Герои в истории](docs/S1_16_SCENARIO_HISTORY_HERO_LABELS.md).

В форме будущей встречи доступна [личная pro-история пятёрки](docs/S2_01_PLAYER_HISTORY.md): выберите игроков → «Загрузить историю игроков». OpenDota ID организации не нужен. Доступен выбор 90–730 дней и 10/25/50 карт на пятёрку; по умолчанию год и 25 карт. Нужен обработчик очереди, описанный в инструкции.

В карточке игрока под профессиональной статистикой героев раскройте [«Рейтинговая практика»](docs/S2_07_RANKED_HERO_SUMMARY.md): для OpenDota v2 доступны игры, победы, наблюдаемый WR и последняя игра по героям. Показаны период, источник и покрытие; раскрытие читает сохранённые данные, внешний запрос запускается кнопкой загрузки/обновления. Малое число игр не доказывает силу на герое, пустой источник не означает нулевой опыт. STRATZ пока показывает доступность истории без геройских показателей. [Backend](docs/S2_07_RANKED_PRACTICE_READER.md) включается флагом RANKED_PRACTICE_ENABLED (default=false, локально включён). Рейтинговые карты не обновляют V1 Elo.

Old observations сохранены, v1 cache обновляется вручную без ожидания прежнего TTL. STRATZ для этого аккаунта ranked-историю не предоставил; источники не объединяются автоматически.

[Дополнение STRATZ](docs/S2_07_STRATZ_ENRICHMENT.md) подключено: в рейтинговой практике OpenDota раскройте **«Дополнительные данные STRATZ»** → **«Дополнить данные STRATZ»**. Повторная загрузка использует кэш; N/WR основной выборки сохраняются.

После загрузки сервис [подготавливает аккаунты остальных участников и серии](docs/S2_01_HISTORY_ENRICHMENT.md). Частичный результат не означает готовность прогноза; модель требует независимой проверки и активации.
